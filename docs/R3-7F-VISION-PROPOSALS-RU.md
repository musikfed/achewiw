# R3.7F — безопасный просмотр предложений распознавания

Статус: экспериментальная ветка, не установлена на Huananzhi. Основа: R3.7E успешно прошла 19/19 Node и 27/27 DOCWORK smoke по журналу пользователя.

В мастерской DOCWORK добавлена отдельная загрузка JSON **непроверенных предложений** фигур и надписей, которые в будущем может выдавать локальная vision-модель. На этапе F модель не устанавливается и не запускается, GPU и Ollama не задействуются. Сервис не считает предложения доказанными, не применяет их к ручному слою или исходному DOCX, не меняет SQLite. Цель — изолированный осмотр и проверка контракта перед подключением реальной модели.

Формат: `achewiw-vision-proposal`, версия 1, `status: unverified`, `autoApply: false`, `documentScope` совпадает с текущим исходным рисунком, `canvas` совпадает по размерам, `proposals` до 100 элементов с однозначными ID, типами и оценкой уверенности 0–1. Файл максимум 256 КиБ. Содержимое отображается только через DOM textContent, без исполнения текста. Структура не делает выводов о семантических связях.

Проверка: `node --check app/static/vision_proposals.js && node --check app/static/docwork_workbench.js && node --test tests/vision-proposals.test.cjs`, после чего регрессионный DOCWORK smoke. Вручную открыть DOCX, попробовать корректный и чужой JSON, убедиться, что оригинальный файл и разметка не изменились.

Следующая стадия: поштучное принятие/отклонение предложений с отдельной проверкой текста, координат и сохранением авторского контроля. Только после этого исследовать подключение выбранной локальной vision-модели с явным запуском и арендой GPU.
