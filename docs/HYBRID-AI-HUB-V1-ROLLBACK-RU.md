## Как получить упаковку ZIP

GitHub сам создаёт архив дерева выбранной ветки — не требуется хранить бинарный ZIP в истории Git:

**[Скачать ZIP архивной ветки](https://github.com/musikfed/achewiw/archive/refs/heads/archive/pre-hybrid-20261119.zip)**

Альтернатива: открыть ветку `archive/pre-hybrid-20261119` в браузере GitHub → зелёное `Code` → `Download ZIP`.

GitHub ZIP содержит **только файлы, отслеживаемые Git в этом коммите**. Он не содержит локальные `.env`, ключи, пользовательские рукописи, SQLite `data/`, контейнерные тома, runtime-файлы и другие исключённые из Git данные. Чтобы восстановить живую систему, **отдельно** нужен безопасный резервный снимок пользовательских данных и конфигурации без публикации секретов в GitHub.

## Безопасный просмотр старой версии без изменения текущей копии

На собственной рабочей машине, когда нужна прежняя версия кода:

```bash
git clone --branch archive/pre-hybrid-20261119 --single-branch \
  https://github.com/musikfed/achewiw.git achewiw-pre-hybrid-20261119
cd achewiw-pre-hybrid-20261119
git rev-parse HEAD
# Должен быть 2c88883797e64ffb401fb8ccbff2e6c9ba1b7857
```

Команды выше создают **отдельную копию** кода; они не заменяют рабочую установку. Для восстановления действующего сервера требуется отдельная согласованная процедура после проверки целостности SQLite и различий миграций; не запускать старую версию сразу поверх новых данных.

## Когда потребуется откат после разработки

1. Остановить **только собственные задачи ACHEWIW** штатным безопасным lifecycle, не трогая другие проекты и Ollama; это отдельное действие после согласования.
2. Зафиксировать состояние текущего кода, редакций и БД, создать резервные копии SQLite через SQLite Backup API (не копировать работающую базу слепо).
3. Проверить, что старый код совместим с текущей схемой; если новые миграции уже применены, откат кода **не означает** автоматический откат данных.
4. Развернуть старую версию в **отдельной тестовой копии** с копией данных, подтвердить доступность библиотек, глав, иллюстраций и экспортов.
5. Лишь после проверки и явного разрешения автора обсуждать переключение активного ACHEWIW на сохранённую версию.

**Никаких `git reset --hard`, `git clean`, удаления `data/`, удаления томов Docker или пересоздания баз.**
