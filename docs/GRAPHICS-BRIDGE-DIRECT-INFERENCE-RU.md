# ACHEWIW Graphics Bridge + Direct Inference: безопасный план перехода

Состояние на 24.11.2026. Дизайн-задание; НЕ подтверждение, что Windows CorelDRAW/Photoshop уже подключены.

## Цель
Перестать блокировать создание редактируемых иллюстраций из DOCX ожиданием Vision-LLM. Использовать **CorelDRAW Technical Suite 2026** для векторизации и операций с фигурами, **Adobe Photoshop 2026** для растра; оба приложения локальные, лицензионные, офлайн, находятся на Windows владельца. ACHEWIW (Linux, Studio 7080) отвечает за извлечение копии изображения, очередь, ручную приёмку и сохранение новой версии, а не исходного документа.

## НЕ удалять
- Не удалять `ollama`, модели `qwen3:8b`, `qwen3:4b-instruct`, `qwen2.5-coder`, `nomic-embed-text` — они могут использоваться независимыми проектами и книгогенератором.
- Не выполнять `ollama rm` для `granite3.2-vision:2b` и `qwen2.5vl:7b` без инвентаризации ссылок на них в сервисах и согласования точного списка владельцем. «Снять с рабочего пути ACHEWIW» ≠ «удалить общую модель».
- Не трогать ComfyUI, GPU-сервисы и существующие контейнеры. Не объединять ветку в main без Windows end-to-end проверки.

## Рабочая архитектура
1. ACHEWIW DOCWORK извлекает из исходного DOCX **копию** исходного изображения, вычисляет sha256; исходный файл остается неизменным.
2. Graphics Bridge создаёт ограниченное задание с operation из allowlist: `vectorize`, `normalize_raster`, `background_cleanup`, `export_svg`, `export_png`. В заявке есть request id, параметры и хеш исходника; никаких исполняемых команд/путей пользователя.
3. Windows-agent работает в пользовательской сессии интерактивных графических редакторов, **сам забирает задания** через локальную VPN/LAN с авторизацией, выполняет последовательно, с идемпотентностью и жёстким deadline. Сервер Linux не открывает удалённый shell и не запускает произвольные пользовательские скрипты.
4. По типу задания агент применяет проверенный VBA/скрипт CorelDRAW либо UXP Photoshop. Для CorelDRAW SVG может быть векторизацией визуальных контуров, но автоматическая топология стрелок и семантика блоков **не гарантированы**.
5. Агент отдаёт результат в quarantined staging. Сервер проверяет MIME, magic bytes, размер, SVG sanitization, размеры, scope draft/image и авторизацию; сохраняет **новую** ревизию.
6. UI показывает до/после, способ обработки, предупреждение «автоматический результат» и кнопки принять/отклонить. Только принятие связывает ревизию с экспортом нового DOCX.

## Минимально полезный результат (без LLM)
Реальное изображение в тестовом DOCX → выбрать «CorelDRAW: векторизовать» → обработать через Windows агент → получить SVG и PNG предпросмотра → явно принять → скачать новый DOCX, сохранив исходный SHA. Сначала тестовая схема, затем принадлежащий владельцу документ. Не нужна Ollama и расход VRAM.

## Какие этапы реально выполняем
A. Инвентаризация Windows: версия CorelDRAW, поддерживаемый механизм скриптов, доступность SVG import/export; Photoshop UXP и лицензия — только подтверждённые локально действия.
B. Контракт обмена + Windows-agent с симулятором CorelDRAW (offline unit), затем рабочий CorelDRAW script. Порт локально/через VPN, нет public bind.
C. Однократный end-to-end на копии пользовательского изображения.
D. Photoshop adapter через тот же контракт после успешного CorelDRAW. Не строить сразу весь универсальный движок.

## Отдельный GPU эксперимент, НЕ блокирующий Graphics Bridge
- `llama.cpp` с CUDA может выполнять GGUF без Ollama и предоставлять локальный OpenAI-совместимый API. `--n-gpu-layers`, размер контекста, KV cache и параллельность влияют на VRAM.
- NVIDIA TensorRT/TensorRT-RTX могут быть полезны с поддерживаемыми форматами и железом, но их настройка не равна запуску произвольных Ollama-моделей «напрямую».
- Начальный режим: **одна** модель/эксперт за раз, явное резервирование GPU, измерение tokens/s, time-to-first-token, VRAM, качества, без вмешательства в действующую Ollama.
- «Система экспертов» на 12GB: маршрутизатор выбирает специализированную модель, возможно поочерёдная загрузка/кэширование/отдельная RAG-память; если все веса не помещаются в VRAM, перекидывание RAM↔VRAM может сделать систему **медленнее**, даже если активен только один эксперт.
- Настоящая Mixture-of-Experts модель имеет обученный router/experts. Набор отдельных моделей + маршрутизация = **система агентов/экспертов**, но не обученная MoE без дополнительной архитектуры и тренировки.
- Не заменять это работой над «Верфью» обучения/дистилляции: это отдельная будущая дорожная карта.

## Критерий готовности
Было: несколько нерезультативных вызовов Granite/Qwen и повторяющихся 27 PASS.
Нужно: один **реальный** редактируемый экспорт через CorelDRAW, без LLM, с ручным принятием, SHA исходника, проверкой режима offline, совместимости SVG и отчётом об изменённых объектах. Только после этого масштабировать.
