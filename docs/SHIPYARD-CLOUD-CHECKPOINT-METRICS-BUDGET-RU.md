# ACHEWIW · Верфь моделей · облачный конвейер (ОТЛОЖЕНО)

**Решение 23.11.2026:** сейчас продолжаем основной издательский конвейер (R3.6 → R4). Эту спецификацию не разворачивать и не смешивать с R4. Верфь — вкладка **того же ACHEWIW**, но работа над ней возобновляется только после ручной приёмки DocWork/нормативных этапов. На действующем сервере ничего не устанавливать, не запускать GPU, не расходовать квоты и кредиты.

## Цель

Облачная «Верфь» управляет обучением, дистилляцией, проверкой и сборкой версий моделей, хранит **кривые и полную историю**, умеет ставить задачу на паузу после исчерпания квоты и продолжать обучение из **проверенного checkpoint** позже. CPU-редактирование книг и рисунков не блокируется.

> **Идёт обучение и сборка модели. Редакция заблокирована.**

Блокируется конфигурация только конкретной обучаемой **редакции модели** (model_revision_id): датасеты, гиперпараметры, промпты, источники весов. Другую редакцию можно создавать отдельно. У редактора книг своя независимая история и автосохранение.

Тарифы, реальные доступные GPU, порядок reset квоты и ограничение срока хранения не прошиты константами! Провайдер-адаптер обнаруживает их по документированному API, а невозможность прочитать квоту отображается как **«Данные о квоте недоступны»**, не как «бесплатно».

**Запрет на случайную оплату:** режим по умолчанию `max_spend_usd = 0`, `allow_paid_fallback = false`, `approval_required = true`; не отправлять платный запрос, если отсутствие расходов нельзя установить надёжно. Для сервисов без механизма жёсткого stop-spend использовать только вручную подтверждённый запуск без привязанного платного перерасхода. Бесплатные **токены inference API ≠ бесплатное обучение GPU**.

## Хранение, воспроизводимость и восстановление

Каждая задача получает:
- immutable `run_id`, `revision_id`, `base_model_repo + commit SHA`, `dataset_repo + revision SHA`, лицензию источника, хэш рецепта, code commit + pinned Python dependencies, цель (SVG, OCR-подписи, QLoRA, DPO, knowledge distillation).
- Последний **верифицированный** checkpoint: LoRA/adapters, tokenizer/config, optimizer state, scheduler state, RNG state, trainer state, глобальный шаг и `samples_seen`; checksum + формат + URI, storage provider + expiry/ACL.
- **Двойную гарантию**: checkpoint выгружен из эфемерного runtime в долгоживущее хранилище с подтверждённым хешем; каталог `last_verified_checkpoint` меняется *после* полного успешного upload. Иначе задача возвращается на предыдущий checkpoint.
- Версионированный `metrics.jsonl` с append-only событиями по глобальному `step`, `wall_time`, `source_run_id`, `provider`: train/validation loss, learning rate, grad norm, eval scores (SVG text fidelity, diagram graph errors, SVG parse/render success, perceptual similarity), tokens/s, GPU memory, quota consumed. Указывать `null`, если метрика не сообщена.
- Вместо чтения чужого непрозрачного dashboard основной источник графиков — **метрики от нашего trainer**, в JSONL/TensorBoard (по выбору) и артефактные логи, сохраняемые в реестр. Внешние провайдерные API/метрики подключаются только там, где реально доступны и разрешены; синхронизация идемпотентна по (run_id, step, metric).

**Состояния задачи:** `queued → waiting_quota → preparing → training → checkpointing → paused_quota → resuming → evaluating → packaging → awaiting_approval → completed`; а также `failed`, `interrupted`, `cancel_requested`, `cancelled`. При преждевременном завершении не выдумывать `paused_quota`: если причина неизвестна — `interrupted`; автоматически продолжать лишь после проверки входных hash и checkpoint.

**Продолжение после квоты:** система не «наращивает токены», а повторно выделяет вычисления, при доступности **новой** квоты запускает job из checkpoint, считывает историю шагов, не меняет глобальную нумерацию, собирает кривую loss по всем сессиям. Если checkpoint только с LoRA без optimizer state — это **warm start следующего этапа**, а не точное продолжение обучения; в UI это отдельный режим.

**Пауза из-за квоты** не всегда возможна: внезапно оборванный notebook не обязан выполнить код финального checkpoint. Поэтому периодическое сохранение, аккуратный checkpoint до лимита времени и запас ресурсов на выгрузку обязательны.

## Инкрементальные эксперименты по промптам и примерам

1. **Без обучения**: базовая открытая модель + разные промпты/few-shot-примеры, шаблон SVG, сравнение на фиксированной проверочной выборке.
2. **Малый SFT LoRA/QLoRA**: те же лицензированные пары «описание/PNG/структурный JSON → SVG» + отрицательные примеры; проверка на новых, не попавших в train схемах.
3. **Повторное дообучение**: новая ревизия датасета + replay старых одобренных примеров, чтобы не забывать предыдущие. Новая версия адаптера, новая кривая и независимые A/B-метрики. Не изменять прежние веса.
4. **Дистилляция**: teacher выдаёт проверенные структурированные ответы; использовать лишь данные, на которые есть права, и учитывать ограничения лицензий teacher/outputs. Student обучается на лицензированных и очищенных парах; измерять качество/скорость/стоимость.
5. **Выпуск**: упаковать tokenizer, base SHA, adapter, recipe, manifest, метрики, checkpoint info, данные о лицензии и отчёт QA; принять новую модель **вручную**. Предыдущий approved artifact остаётся доступен.
6. **Применение**: 5–10 иллюстраций за пакет, предложение SVG/PNG в R3.6, явное утверждение каждой замены, без массового перезаписывания книги.

## Интерфейс Верфи

В карточке модели: `model version`, `train job`, `dataset version`, `provider`, `quota status`, `last_verified_checkpoint`, `next_resume_possible`, `last_sync`. Графики: train/val loss (ось X = глобальный step), LR, grad norm, VRAM, text accuracy, SVG structure/compile error, оценка экспертной приёмки. Вертикальные маркеры: смена сессии, пауза, checkpoint, изменения конфигурации **в новой версии**.

Кнопки: «Смотреть графики», «Журнал», «Скачать адаптер», «Восстановить из checkpoint», «Дать ещё примеры → новая редакция», «Проверить квоту», «Продолжить вручную», «Запланировать проверку квоты» только при явном согласии, «Отменить задание» только своё. **Редактор книг, текст и иллюстрации остаются доступными.**

## Очерёдность после завершения главного конвейера

1. Изоляция карточек моделей + замок только редактируемой ревизии (HTTP 409 на изменение).
2. Реестр checkpoints, datasets, license manifest, metrics JSONL, кривые и импорт provider logs — **без запуска обучения**.
3. Первый короткий бесплатный eval / LoRA на строго ограниченной синтетической выборке, checkpoint и восстановление.
4. Проверка паузы/возобновления через завершение ноутбука, воспроизводимость `global_step` и отсутствие перерасхода.
5. Только затем включение обучения по одобренным реальным авторским примерам и выпуск модели для R3.6.

**Этот документ не запускает задачи и не устанавливает модели. Текущая разработка: R3.6 manual host QA → R4 normative preflight/bibliography.**
