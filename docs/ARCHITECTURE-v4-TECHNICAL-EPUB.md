# RFC-0004 — ACHEWIW: технические книги, EPUB-first и проверка перед выпуском

**Статус:** архитектурная спецификация — не заявлять как реализованный UI. **Приоритет:** электронная книга с локальным просмотрщиком; печать и исходники издательства только после того, как EPUB/предпубликационные проверки стабильны.

## Цель

«Закулисная мастерская» выпускает **художественные, технические, научно-популярные, учебные, справочные и методические издания** на одном движке карточек и версий. Художественный StoryGraph имеет канонические события; техническая литература опирается на KnowledgeGraph доказательств, ссылок, терминов и методик. Исходники и произведения сохраняются независимо от производных EPUB/PDF.

## Форматы произведения

`PublicationType = fiction | technical | scientific_popular | textbook | manual | reference | performance | periodical`.

`PublicationProfile` задаёт структуру: обложка, титул, целевая аудитория, чему научит издание, требования к читателю, организация глав, иллюстрации, библиография, словарь терминов, предметный указатель, приложения. Для повествования переключает «сюжетные нити»; для технических книг переключает «ссылки/определения/схемы/проверяемые утверждения». Персональные настройки жанра можно задавать на уровне тома, главы, секции, блока.

## Структура технической публикации

`Work > Part/Volume > Chapter > Section > Block`, где `Block.kind`:
- `paragraph` — исходный авторский текст;
- `definition` — термин, формулировка, альтернативные названия, статус утверждения и ссылки на карточки употребления;
- `theorem|claim` — утверждение, границы применимости, уровень уверенности, привязка к доказательству;
- `formula` — LaTeX/math, номер, определение величин и единиц;
- `code` — язык, версия, входы, воспроизводимая команда, ожидаемый вывод и версия проверки;
- `diagram` — Mermaid/Graphviz/PlantUML или собственный SVG с ссылками на источники;
- `table` — табличные исходные данные с единицами, подписью, таблицей прав;
- `figure` — alt-текст, описание, источник/права, номера и ссылки на текст;
- `citation` — DOI/URL/библиографические поля, точная привязка к утверждению;
- `callout` — совет, примечание, опасность, ограничение;
- `exercise` — задача, решение, ссылки на требования;
- `quiz` — при необходимости;
- `glossary-entry` — словарная карточка, связанные термины;
- `appendix` — дополнительные материалы.

Карточки хранятся независимо от оформления. Упоминаемые определения связываются с **первым содержательным введением** и автоматически проверяются на несогласованность.

### Автоматически собираемое предисловие

Поле `AudiencePreface`: кому адресована книга; чего читатель достигнет; входные знания; как пользоваться примерами и схемами; что входит и не входит; версии зависимостей и дата актуальности; контактные сведения только с разрешения автора. ИИ предлагает текст предисловия, но не выдумывает квалификацию автора и не объявляет книгу научно рецензированной без доказательств.

### Словарь терминов и база знаний

`Term`: id, preferred_name, aliases, definition, discipline, disambiguation, first_use_card_id, source_ids, related_term_ids, author_verified, version. Переименование термина — транзакция по зависимостям с авторским предпросмотром.

`KnowledgeClaim`: id, text, `support_status=unverified|source_located|verified|disputed|outdated`, `citations`, `scope`, `verified_by_author`. RAG находит источники, **не ставит статус verified за автора**. Карточки «что точно установлено» отделены от гипотез, учебных упрощений и художественных допущений.

## Научные/публичные источники

`Reference`: id, creator, title, publisher, date, accessed_at, DOI, canonical URL, type (peer_reviewed|standard|government|documentation|preprint|book|public_web), license, rights_notes, quote_spans, metadata_source, retract/update status, verification_method, original snapshot/quote provenance.

- Никаких придуманных DOI/ссылок: `unverified` по умолчанию, проверять ответ от реестра/страницы при запросе и сохранять дату обращения.
- Кандидаты: Crossref API для DOI-метаданных, DataCite API для иных DOI, OpenAlex для поиска публикаций, официальные документации/нормативные реестры, открытые библиотеки; качество и доступность оценивать отдельно.
- Метаданные Crossref не доказывают истинность научного вывода. Для технических утверждений проверяются конкретные страницы/разделы/измерения, а не только совпадение заголовка.
- Библиография хранится в `CSL JSON` / `BibTeX`, экспорты IEEE, APA, ГОСТ-подобный (с указанием принятого регламента, без утверждения универсального соответствия).
- Каждая цитата ссылается на `reference_id + locator`; на черновые источники — предупреждение.
- Битые ссылки: предупреждение и запрос подтверждения; отсутствие интернета само по себе не превращает ранее верифицированный источник в «ложный».
- Доступ к сети только по согласию, аннотации источников в локальном архиве с учётом лицензии. Не зеркалировать закрытые платные статьи без прав.
- Для RAG разделить доверенные approved sources, черновики LLM и внешние недоверенные документы; контент веб-страниц никогда не исполняется как инструкции модели (защита от prompt injection).

## Два уровня QA и издательский шлюз

### QA содержания (до верстки)

1. Структура и канон: ID, причинность, таймлайн, глоссарий, цитирование и определения.
2. Научно-техническая проверка: формулы/единицы/версионность API, код и схемы с журналом тестов, надежность ссылок, рецензирование человеком, заявление об уровнях уверенности.
3. Оригинальность: similarity report (источник, отрывок, степень совпадения, возможное цитирование/заимствование, лицензия/разрешение) **не является юридической оценкой**. НЕ вводить магический «допустимый процент плагиата»; даже маленькая ключевая цитата может нарушать права, а большие корректно лицензированные блоки могут быть разрешены. Отдельные rights flags для исходников, обложки, иллюстраций, шрифтов, кода и чужих графиков.
4. Правовые/регуляторные риски: policy profile по **целевой стране и рынку, возрасту, виду продукции, дате, издательству**. Категории: авторское право, товарные знаки/личные данные, дискриминационные или потенциально запрещённые публикационные риски, отдельные требования распространителей. Это **только сигналы для проверки**, не «автоматический суд» и не универсальный список запрещённых идей. Категории чувствительного контента не подменяют объективную оценку научных данных и свободу художественного выражения.
5. Авторские approvals: содержимое, ссылки, права, местное законодательство при необходимости, художественный/технический редактор.
6. QA доступности: alt-текст, заголовки по иерархии, подписи, контраст, навигация, семантика таблиц, описания технических схем.

### QA формата (после верстки)

EPUBCheck и отдельный внутренний proof в читалке; проверка читабельности кириллицы, шрифтов/их лицензий, ритма абзацев, переносов, ссылок/сносок, семантики/доступности. Для печати — отдельный PDF preflight, ICC, шрифты/встраивание, разрешение изображений, Trim/BleedBoxes, комплектность ссылок и шаблон типографии.

### Публикационный шлюз — конечный автомат

`draft → content_review → rights_review → format_build → format_preflight → proof → author_approved → released`.

Критические машинные ошибки (битая структура, отсутствие утверждённой версии, отсутствующие атрибуты/ресурсы, неразрешённые обязательные лицензии) **блокируют финальный выпуск**. Результаты similarity report и LLM правовой классификации создают **очередь ручного решения**, но не автоматический вердикт. Автор фиксирует обоснование/разрешения, при необходимости привлекает юриста. После правки содержимого или оформления зависимые approvals сбрасываются по hash, но старые релизы сохраняются.

Важно: автор имеет техническую возможность получить **черновой preview** для собственной проверки; «release» отличается от «build preview». Без такого различия невозможна нормальная редактура.

## ЭЛЕКТРОННОЕ ИЗДАНИЕ — ПРИОРИТЕТ №1

**Основной формат: EPUB 3.3, reflowable**, включая главы, рисунки, SVG, семантические таблицы, формулы/MathML с fallback при необходимости, сноски, внутренние переходы, оглавление, глоссарий, библиографию. Для высокодетализированных атласов/верстки допускается отдельный `fixed-layout` EPUB или PDF, но **не замена** адаптивной книги.

- EPUB 3.3 W3C Recommendation: https://www.w3.org/TR/epub-33/
- EPUB Reading Systems 3.3: https://www.w3.org/TR/epub-rs-33/
- EPUB Accessibility 1.1: https://www.w3.org/TR/epub-a11y/
- EPUBCheck: https://github.com/w3c/epubcheck (проверять совместимость версии с целевой EPUB-спецификацией; на 2026-11-02 версия 5.4.0 — валидатор с поддержкой EPUB 3.4).
- EPUB.js: https://github.com/futurepress/epub.js (BSD-licensed browser rendering library; подключать локально, без внешних CDN).
  
### EPUB Viewer — приложение внутри ACHEWIW

Читательский экран `/reader/{edition_id}` должен читать **ровно тот EPUB-артефакт, который будет экспортирован** (а не отдельную HTML-подделку макета). Отличать UI прототип от готового EPUB viewer.

Функции:
- оглавление, поиск, закладки, выделения, заметки, история чтения;
- изменение гарнитуры, масштаба, межстрочного интервала, светлая/тёмная/сепия темы, reflowable pagination/continuous, адаптация к телефону;
- внутренние ссылки на сноски, словарь, формулы, таблицы; просмотр SVG и масштабирование схем;
- раздельные режимы **«читатель» (чистая книга)** и **«редактор» (якорь/карточка, точечный комментарий, diff)**;
- позиция в формате EPUB CFI или похожий стабильный локатор, связанный с `edition_id/manuscript_hash`; новая редакция не должна молча перетаскивать старые закладки;
- подогнанное чтение технической книги — код с переносами/горизонтальной прокруткой, специальное внимание к длинным формулам и wide tables;
- офлайн по выбранным сохранённым экземплярам, чтение локальных импортированных книг только через защищённый обработчик;
- приватность: без скрытого сбора действий чтения; пользователь явно решает, сохранять ли историю и заметки.

**Безопасность для пользовательских EPUB:** ZIP size/ratio limits, sanitize HTML/SVG/URL, не выполнять embedded scripts, CSP, sandbox/origin isolation, блокировать file://, URL с опасными схемами, чужие network requests и автоматические внешние ссылки. Нужна проверка против ZIP bomb/XXE и запретить активный код в импортированных книгах по умолчанию.

Механика редакторской проверки: `editor opens card → build preview EPUB → view exact result → flag issue at locator → jump to source card → revise → preview again`.

## ВЫХОДНЫЕ ФОРМАТЫ

- **Priority 1 — EPUB 3.3 + ACHEWIW Viewer**: основной электронный продукт.
- **Priority 2 — Reading PDF**: доступный для скачивания PDF с оглавлением и работающими ссылками, аккуратная A4/A5 версия для домашней печати (не путать с PDF/X).
- **Priority 3 — Publisher Editable Package**: `manuscript.docbook.xml` (DocBook 5.2), ODT, семантические HTML/CSS, Markdown+assets, опциональный LaTeX, CSL JSON/BibTeX, SVG assets и оригиналы изображений; manifest + лицензии + шрифтовые требования.
- **Priority 4 — PDF/X**: под конкретный пресс/бумагу и ICC профиль типографии, отдельно обложка/блок, проверки bleed/trim, Scribus SLA при реализации полноценного подготовленного макета. SLA не следует выдавать, пока не доказана корректность автоматического импорта в выбранную версию Scribus.
- **Priority 5 — журнал/газета/брошюра/флаер/мерч** с отдельными шаблонами.

**Один master format для всех книг — структурированная база с карточками и версиями**, а не PDF/EPUB как исходник. DocBook XML — хороший исходный формат передачи для технической литературы (https://docbook.org/schemas/docbook/).

### PublisherPackage (передача издательству)

`/edition-N/`: `manuscript.docbook.xml`, `manuscript.odt`, `references.csl.json`, `references.bib`, `assets/{id}.svg|png|tiff`, `style-guide.md`, `fonts-and-rights.md`, `publication-manifest.json`, `proof-reading.pdf`, `preview.epub`, `editor-synopsis.md`. Наличие каждого файла в конкретной сборке отмечается отдельно в manifest; не обещать то, что не создано.

Профиль `publisher_custom` задаёт требуемые форматы и шаблоны; качество ручной верстки издательства не зависит от нашей версии.

## Минимальная дорожная карта

P0: канон/карточки/версии + KnowledgeGraph типов блоков (обязательно).
P1: reliable source registry, glossary, cite+diagram blocks, QA с provenance.
**P2: EPUB builder → встроенный EPUB viewer → EPUBCheck → proof/approval (самый первый готовый продукт).**
P3: reading PDF, удобный print-at-home PDF, пакет редактируемых исходников.
P4: publisher-specific PDF/X and prepress, рабочая совместимость Scribus, новые профили.
P5: остальная маркетинговая и полиграфическая линейка.

Все новые модули работают поверх стабильной графовой БД; обновление одного абзаца не перегенерирует весь мир. Никакого переноса Ollama внутрь Docker или установки новых моделей без отдельного решения автора.
