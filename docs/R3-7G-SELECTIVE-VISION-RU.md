# ACHEWIW R3.7G — поштучное принятие предложений Vision

Статус: отдельная экспериментальная ветка от R3.7F; не установлена на Huananzhi. Для R3.7F пользователь сообщил 24/24 Node-тестов и 27/27 проверок DOCWORK.

## Назначение
После загрузки допустимого JSON `achewiw-vision-proposal` каждое предположение отображается **только для просмотра**, с отдельными кнопками «Принять фигуру» и «Отклонить». При принятии редактор повторно проверяет границы и тип, показывает подтверждение и добавляет одну фигуру на ручной холст. Предложения не принимаются автоматически, даже с высокой оценкой уверенности. Отклонённые предложения не добавляются.

Действие «Принять» использует текущую привязку к черновику, индексу рисунка, версии рисунка и размерам. Если контекст сменился, список закрывается без переноса. Принятая фигура входит в обычную локально сохраняемую разметку (R3.6.1), её можно отменить через Undo. Только отдельное действие «Применить замену в книге» создаёт новый PNG-asset. Исходный DOCX остаётся неизменным. Никаких новых API, GPU-аренд, загрузок vision-моделей или миграций SQLite.

**Ограничение:** решения «Отклонить» и сам список непроверенных предложений живут только до перезагрузки страницы или смены рисунка. Принятые фигуры сохраняются как ручная разметка. Этот этап не делает распознавание исходного растра: JSON предстоит создать/получить отдельно.

## Автоматическая приёмка
1. `node --check app/static/vision_proposals.js && node --check app/static/docwork_workbench.js`.
2. `node --test tests/diagram-graph.test.cjs tests/diagram-import.test.cjs tests/vision-proposals.test.cjs` — ожидается 28 Node-тестов.
3. `docker exec -i -w /app achewiw-studio python - < scripts/docwork-image-host-smoke.py` — 27 прежних регрессионных проверок.
4. В браузере на синтетическом DOCX: загрузить JSON с несколькими предложениями; убедиться, что без нажатия «Принять» рисунок не меняется. Отклонить первое, принять второе — только второе появляется на холсте.
5. Нажать Undo, проверить удаление только последней принятой фигуры; F5 должен сохранить принятый ручной слой.
6. Изменить выбранный рисунок и проверить отсутствие предложений из предыдущего изображения.
7. Повторно открыть исходный DOCX; убедиться, что оригинальные байты и другие книги не изменены.
8. Проверить отказ для координат за холстом, пустых надписей, слишком коротких линий, повреждённого и чужого JSON.

## Следующие шаги

Сначала оценить существующие локальные модели, GPU-очередь и качество на размеченных примерах, затем включать модель строго по явной команде. Генерацию книг и литературные повторы в этой ветке не исправлять.
