# Перевод ACHEWIW на 2 ветки

**Публикуемая:** `main` — новая редакция издательского конвейера.  
**Архивная:** `archive/dual-model-20261105` — предыдущая версия генератора.

Остальные ветки удаляются только после того, как уникальные истории входят в `main`. Старые PR будут закрыты как заменённые выпуском на `main`, но их обсуждения сохранятся.

## Почему не `git reset --hard`

`main` и старые RFC-ветки имели разные корни истории. Чтобы не потерять уникальные коммиты, выпуск формируется объединяющим коммитом с несколькими родителями; рабочее дерево выбирается из проверенной версии конвейера. Старые идеи Release Gate сохранены как экспериментальные файлы `app/release_gate_core.py`, тесты, схемы. Деструктивные скрипты сброса базы не подключаются к текущему конвейеру.

## Как очистить ветки на GitHub с сервера после валидации

```bash
cd /1tbdisk/achewiw
git status --short
git fetch --no-tags origin
git switch main
git pull --ff-only origin main
bash scripts/prune-legacy-branches.sh preview
# если все проверки пройдены:
bash scripts/prune-legacy-branches.sh apply DELETE_OLD_ACHEWIW_BRANCHES
```

Скрипт откажется удалять ветку, если она содержит хоть один коммит, не доступный из `origin/main`. Он не трогает `main`, `archive/dual-model-20261105`, `data/`, контейнеры Docker или Ollama.

### Почему это отдельная команда

GitHub-коннектор позволяет читать/обновлять файлы, коммиты и PR, но в текущем подключении не предоставляет операцию удаления Git-ветки. Поэтому реальное удаление производится с сервера, где у владельца уже настроены полномочия Git, только после просмотра preview. Не выдавать созданный скрипт за выполненное удаление.
