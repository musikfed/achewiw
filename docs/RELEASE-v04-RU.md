# ACHEWIW — v0.4: настоящий мониторинг, иллюстрации и подготовка книги к выпуску

Рабочая ветка: `feature/technical-epub-first`  
Каталог на Ubuntu: `/1tbdisk/achewiw`  
Web: `http://192.168.0.100:7080` через свою доверенную LAN/VPN. Паролей HTTP Basic нет.

## Исправление мониторинга и компактная панель · 4 ноября 2026

При первом запуске нового `achewiw-metrics-v2.service` systemd успешно создал ссылку `~/.config/systemd/user/achewiw-metrics-v2.service`, но проверка ошибочно требовала, чтобы `FragmentPath` содержал только исходный путь `/1tbdisk/achewiw/ops/achewiw-metrics-v2.service`. Это объясняет `Loaded: linked` одновременно с `Active: inactive (dead)`.

В `scripts/monitor-v2.sh` исправлена **проверка настоящей цели ссылки** (`readlink -e`), плюс проверяются точные `WorkingDirectory` и `ExecStart`. Проверка чужих единиц systemd остаётся строгой. Новая регрессионная проверка воспроизводит именно случай Ubuntu с симлинком.

На главной странице монитор теперь **компактный**: небольшой заголовок, четыре негромоздкие карточки CPU/RAM/GPU/Ollama; длинная подсказка спрятана под «Диагностика датчиков». Кнопка «Свернуть» запоминает состояние локально в браузере; регулярное получение метрик не прекращается.

Для этого исправления **не нужно снова стирать SQLite** и очищать какие-либо архивы. После `git fetch` и `git merge --ff-only` достаточно `bash scripts/monitor-v2.sh start` для CPU/RAM/GPU и **одной** пересборки `bash scripts/achewiw-control.sh rebuild` для обновлённого компактного интерфейса. При первой проверке после запуска Docker может быть краткая задержка готовности HTTP; отдельно повтори `auth-check`, не удаляя контейнер вручную.

Полный алгоритм и команды: [MONITORING.md](MONITORING.md).

## 1. Почему показывало «Нет данных» в CPU, RAM и GPU

Веб-контейнер читает `data/monitor/host.json`, но сам **не запускает nvidia-smi и не получает доступ к GPU хоста**. Раньше обычный `rebuild` менял только веб-контейнер. Старое имя systemd `achewiw-host-monitor.service` оказалось не подтверждено и запуск блокировался.

Для устранения конфликта появился **отдельный точно названный user-unit** `achewiw-metrics-v2.service` и контроллер:

```bash
cd /1tbdisk/achewiw
bash scripts/monitor-v2.sh once     # снимок CPU RAM GPU сразу, без запуска службы
bash scripts/monitor-v2.sh start    # самостоятельный сборщик каждые 5 секунд
bash scripts/monitor-v2.sh status
```

Новая служба использует `/usr/bin/python3` на самом Ubuntu и `nvidia-smi`, пишет только `/1tbdisk/achewiw/data/monitor/host.json`. Общая Ollama и старые/чужие systemd-службы **не перезапускаются**. Если `start` не выполняется, нужен вывод `systemctl --user status achewiw-metrics-v2.service --no-pager` и `journalctl --user -u achewiw-metrics-v2.service -n 30 --no-pager`. Если `nvidia-smi` отсутствует на хосте, GPU честно остаётся «Нет данных» при работающих CPU/RAM.

Состояние моделей Ollama берётся отдельно из локального API `/api/ps`. `Загружены: нет` означает, что модель пока выгружена — это **не** отсутствие установленных моделей.

## 2. Где выпуск PDF и редакторских файлов

После выбора книги:

- верхняя кнопка **«06 · Типография: PDF / DOCX / EPUB»**;
- вкладка **«06 · Типография / Экспорт»**;
- кнопки реального скачивания: `EPUB 3`, `FB2`, `DOCX`, `PDF A5 для чтения`, `PDF A5 печатная проба`, `Markdown`.

В эти файлы попадает **только утверждённый и сохранённый текст** глав, плюс иллюстрации, привязанные к написанным главам. Если имеется только QA-отчёт без написанных сцен, пустой PDF **не выдаётся**: сначала нужно сохранить хотя бы одну главу.

**Для настоящего коммерческого тиража:** A5-печатная проба — корректный PDF с кириллическим шрифтом и изображениями, но она пока **не PDF/X-4**. Перед передачей типографии нужно уточнить формат обреза, выпуск за обрез, профиль ICC, разрешение картинок и требования конкретного исполнителя. DOCX — редактируемый исходник для редакции, в нём сохраняется текст и изображения. Скрипты не выдают заглушку под видом сертифицированного файла для тиража.

## 3. Иллюстрации — новая самостоятельная вкладка

Вкладка **«04 · Иллюстрации»** (и верхняя кнопка «Иллюстрации») теперь позволяет:

1. выбрать конкретную главу/сцену;
2. загрузить реальную картинку PNG/JPEG/WebP до 12 МиБ;
3. указать подпись и размещение **после заголовка** или **после текста** главы;
4. увидеть изображение в галерее, удалить выбранное;
5. скачать иллюстрированную электронную/печатную пробу и редактируемый DOCX.

Рисунки преобразуются в PNG, проверяются через Pillow и хранятся отдельно под `data/illustrations/<project-id>/`. Никакого HTML, произвольного file path или внешнего URL в книгу не подмешивается. Часть допустимого файла может увеличиться при конвертации — лимит на выходной PNG 50 МиБ.

### Автоматическое переключение между текстовой LLM и изображениями

Установленные сейчас модели `qwen3:8b`, `qwen2.5-coder:14b`, `qwen2.5vl:7b`, `granite3.2-vision:2b` **не являются генераторами PNG**. Vision-модели распознают/описывают изображения, но не рисуют новые.

Добавлен отдельный **реальный**, но **опциональный** движок `ComfyUI`, ожидаемый на `127.0.0.1:8188`. Если он запущен и имеет checkpoint, ACHEWIW обнаруживает его, выбирает установленный checkpoint автоматически (предпочитает SDXL), отправляет текстовый запрос в workflow и сохраняет полученную картинку в выбранную главу. Если ComfyUI нет, генерация **отключена и прямо сообщает причину**; загрузка готовых картинок остаётся доступна. ComfyUI **не устанавливается и не запускается автоматически** — он может конкурировать за общую RTX 3060.

**Освобождение VRAM:** перед графической задачей можно отметить специальный чекбокс, чтобы **после твоего отдельного подтверждения** запросить выгрузку только выбранной текстовой модели из **общей Ollama**. Все остальные модели, CUDA-контексты и графические приложения остаются на месте. Без этого чекбокса Ollama не выгружается. При наличии загруженной Ollama backend перед совместной генерацией дополнительно требует подтверждение конкуренции за GPU. Следующий текстовый запрос загрузит модель обычным способом.

Для SDXL 1024×1024 и 12 ГБ VRAM может понадобиться освободить место; модель на диске размером 5–9 ГБ не равна фактической сумме VRAM с KV-cache. Это не гарантирует отсутствие OOM, поэтому реальные изображения надо проверять по метрикам GPU. ComfyUI — отдельная установка, не замена Ollama.

## 4. ОБЯЗАТЕЛЬНО: выбор между обычным обновлением и полной очисткой

**Обычное обновление сохраняет рукописи:** `bash scripts/update-editorial.sh`. Оно обновляет Git fast-forward, пересобирает только `achewiw-studio`, проверяет HTTP и пытается включить свой монитор v2.

**Чистая установка (то, что запросил автор) УДАЛЯЕТ ВСЁ в библиотеке ACHEWIW.** Старый проект «Космо-мартышки», задания, QA, тексты, изображения и резервные копии собственных SQLite-баз **будут необратимо потеряны**. По требованию автора **новый архив при сбросе не создаётся**. Это сознательная опция, **не побочный эффект Git-update**. Перед запуском проверь, что ничего важного не осталось.

Сначала обновить код и посмотреть точный список удаления без изменений:

```bash
cd /1tbdisk/achewiw
git status -sb
git fetch --no-tags origin
git merge --ff-only origin/feature/technical-epub-first
bash scripts/reinstall-studio-fresh.sh preview
```

Затем **только если нужен действительно пустой запуск без старых книг и архивов**:

```bash
cd /1tbdisk/achewiw
bash scripts/reinstall-studio-fresh.sh ERASE_ACHEWIW_LIBRARY_AND_ARCHIVES
```

Скрипт:
- проверит ветку, Git origin, отсутствие незакоммиченных изменений, `compose config --services=studio`, точные Docker-метки и `/data`-mount;
- остановит **только** `achewiw-studio`, не затрагивая другие Docker-проекты;
- удалит ровно `data/achewiw.sqlite3` с WAL/SHM, свои архивы `data/backups/achewiw-before-*.sqlite3`, `data/illustrations/`;
- пересоберёт **только** `studio` и запустит его с новой пустой SQLite (FastAPI создаёт таблицы при старте);
- проверит отсутствие HTTP Basic, включит отдельную службу CPU/RAM/GPU v2 и покажет результат.

**Чего скрипт НЕ делает:** `rm -rf /1tbdisk`, `docker system prune`, `docker compose down -v`, `git reset --hard`, удаление `.env`, `data/monitor/`, действий с проектами `YadroKreator`, `wificam_T23N` и общей Ollama.

Если есть ещё неизвестные старые файлы внутри `data/`, скрипт не удалит их вслепую: покажи имена перед отдельной проверкой.

## 5. Проверка после пересборки

```bash
cd /1tbdisk/achewiw
bash scripts/achewiw-control.sh auth-check
bash scripts/monitor-v2.sh status
docker compose -f compose.yaml ps
```

В браузере открой `http://192.168.0.100:7080` и обнови страницу `Ctrl+Shift+R`. В новом UI должны появиться **«04 · Иллюстрации»** и **«06 · Типография / Экспорт»**.

Общие host-модели, сервисы 1С, VPN, системные контейнеры и остальные проекты лежат за границей ACHEWIW и здесь не управляются.
