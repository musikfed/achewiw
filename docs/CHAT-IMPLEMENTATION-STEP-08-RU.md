# ACHEWIW · Шаг 08 — две чатовые вкладки в существующей студии

**Статус:** UI в отдельной Draft-ветке, не развёрнут на сервере. Новых сервисов, портов и замены исходного интерфейса нет.

## Как работает пользовательский интерфейс

- Существующие вкладки `01 Задание`, `02 План`, `03 Редактор`, `04 Иллюстрации`, `05 Проверка`, `06 Типография` сохранены в прежнем порядке, структуре, стиле и функциональности.
- Добавлены `07 Чат генерации` (сохранение поручений, режим уточнения/автономный, план операций по этапам 01–06) и `08 Чат редактуры` (история, сохранённые редакции, конкретная глава, Ollama-кандидат, unified diff, принятие/отклонение).
- Чат генерации **пока не запускает создание книги** по сообщению. Он выполняет только планирование через существующий planner API. Настоящая генерация книги остаётся в старой вкладке до следующего шага связи с job/RAG/Graph.
- Чат редактуры позволяет выбрать существующий снимок книги `work_book_versions` или создать новый снимок авторской рукописи через существующий API. Это **копия**, не перезапись оригинала. При повторном выборе другого снимка уже подключённая рабочая редакция не переключается молча.
- Для короткой главы (до 4500 символов) команда сохраняется в SQLite, запрос `ollama-candidate` использует выбранную модель панели «Модель на хосте», и ответ возвращается только как предложение.
- `Принять новую редакцию` вызывает отдельный `decision`, `Отклонить` ничего не меняет в книге. Отображение diff — через `textContent`, без выполнения HTML/JS, пришедших от модели.
- Thread ID хранится в проектно- и workspace-scoped ключе браузера, но история и предложения — **на сервере в SQLite**. После обновления вкладка запрашивает сохранённые сообщения и восстанавливает предложенный diff с сервера. Никакой старый проект автоматически не открывается при загрузке главной страницы.
- Выделенный `chat_studio.js` добавлен в allowlist статических файлов через `app/main.py`, а также в уже существующую проверку версионированных ресурсов `scripts/verify-versioned-assets.py`. Он использует самостоятельный cache key `20261125-chat-v1`. Другие версии существующих JS/CSS не меняются.

## Проверка

```bash
node --check app/static/chat_studio.js
python3 scripts/verify-versioned-assets.py
python3 -m unittest discover -s tests -p 'test_chat_studio_ui.py' -v
python3 -m unittest discover -s tests -p 'test_chat_ollama_editor.py' -v
python3 -m unittest discover -s tests -p 'test_chat_editorial_api.py' -v
```

UI-тест охватывает сохранность восьми вкладок, отсутствие HTML-вставки LLM, доступность контролов и восстановление diff на временной SQLite. Браузерный визуальный E2E на существующем тестовом сервере — следующий этап, он ещё не исполнен.

## Известные ограничения

- Пока нет виджета списка нескольких сохранённых чатовых бесед — одна выбранная ветка для каждой книги/мастерской; интерфейс диалога не ведёт физическую редактуру DOCWORK.
- Принятая версия доступна в `work_book_versions` и редакторском API, но не заменяет автоматически канонический текст книги или выбор типографии. Это необходимо довести отдельной явной интеграцией, без переключения редакций тайком.
- Работа с большой главой будет реализовываться как пофрагментная обработка с контролем общего контекста, а не снятие всех лимитов.
- Диктовка и запуск автономной full-book generation из чата пока не подключены.
- UI зависит от цепочки Draft PR до #71 и исправленного lifecycle CI #70. Не сливать ветку отдельно.

**Не создаём отдельный сервер `17080`**. Существующие рабочие `7080`, DOCWORK и пользовательские рукописи этим шагом не меняются.
