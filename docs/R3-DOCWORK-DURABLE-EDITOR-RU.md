# ACHEWIW · R3 — черновики DocWork, F5 и история редакций

**Дата:** 23 ноября 2026 г.  
**Ветка:** `fix/r3-docwork-durable-sessions-20261123` → draft PR №26.  
**Состояние:** экспериментальная реализация в GitHub, НЕ развёрнута на Huananzhi.  
**Область:** только существующий редактор `/docwork/` внутри одного ACHEWIW.

## Что меняется

Раньше DocWork держал выбранный файл, стиль, правки абзацев и поиск только в памяти JavaScript. При F5 всё исчезало. В R3:

1. **Серверный черновик:** после «Проверить структуру» исходный DOCX/PDF сохраняется в `docwork_drafts` SQLite **один раз**, с SHA-256. Действующие пользовательские проекты, канон книг и таблицы генерации не меняются.
2. **Автосохранение:** параметры оформления, ручные замены, роли абзацев, открытая незавершённая редактура и фильтр/поиск сохраняются как маленькие состояния. Изображения и оригинал **не дублируются** с каждой версией.
3. **Восстановление после F5:** в `sessionStorage` текущей вкладки хранится случайный ключ доступа к черновику; после перезагрузки браузер запрашивает исходник и последнюю версию с сервера. На случай изменения во время перезагрузки во вкладке отдельно хранится локальная «страховочная» запись состояния; серверная ревизия имеет приоритет при конфликте.
4. **Несколько вкладок:** сохранение передаёт текущий номер редакции; устаревшая вкладка получает HTTP **409**. Нет механизма тихой перезаписи; пользователь может скачать свои правки как JSON и отдельно обновить версию сервера.
5. **Неизменяемая история:** каждое подтверждённое сохранение получает новый номер. В интерфейсе можно выбрать старую версию и восстановить её **созданием новой**, не изменяя историческую запись.
6. **Закрытие:** удалить только текущий черновик DocWork и его редакции можно по явному подтверждению через кнопку. Отдельно проверяется, что библиотека книги и другие черновики остались нетронутыми.
7. **Доступ:** private LAN/VPN и проверка Origin, как в ACHEWIW ранее, плюс криптографически случайный ключ сессии. Сервер хранит только SHA-256 ключа; сам ключ не помещается в URL или Git.

## Размеры и защита диска

- Не более **5** черновиков DocWork.
- Суммарно не более **50 МиБ** исходных DOCX/PDF в черновиках.
- По **500** редакций на один черновик; при превышении — понятный отказ, а не стирание старых версий.
- Состояние одной редакции — не более **96 КиБ**, без дублирования бинарного исходника.
- Никакого скрытого таймера очистки, автоматических резервных копий, удаления журналов или установки моделей.
- Для освобождения лимита нужно вручную закрыть ненужный черновик **после скачивания результата**.

## Принципиальные ограничения

- Секретный ключ хранится во вкладке браузера (sessionStorage); **F5 сохраняется**, но при закрытии вкладки или очистке её данных доступ к черновику может быть потерян. Это не система долговременного хранения больших библиотек и не полноценная учётная запись.
- Локальные правки, набранные в миллисекунды перед аварийным отключением компьютера, не всегда попадут на сервер. Их восстановление после обычного F5 обеспечивается локальной записью, а успешный автосохранённый сервером результат подтверждается отдельным статусом.
- Текущая архитектура ACHEWIW рассчитана на доверенный частный LAN/VPN, **не на общедоступную многопользовательскую платформу**. Для внешних авторов позже потребуется отдельная аутентификация, ACL, политика хранения, договорные согласия и антивирусные проверки.
- Изначальный файл хранится в **той же локальной SQLite**, что и другие данные сервиса, но в отдельной таблице. Это не резервная копия. Владелец ранее отказался от отдельного бэкапа текущего экспериментального сервера.
- Полная визуальная вёрстка, ГОСТ, библиография и выпуск чужих произведений — отдельные последующие стадии. Публикационный допуск 00-Д остаётся **BLOCKED**.

## Новые API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/docwork/drafts` | Проверка файла и создание черновика |
| GET | `/api/docwork/drafts/{id}` | Состояние и версия |
| GET | `/api/docwork/drafts/{id}/source` | Неизменный оригинал |
| PUT | `/api/docwork/drafts/{id}` | Новая версия с защитой от конфликта |
| GET | `/api/docwork/drafts/{id}/history` | Список сохранённых версий |
| GET | `/api/docwork/drafts/{id}/history/{version}` | Старая версия без изменения данных |
| DELETE | `/api/docwork/drafts/{id}` | Явно подтверждённое закрытие ТОЛЬКО выбранного черновика |

Доступ к каждой операции, кроме создания, требует заголовка `X-ACHEWIW-Docwork-Token`; для удаления дополнительно требуется `X-ACHEWIW-Confirm-Close-Draft: yes-delete-only-this-draft`. Это не публичный API для сторонних авторов.

## Проверки и порядок ввода

Запускать тесты только в изолированном runner или на копии без авторских данных:

~~~bash
PYTHONPATH=app python3 -m pytest -q tests/test_r3_docwork_sessions.py
node --check app/static/docwork.js
~~~

Тест-кейсы: F5 воссоздаёт документ и настройки с сервера; исходные байты/хеш неизменны; две вкладки дают конфликт 409; старые версии не затираются; чужой ключ не открывает данные; 5 черновиков и крупное состояние не приводят к бесконтрольному расходу диска; явное закрытие сохраняет другие книги.

**Нельзя сливать PR/обновлять сервер автоматически.** Отдельно потребуется одобрение владельца на изменение работающей системы и инициализацию двух новых таблиц SQLite, а также ручная проверка F5 в Firefox/Chrome и браузерного сценария двух вкладок.

**Далее по повестке:** R4 — профили оформления по конкретным ГОСТ и библиографическим нормам с привязкой к редакциям стандартов и доказательным контролем.
