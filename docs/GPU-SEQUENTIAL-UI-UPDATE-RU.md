# ACHEWIW v0.6: последовательная VRAM, промпты и сохранение UI

Рабочая ветка: feature/technical-epub-first  
Каталог на Ubuntu: /1tbdisk/achewiw  
LAN/VPN Studio: http://192.168.0.100:7080

Дата ревизии: 04.11.2026.

## Проверенная проблема и её устранение

До исправления сервер отклонял изображение при активной текстовой задаче, но мог одновременно принять новую задачу Ollama в момент рендеринга ComfyUI. Кнопка изображения также позволяла игнорировать проверку VRAM по подтверждению. На единственной RTX 3060 12 ГБ это могло приводить к конкуренции и OOM.

Теперь существует SQLite-таблица achewiw_gpu_lease. **Внутри ACHEWIW** три разновидности действий — текстовая генерация, подготовка SDXL-промпта и генерация иллюстрации — взаимно блокируют друг друга. Проверка выполняется атомарно вместе с созданием задания. Lease освобождается при успехе и ошибке, имеет срок жизни для восстановления после падения.

**Граница гарантии:** процессам других проектов невозможно приказать не использовать RTX 3060 через этот lock. При генерации изображения ACHEWIW дополнительно читает общую Ollama /api/ps. При наличии *любой* загруженной LLM генерация изображения запрещается; автоматического обхода через confirm_shared_gpu больше нет. Если Ollama недоступна, графическая задача тоже не запускается.

Выгрузка Ollama — только по отдельному разрешению автора, так как другие приложения могут пользоваться выбранной моделью. После генерации изображения можно отдельно разрешить ComfyUI освободить кэш моделей командой /free; это выполняется лишь при пустой очереди ComfyUI. Флажок по умолчанию **выключен**: автор сознательно включает его перед запросом освобождения памяти. ComfyUI может использоваться другими проектами, поэтому чужой кэш без согласия не выгружается. Освобождение VRAM не равно остановке графического сервера.

## Какой промпт лучше писать?

**Обычного русского описания достаточно для старта, но SDXL часто точнее следует конкретному английскому визуальному промпту.**

1. Напиши по-русски коротко и естественно: «Миирус — чёрный кот на московском бульваре 1964 года. Дождливое утро, реалистичная иллюстрация, без надписей».
2. По желанию нажми «Уточнить описание через выбранную Ollama». Перед началом ты увидишь подтверждение, что текстовая модель общая и по завершении ей будет отправлен keep_alive=0.
3. Результат на английском попадёт в **отдельное редактируемое поле**. Это не скрытая автоматическая вставка, ты можешь изменить результат и увидеть добавленные детали.
4. Нажми «Сгенерировать и добавить в главу». Если уточнение не нужно, поле английского промпта оставь пустым — ComfyUI получит обычное описание.
5. Перед запуском сервер читает /api/ps и проверяет внутренний GPU-lock. Если другая Ollama-модель всё ещё загружена, операция остановится без принудительной выгрузки.
6. При выбранном флажке ComfyUI после рендера получит /free, **только если его очередь пуста**.

Изменение первого описания в браузере автоматически сбрасывает старый подготовленный промпт, чтобы нельзя было случайно нарисовать устаревшую сцену.

## После F5 / Ctrl+Shift+R

| Элемент | Где хранится | Поведение |
| --- | --- | --- |
| Библиотека, книги, главы и принятый текст | SQLite на сервере | Сохраняются как прежде |
| Активная книга, рабочая вкладка, выбранная модель Ollama, выбранная сцена | localStorage браузера | Восстанавливаются после F5 |
| Выбранный вид мастерской | localStorage | Восстанавливается |
| Прокрутка страницы | sessionStorage | Восстанавливается в той же вкладке |
| Несохранённые поля проекта, рукописи и планы блоков | sessionStorage с проверкой server updated_at | Снимок обновляется во время ввода (350 мс) и перед закрытием страницы. После F5 возвращается, если серверная версия не изменилась; для записи в SQLite по-прежнему нужна кнопка «Сохранить» |
| Описание иллюстрации, подготовленный промпт, подпись и размещение | sessionStorage отдельно по книге | Восстанавливаются после F5; при восстановлении вкладки иллюстраций автоматически вызывается загрузка черновика |
| Флажки работы с VRAM | localStorage | Восстанавливаются |
| Запущенная из интерфейса установка ComfyUI, загрузка SDXL, запуск/остановка | Идентификатор задачи в sessionStorage и процесс контроллера на Ubuntu | После F5 браузер повторно подключается к текущей задаче и показывает журнал; скачивание не запускается вторично. Если сам контроллер перезапущен, задача может потерять наблюдение, но оставшиеся файлы скачивания сохраняются штатным скриптом |
| Выбранный файл через input type=file | Не сохраняется по правилам браузера | Нужно выбрать файл снова |
| Генерация рисунка в момент закрытия/обновления страницы | Не фоновые image-jobs | **Её продолжение и сохранение в ACHEWIW пока не гарантированы**. Не обновляй страницу во время рендеринга. Текстовые ai_jobs сохраняются в SQLite |

Если другая вкладка уже сохранила новый текст, старый локальный черновик не подставляется поверх него — страница выдаёт предупреждение. Для полного multi-tab merge потребуется отдельная система версий.

Для HTML, CSS и JS сервер уже отдаёт Cache-Control: no-store; пути к ассетам обновлены на editorial-v9. Ctrl+Shift+R достаточно для смены ресурсов, стирать browser localStorage НЕ нужно — иначе настройки и черновики будут потеряны.

## Управление локальным ComfyUI из интерфейса

После обновления `scripts/update-studio-clean.sh apply` запускает отдельный user-systemd host-control на `127.0.0.1:8190`. В окне «Иллюстрации» кнопка «Подготовить генератор» последовательно выполнит только недостающие действия: установку ComfyUI, загрузку SDXL (~7 ГБ) после отдельного подтверждения, запуск ComfyUI на `127.0.0.1:8188`. Команды выполняются на хосте, потому что Studio работает в Docker и не управляет процессами хоста напрямую. Контроллер принимает только фиксированный список действий, проверяет закрытый токен и не принимает shell-команды.

Сам checkpoint загружается в видеопамять при первом запуске генерации. После рисунка флажок освобождения ComfyUI отправляет `/free` только при пустой очереди; если очередь занята, память не трогается. Ответ `/free` подтверждает **приём команды**, а не гарантирует точное количество освобождённых мегабайт: измеряй фактическую VRAM через мониторинг GPU. Кнопка остановки завершает только подтверждённый PID ACHEWIW, а не чужой процесс. Во время обновления host-controller не перезапускается, пока в нём выполняется установка или скачивание SDXL.

## Доставка новой версии без удаления данных

**Сначала получить свежий скрипт:** старые локальные скрипты ничего не знают о новых режимах.

```bash
cd /1tbdisk/achewiw
git status -sb
git fetch --no-tags origin
git merge --ff-only origin/feature/technical-epub-first

bash -n scripts/update-studio-clean.sh
bash scripts/update-studio-clean.sh preview
```

Preview читает только метаданные, статус и SQLite read-only, не удаляет никакие файлы, не обновляет Git и не перезапускает контейнер.

**Когда все задачи Ollama и изображения завершены, применить:**

```bash
cd /1tbdisk/achewiw
bash scripts/update-studio-clean.sh apply
```

При apply:
- проверяется branch, Git origin и чистота рабочего дерева, только fast-forward без reset/clean;
- через read-only SQLite проверяется отсутствие работающей генерации ACHEWIW;
- удаляются лишь файлы *.pyc и пустые __pycache__ в app/ и tests/, без следования символическим ссылкам;
- контроллер проверяет подтверждённые метки и docker compose service=studio, затем запускает **docker compose build --no-cache studio** и пересоздаёт только свой контейнер;
- глобальный Docker builder-cache **не удаляется**, чтобы не повредить соседние проекты; --no-cache принудительно собирает образ заново;
- проверяются HTTP 200 и отсутствие Basic Auth; подключается либо обновляется только собственный host-control ComfyUI (лишь при отсутствии его активных операций) и запускается собственный v2 монитор;
- пользователь обновляет страницу Ctrl+Shift+R.

Остаются нетронутыми: data/achewiw.sqlite3, data/illustrations/, data/comfyui-runtime/ (ComfyUI/SDXL), .env, Ollama, VPN, драйвер Nvidia, контейнеры всех иных проектов и каталог /1tbdisk/PegineLab/projects.

ВНИМАНИЕ: rebuild создаёт новую Studio и может прервать уже начавшуюся HTTP-генерацию рисунка вне контроля SQLite. Поэтому сверяй состояние ComfyUI и не запускай deploy посреди рендера. Скрипт не останавливает ComfyUI и не делает prune.

## После обновления

```bash
cd /1tbdisk/achewiw

bash scripts/achewiw-control.sh auth-check
bash scripts/achewiw-control.sh status
bash scripts/monitor-v2.sh status
bash scripts/comfyui-control-agent.sh status
bash scripts/comfyui-local.sh doctor

# Только если ComfyUI ранее установлен и сам запущен:
curl --noproxy '*' -fsS --max-time 5 \
  http://127.0.0.1:8188/object_info/CheckpointLoaderSimple > /tmp/achewiw-check.json
```

Никакой GPU-тест через GitHub Actions не заменяет реальную проверку на RTX 3060. Автоматические тесты запускаются со смоделированной Ollama, SQLite и ComfyUI.
