# ACHEWIW — удаление книг из библиотеки (проверка)

## Что изменено

Кнопка «✕» на каждой карточке книги в левой панели, доступная при наведении мыши и с клавиатуры. Кнопка открытия книги независима от кнопки удаления. Удаление вызывается строго по ID выбранного проекта, а не по текущей открытой карточке. В диалоге указано точное название, требуется повторить его ввод.

Серверный маршрут `DELETE /api/projects/{project_id}` **уже существовал** и не изменён. Он отказывает при активной генерации, до удаления создаёт согласованную SQLite-копию в `data/backups/`, затем удаляет записи проекта, его задания, отзывы, сюжетную память и привязки иллюстраций. Файлы, исторические копии и производные данные других хранилищ этим маршрутом **не обещано** удалять без остатка. Поэтому это **удаление из рабочей библиотеки**, а не необратимое стирание всей истории с диска. Безопасное адресное освобождение места — отдельный этап с инвентаризацией зависимостей.

После успешного ответа браузер очищает только локальные данные выбранного проекта (черновик, выбранная вкладка и прокрутка); чужие проекты и служебное состояние графического контроллера не трогает. Серверную базу не очищает целиком.

## Сценарии ручной приёмки

1. Создать две тестовые книги. Убедиться, что возле каждой есть кнопка «✕», которая видна при наведении и доступна по Tab.
2. Нажать кнопку удаления книги A, отменить первый диалог — обе книги остаются.
3. Ввести неверное название — обе книги остаются.
4. Подтвердить точное название A — A исчезает из библиотеки и из `GET /api/projects`; книга B сохраняется неизменной.
5. Обновить страницу F5 — A не возвращается из браузерного черновика.
6. Выбрать книгу B, затем удалить другую A: текущая книга B не должна сбрасываться.
7. Для книги с выполняющимся серверным заданием запрос обязан завершиться отказом 409; книга и задание должны остаться.
8. Проверить наличие согласованного SQLite-архива в `data/backups/`; проследить за занимаемым местом.
9. Проверить, что `/docwork/`, R3.6/R3.7 и Ollama не затронуты.

## Что отложено

Кнопки удаления других ресурсов («удалить иллюстрацию», «очистить временный черновик», «удалить неиспользуемый экспорт» и т.д.) должны быть привязаны к конкретным существующим API и проверкам связей, а не к общему `DELETE` для всего каталога. Не добавлять массовое стирание `data/` или SQLite. Правила полного стирания старых бэкапов и ротации — в будущем «Хранителе», после продуктивных испытаний.

**Статус:** изменения в отдельной ветке. До тестирования на Huananzhi и просмотра браузером не считать удаление визуально принятым.
