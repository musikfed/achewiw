# Реестр управляемых служб ACHEWIW (fail-closed)

**Домашняя папка ACHEWIW:** `/1tbdisk/achewiw`. Не путать с `/1tbdisk/PegineLab/projects`, где находятся независимые `wificam_T23N` и `YadroKreator`.

## Обязательная принадлежность

Скрипт [`scripts/achewiw-control.sh`](../scripts/achewiw-control.sh) может останавливать Docker-контейнер **только при одновременном совпадении всех признаков**:

1. Docker Compose: `com.docker.compose.project=achewiw`.
2. Действительный каталог создания: `com.docker.compose.project.working_dir=/1tbdisk/achewiw`.
3. Собственная метка в `compose.yaml`: `org.achewiw.lifecycle=managed`.
4. Метка рабочей папки: `org.achewiw.workspace=/1tbdisk/achewiw`.
5. Имя службы `com.docker.compose.service` включено в **проверяемый allowlist** скрипта; на данном этапе это только `studio`.

`docker ps` с одним совпавшим именем проекта недостаточно для остановки. Сначала собирается **весь список кандидатов**, затем он проверяется целиком, и если хотя бы один запущенный кандидат не подтверждён — **операция отменяется без единой остановки**. Перед действием метки проверяются повторно. Случайный чужой контейнер с именем `achewiw` или соседняя служба на порту 7080 не являются основанием для остановки.

## Текущий список

| Компонент | Где работает | Статус | Действие stop |
| --- | --- | --- | --- |
| `studio` / `achewiw-studio` | Docker Compose, HTTP 7080 | Есть в `compose.yaml`; не развёрнут отсюда | **Останавливать** после всех проверок принадлежности |
| SQLite `data/` | Файлы проекта в `/1tbdisk/achewiw/data` | Используется веб-приложением | **Никогда не удалять**; файл остаётся |
| `epub-builder`, `render-worker`, `image-worker`, `gpu-scheduler` | В проекте пока не запущены | RFC/план | **Не угадывать процессы.** Подключать к lifecycle только после явной регистрации |
| Ollama / LLM (порт 11434) | Отдельная служба Ubuntu | Общий сервис хоста | **Никогда не останавливать** |
| `YadroKreator`, `wificam_T23N` | Другие директории и службы | Независимые проекты | **Никогда не останавливать** |
| Docker daemon, UFW, VPN, SSH | Ubuntu | Общая инфраструктура | **Никогда не останавливать** |

В будущем каждый **контейнер самого ACHEWIW** получает те же собственные метки и отдельное имя службы, которое **явно добавляется в allowlist после тестирования**. Случайные, устаревшие или неподтверждённые контейнеры не останавливаются «на всякий случай».

Если будущий модуль работает на хосте через systemd/отдельный GPU-worker, текущий Docker-выключатель **не управляет им**. Нужен отдельный ограниченный host supervisor с точным allowlist юнитов и проверкой `WorkingDirectory=/1tbdisk/achewiw`/реальной принадлежности сервиса. Нельзя применять `pkill`, `killall`, `fuser -k`, `docker stop $(docker ps -q)`, `systemctl stop ollama`. Предварительно согласовывать сохранение задач, drain и остановку по конкретным экземплярам.

## Совместимость с ранее созданными контейнерами

Контейнеры, созданные до появления `org.achewiw.lifecycle` и `org.achewiw.workspace`, **не проходят проверку и не будут принудительно остановлены новым скриптом**. Это ожидаемое безопасное поведение. Не запускать `docker compose up` или пересоздание контейнера автоматически; позднее во время отдельно согласованного запуска/миграции обновить экземпляр по новому compose.yaml и убедиться в метках.

Команды для будущего использования (не выполнять прямо сейчас, если проект ещё не запускали):

```bash
cd /1tbdisk/achewiw
bash scripts/achewiw-control.sh status
bash scripts/achewiw-control.sh stop
```

Команда `stop` сохраняет проектные данные. Проверка порта 7080 лишь **сообщает** о слушателе; она никогда не убивает процессы по порту. Веб-кнопка выключения пока остаётся отдельной задачей [#14](https://github.com/musikfed/achewiw/issues/14), а не внедрённой функцией.
