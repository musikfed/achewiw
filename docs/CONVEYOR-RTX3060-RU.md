## Реальные этапы (состояния в SQLite)

`book → mechanical_qa → literary_qa → editorial_proposals → illustration → proof → author_review → archive`

1. **Писатель:** использует уже существующий возобновляемый книжный job; длинный текст записывается по главам, не в каркас автора.
2. **Лексическая проверка CPU:** петли, повторённые параграфы, межглавные эхо, короткие/пустые диалоги; сохраняется отчёт.
3. **Независимый критик:** Ollama оценивает каждую часть *каждой* главы через `review_windows`, критические отзывы сохраняются по частям с SHA.
4. **Редактор:** другая роль той же выбранной модели делает только точные предложения `original → replacement`, уникальные цитаты проверяются; исходный текст НЕ переписывается.
5. **Художник:** ComfyUI + SDXL, при отсутствии иллюстрации делает обложку и по выбору рисунки к главам; существующие не перерисовывает. Предварительная карточка визуальной загадки уже хранится в `visual_puzzles.py`, критик проверяет выбранную главу разгадки. Автоматический алгоритм нового ребуса не реализован; он не должен придумывать бессмысленные секреты.
6. **Проба:** собирает настоящий черновой A5 PDF и EPUB, без принятия автора. PDF НЕ является сертифицированным PDF/X.
7. **Автор:** просматривает текст, отчёты и все предложенные редакции по главам, явно отмечает приемлемые версии; проверка SHA запрещает принимать изменённый исходник. Только здесь записывается авторская рукопись, с историей.
8. **Архив:** A5 PDF, EPUB, DOCX, FB2, `approved-corpus.jsonl` с проверкой снимка текста; корпус — материал для локального RAG, **без самостоятельного fine-tuning**. Без глобального очищения Docker/GPU.

У каждого этапа есть статус, версия, хеш входа/выхода, база SQLite. F5 не останавливает Python job; после перезапуска Studio выполнение восстанавливается по кнопке. Ошибки не стирают сохранённые результаты. Процент — количество завершённых стадий, а не количество токенов; живой прогресс книжной генерации показывается в прежней панели.

## Память GPU и очередность

Модели живут **на Ubuntu CORE**, внутри Docker Studio нет GPU-LLM или ComfyUI. Все LLM-вызовы/ComfyUI этапа используют внутренняя SQLite GPU-аренда, продлеваемая каждые 90 секунд при сроке 600 секунд, и чтение `Ollama /api/ps`. Модель критика сохраняется между окнами/главами своего этапа, не перезагружается перед каждым абзацем; между ролями удаляется из VRAM только с явно разрешённой пользователем выгрузкой. Если в Ollama уже присутствует посторонняя модель, конвейер выдаёт ошибку вместо её выгрузки. Изображения запускаются при пустом `/api/ps`. `ComfyUI /free` только с подтверждением и только при пустой очереди.

`nvidia-smi` и `ollama ps` на CORE — обязательная проверка перед эксплуатацией; CI тестирует алгоритм, но не способен подтвердить физическую RTX 3060. Для проблем с RAM/VRAM сократить `num_ctx`, выбрать меньшую модель, а не включать несколько одновременно. Текущее значение для литературного QA — 8192 контекстных токена; старый генератор книги использует 16384.

## Модели

Существующие Ollama-модели продолжат работать без скачивания. Для новых (команды на **хосте CORE**, только по желанию):

```bash
cd /1tbdisk/achewiw
bash scripts/prepare-conveyor-models.sh status
bash scripts/prepare-conveyor-models.sh pull-writer  # qwen3.5:9b-q4_K_M
bash scripts/prepare-conveyor-models.sh pull-editor  # gemma3:12b
ollama ps
nvidia-smi
```

Модели не скачиваются автоматически при открытии вкладки.

## Обновление на сервере (только при простое книги и после резервной копии data)

```bash
cd /1tbdisk/achewiw
git status --short
# если есть несохранённые изменения — остановись, без reset/clean
git fetch --no-tags origin
git switch --track origin/feature/production-conveyor-rtx3060
bash scripts/update-studio-clean.sh preview
# если все проверки пройдены и нет активного задания:
bash scripts/update-studio-clean.sh apply
bash scripts/achewiw-control.sh status
```

Если новая локальная ветка уже существует, вместо `git switch --track` используй `git switch feature/production-conveyor-rtx3060`. Если у текущей ветки разошлась история, не делай `reset --hard`: остановись и сохрани локальные изменения.

Работай в веб-интерфейсе на вкладке **06 · Типография → Издательский конвейер**. Выбери две установленные модели и режим иллюстраций, **подтверди право выгрузки именно выбранных моделей**, затем запусти. После этапа QA проверь PDF/EPUB и предложения редактора, отметь по главам и утверди. Нельзя принимать рукопись не читая её.

## Ограничения, которые важно не выдавать за готовую систему

- CI проверяет сохранение, сериализацию и API с подменёнными Ollama/ComfyUI; не проверяет фактическую скорость и русскую художественную прозу.
- Подготовка типографского PDF/X и проверка прав на изображения и шрифты требуют отдельного ReleaseGate; A5 PDF — проба.
- Формальные проверки повторов не доказывают литературную ценность, а LLM-оценка может ошибаться.
- Точная художественная загадка в рисунке проверяется автором: генератор не обязан придумать её автоматически.
- Не удалять старые ветки, пока уникальные изменения из старых RFC и восстановителя библиотеки не сохранены. Удаление `main` потребует сначала изменить default branch в настройках GitHub.
