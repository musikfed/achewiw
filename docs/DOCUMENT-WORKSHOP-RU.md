# ACHEWIW — Умный редактор DOCX/PDF (Document Workshop v1)

## Самостоятельная мастерская

Пункт «Умный редактор DOCX / PDF» в левом меню или адрес /docwork/ открывает отдельную рабочую область. Загрузка документа не создаёт книгу в SQLite, не меняет текущий проект и не требует Ollama или GPU. Вся обработка идёт из загруженного файла и завершается скачиванием отдельной копии.

## Функции первой рабочей редакции

- DOCX: автоматический поиск «Глава 1», «Часть 2», «1.1. Название» и встроенных стилей Heading 1/2. Показывается структура и поиск по содержимому книги, до 3000 непустых абзацев; остальные остаются в итоговом файле.
- Стиль без изменений или пресеты «Книжная классика A5», «Техническая книга», «Современный документ», «KARATE LINUX». Можно вручную назначить главу/подглаву и задать имя выходного файла.
- Ручное изменение текста простого абзаца: текст заменяется только после нажатия «Применить правку», и только при последующем экспорте. Внутреннее форматирование (runs) изменённого абзаца может упроститься. Изображения, поля и ссылки внутри абзаца блокируют изменение его текста; другие элементы DOCX не пересоздаются.
- Отдельный флажок убирает прямую подсветку и заливку абзацев/текстовых фрагментов (OOXML w:highlight, w:shd). Заливка ячеек таблиц не удаляется.
- Отдельный флажок задаёт скрытие орфографических и грамматических волн в Word (hideSpellingErrors, hideGrammaticalErrors) и удаляет сохранённые маркеры проверки. Это НЕ исправление русского словаря, не исправление орфографии, и приложение Word может иметь собственные пользовательские настройки.
- DOCX → PDF: через LibreOffice Writer с отдельным временным профилем.
- PDF → DOCX: извлечение доступного текстового слоя PyMuPDF и создание редактируемых абзацев с разделением страниц. Точные таблицы, колонки, рисунки, колонтитулы и позиции в PDF обычно НЕ воспроизводятся. PDF без текстового слоя требует OCR и отклоняется.
- Просмотр структуры — не полноценный визуальный постраничный рендер Word. Перед выпуском проверить итоговые страницы в Word/LibreOffice и PDF-ридере.
- Ограничение загрузки 20 МиБ, распаковки DOCX — 180 МиБ, PDF до 400 страниц, без автоматической отправки в облако и без хранения загруженного файла. Доступ ограничен существующей LAN/VPN-проверкой ACHEWIW.

## Файлы и API

- app/document_workshop.py: валидация, обработка DOCX, конверсия PDF.
- app/static/docwork.html, docwork.css, docwork.js: самостоятельный интерфейс.
- POST /api/docwork/inspect: список глав, абзацев и предупреждений.
- POST /api/docwork/export: новая копия DOCX/PDF, имя на русском допустимо.
- tests/test_document_workshop.py: регрессия; исходный DOCX остаётся нетронутым.

Для производственного контейнера требуются python-docx, PyMuPDF, LibreOffice Writer и шрифты Liberation / DejaVu. Обновление GitHub-кода НЕ означает автоматическое обновление работающего контейнера Huananzhi: установка проводится отдельно штатным безопасным процессом Studio.

## Пример для «KARATE LINUX»

Загрузить DOCX → выбрать «KARATE LINUX» → автоопределение глав и подглав → очистить серую заливку/подсветку → при необходимости скрыть красные волнистые линии Word → вручную назначить «Глава» абзацу «Основы Linux» → скачать новую DOCX и PDF для проверки.

## После v1

Задачи будущих редакций: постраничный редактор с точным визуальным предпросмотром, форматирование выделенного текста, пакетные пользовательские правила, шаблоны титульного листа/оглавления, OCR, более точное восстановление сложных PDF, хранение пресетов в локальной базе. Эти возможности в v1 НЕ объявляются реализованными.

## Улучшенная навигация и реальный визуальный предпросмотр

После проверки документа редактор показывает сразу четыре шага: загрузить → выбрать стиль → **посмотреть страницы PDF** → скачать новую копию. Кнопки предпросмотра и скачивания видны над основной формой; длинную левую колонку прокручивать необязательно.

В структурном просмотре сначала показаны только заголовки, чтобы автор книги на сотни страниц быстро переходил к нужной части. Есть поиск по заголовкам и тексту, выбор «Все абзацы» и дозагрузка карточек по 80. Обычный текст больше не отображается как зелёный жирный заголовок.

Кнопка «Посмотреть страницы PDF» отправляет текущие настройки оформления на существующий изолированный серверный конвертер и показывает PDF внутри браузера. Можно просмотреть визуальный результат, прежде чем скачивать файл. После изменения шрифта, стиля или параметров предыдущий просмотр сбрасывается; PDF нужно построить повторно. Сам исходный DOCX при этом не переписывается, а готовый PDF не сохраняется в библиотеке ACHEWIW.

Это постраничный PDF-просмотр, **не визуальный редактор DOCX**: корректировка текста и назначение роли заголовка выполняются в структурном списке, а итоговая вёрстка отображается после конвертации LibreOffice. Для PDF в качестве источника показывается оригинальный PDF; настройка его оформления требует сначала получить редактируемый DOCX.
