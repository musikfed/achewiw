# ACHEWIW 0.2 — литературные мастерские и типография

**Репозиторий:** https://github.com/musikfed/achewiw  
**Рабочая ветка приложения:** `feature/technical-epub-first`  
**Каталог:** `/1tbdisk/achewiw`  
**Студия:** http://192.168.0.100:7080, только внутри защищённой LAN/VPN.

## Что действительно работает в коде

| Раздел интерфейса | Обработка | Результат |
| --- | --- | --- |
| **Фантастика и проза** | Канон/якоря, сюжет и сцены, генерация текста выбранной сцены, редакторский QA | Сохранённые части книги |
| **Технические книги** | Тезисы, источники автора, список терминов/доказательств, технический prompt для плана, текста и критики | Сохранённые главы с отдельной редакционной проверкой |
| **Выступления** | Длительность, заметки для докладчика, блоки речи, паузы, переходы, AI-черновики речи | Готовые части сценария выступления |
| **Нонфикшн** | Тезисы, источники автора, структура аргументации, объяснения и QA фактов | Сохранённые главы |
| **Типография / Экспорт** | Читательское представление из **сохранённого текста**, без отчётов и промптов | EPUB, FB2, Markdown, DOCX, PDF для чтения и A5 PDF-проба |
| **Состояние сервера** | NVIDIA GPU/VRAM, CPU/RAM, выбранная и загруженные Ollama-модели | Показатели от хостового мониторинга, если сборщик включён |

**Текст из QA-отчёта НЕ является главой.** AI-черновик попадает в рукопись только после решения автора и сохранения сцены/раздела. Подтверждённый канон и версии рукописи требуют дальнейшего отдельного развития — старые пользовательские поля не стираются при обновлении модели данных.

**Для технического раздела** источники и DOI записывает автор. Модель не должна выдумывать DOI; однако текущий MVP **не проверяет** DOI через Crossref, не выполняет RAG-поиск и не может автоматически подтвердить научную достоверность. Это не «готовая научная экспертиза».

## Фактические форматы

| Формат | Что создаётся | Ограничение |
| --- | --- | --- |
| `.epub` | Настоящий EPUB 3 ZIP: манифест, XHTML-главы, навигация, metadata | Проверка EPUBCheck и расширенная доступность ещё нужны |
| `.fb2` | Настоящий XML FictionBook 2.0 с разделами | Совместимость с конкретной читалкой проверить |
| `.docx` | Реальный Word OOXML для редактора с заголовками и текстом | Допечатную верстку редактор утверждает отдельно |
| `.pdf` | A5 PDF для чтения с встроенным DejaVu Serif/кириллицей и страницами | Не подменяет PDF/X |
| `.print.pdf` | A5 пагинированный PDF — **проба для типографии** | **Не сертифицирован PDF/X**: нет printer ICC/output intent, гарантированных вылетов/TrimBox; печатные требования конкретной типографии неизвестны |
| `.md` | Чистый Markdown из сохранённой рукописи | Нет макета и печатных свойств |

Для **PDF/X-4, SLA/Scribus, CMYK, раздельной обложки, спуска полос и принтерского sign-off** понадобится отдельный полноценный препресс-пайплайн и параметры конкретной типографии. Нельзя честно назвать текущую A5-пробу готовым PDF/X-файлом. Этот функционал остаётся в RFC, но **не изображается готовой кнопкой**.

Без сохранённого текста хотя бы одной главы экспорт возвращает понятную ошибку, а не выдаёт пустую или выдуманную книгу. Ненаписанные части перечисляются в «Типографии».

## Без окна входа и пароля — но только внутри VPN

В новой сборке HTTP Basic **не используется**. Удалены обязательные `ACHEWIW_USERNAME` и `ACHEWIW_PASSWORD` из `compose.yaml`; старые переменные могут оставаться в локальном `.env`, но контейнер их не получает.

Вместо пароля действуют:
- разрешение **только частных адресов клиента** (RFC1918 / IPv6 ULA и loopback), без доверия `X-Forwarded-For`;
- разрешение Host по умолчанию: `192.168.0.100`, `127.0.0.1`, `localhost`; `ACHEWIW_ALLOWED_HOSTS` в `.env` меняет список;
- для запросов изменения данных — проверка заголовка `Origin` на тот же host и scheme для браузера;
- приложение по-прежнему слушает 7080, **не публиковать порт напрямую в Интернет** и не открывать доступ ненадёжным участникам LAN/VPN.

**Компромисс безопасности:** любой участник доверенной VPN/LAN, способный открыть адрес, теперь может **читать, редактировать и удалять книги**. Автор сознательно отказался от входа по паролю. HTTP без TLS вне защищённого VPN не подходит для закрытых рукописей. Если нужен многопользовательский доступ или сторонние сотрудники — потребуется отдельная полноценная аутентификация.

## Рекомендации LLM из уже установленных Ollama

| Задача | Модель | Почему |
| --- | --- | --- |
| Роман, фантастика, творческая проза | **`qwen3:8b`** | Лучший практический баланс для первой версии, 5.2 ГБ весов на диске |
| Альтернативный художественный стиль | `hf.co/bartowski/NousResearch_Hermes-4-14B-GGUF:Q4_K_M` | Проверять сравнением на одних и тех же сценах; модель 14B Q4 тяжелее |
| Код, фрагменты инженерных глав | **`qwen2.5-coder:14b`** | Специализированная модель для кода; 9 ГБ весов — осторожно с 12 ГБ VRAM и длинным контекстом |
| Доклад/выступление, быстрые редакторские проходы | `qwen3:8b` | Баланс скорости и качества; компактная `qwen3:4b-instruct` — для очень быстрых эскизов |
| Проверка более сложных рассуждений | `hf.co/liodon-ai/DeepSeek-R1-Distill-Qwen-14B-imatrix-GGUF:Q4_K_M` | Для второго независимого разбора, но не заменяет источники и факты |
| Смысловой поиск по документам (позже) | `nomic-embed-text:latest` | Embedding-модель, **не** генератор текста |
| Анализ изображений | `qwen2.5vl:7b` или `granite3.2-vision:2b` | Визуальные задачи, не основной писатель |

Вес модели на диске **не равен** полной потребности VRAM: контекст/кэш и параллельные программы требуют дополнительной памяти. Не выгружать Ollama и другие модели автоматически ради ACHEWIW. Панель мониторинга показывает фактически занятый объём GPU и резидентные модели.

## Безопасно обновить сервер, не удаляя книги

Если ветка `feature/technical-epub-first` и нет незакоммиченных файлов:

```bash
cd /1tbdisk/achewiw
git status -sb
bash scripts/achewiw-control.sh update
bash scripts/achewiw-control.sh status
```

`update` выполняет проверенный Git fast-forward и, **если studio уже запущен**, пересобирает/обновляет **только контейнер ACHEWIW**. Другие Docker-проекты и Ollama не перезапускаются. Файлы `.env`, `data/` и `data/achewiw.sqlite3` не удаляются. Если studio был остановлен, обновление не запускает его.

Если старый `update` не может пройти из-за проверки пароля, см. [инструкцию Git и ручной безопасный fast-forward](GIT-SERVER-SYNC.md), после которого `bash scripts/achewiw-control.sh update` уже не требует пароля. **Не использовать `rm -rf`, `git reset --hard`, `docker compose down -v` или удаление соседних проектов.**

## Удаление старых данных — только по запросу

**Обновление НЕ очищает старую SQLite.** Это сделано, чтобы не потерять существующую книгу «Космо-мартышки», QA и историю генерации.

- Для ненужного **одного** проекта: внутри «01 · Задание» нажать **«Удалить ненужную работу (с архивом)»**. Приложение требует два подтверждения, сохраняет полную копию SQLite в `data/backups/` и лишь затем удаляет связанные записи проекта и его QA-задания.
- Для просмотра содержимого SQLite без изменений:

```bash
cd /1tbdisk/achewiw
python3 scripts/library_admin.py --list
```

- Для **полной очистки библиотеки** сначала остановить **только ACHEWIW**, затем явно подтвердить:

```bash
cd /1tbdisk/achewiw
bash scripts/achewiw-control.sh stop
python3 scripts/library_admin.py --reset-all --confirm DELETE_ALL_ACHEWIW_LIBRARY
```

Команда создаёт отдельный архив всей базы `data/backups/achewiw-before-reset-*.sqlite3` и затем очищает **только** таблицы `projects`, `ai_jobs`, `ai_job_reviews` в `data/achewiw.sqlite3`. Она **не удаляет** `.env`, папки, рукописи в других каталогах, Ollama, ветки Git и другие проекты. Пока отдельно не принято решение об очистке, **эти команды НЕ выполнять**. Для отдельного ID есть `--purge-project HEX_ID --confirm DELETE_PROJECT`.

## Проверки

GitHub Actions: синтаксис backend/JS, проверка разделов интерфейса, тесты доступа без пароля из VPN, блокирования внешнего IP и небезопасного Origin, генерация настоящих EPUB/FB2/DOCX/PDF, тест восстановления/backup SQLite и изоляция выключателя. Реальная проверка на Ubuntu и читалках/типографии проводится после `update`, не из GitHub.
