# ACHEWIW — Шаг 09. Чат генерации управляет существующим конвейером

**Статус:** Draft PR, без деплоя. Базовая ветка: UI PR #72. Условие начала этапа — успешный `lifecycle isolation` — проверено.

## Архитектурное решение

Нет второй службы, очереди или генератора. Чат 07 использует те же внутренние функции сервера, что и уже существующие маршруты:

| Кнопка чата | Canonical функция | Данные |
|---|---|---|
| Открыть статус | `_current_book_job_id` + `_book_record` | `achewiw.sqlite3.ai_jobs` + `ai_book_chapters` |
| Запуск | `start_full_book(BookRequest)` | Утверждённый `book-plan`, глава и исходные SHA |
| Пауза | `pause_full_book(job_id)` | Безопасное завершение текущего фрагмента |
| Продолжение | `resume_full_book(job_id)` | Проверка каркаса, исходных SHA и очереди GPU |
| Просмотр/принятие | существующий экран `06 · Типография` | Текущий черновик, PDF и отдельная приёмка |

Действующий `execute_book` и его RAG/Graph-контекст остаются без изменений. `07 · Чат генерации` отправляет управляющую команду в существующий конвейер, а не формирует новую независимую рукопись.

## Контракт API

- `GET /api/projects/{project_id}/chats/{thread_id}/book-job` возвращает **каноническое** текущее задание книги и историю действий этого чата.
- `POST /api/projects/{project_id}/chats/{thread_id}/book-control` получает `action` (start/pause/resume), `confirm: true`, при старте — `model`.
- Прежде чем стартовать, нужно сохранить хотя бы одно поручение автора в **этом** generation-чате. Команда в текстовом поле сама не запускает модель.
- Пользователь нажимает отдельную кнопку и подтверждает операцию через диалог браузера. Повторный запуск возвращает ту же активную задачу благодаря канонической идемпотентности. Пауза/продолжение проверяют, что задача книги действительно принадлежит выбранному проекту.
- Дополнительная таблица `work_chat_book_control_events` хранит только журнал кнопок, project/thread/job/action. **Нет дублирования текста, графа, RAG-индекса и состояния работы.**
- Контекст и авторизация — прежний `/api` router с `Depends(require_auth)`.
- Редакторский чат 08 не получает доступ к запуску книг.
- Изменение `work_chat_book_control_events` — служебная аудиторская информация. Принятие готовой книги, обновление канона и экспорт по-прежнему выполняются только существующей типографией.

## Автоматическая проверка

`tests/test_chat_book_conveyor.py` через in-process FastAPI и временную SQLite проверяет последовательность start/pause/resume, один canonical job ID, явное подтверждение, обязательное поручение автора, изоляцию проектов и редакторского чата, состояние без активной задачи и сохранение событий. Фальшивый исполнитель моделирует текущий book runner — **не запускает реальный Ollama**.

```bash
python -m unittest discover -s tests -p 'test_chat_book_conveyor.py' -v
node --check app/static/chat_studio.js
python scripts/verify-versioned-assets.py
```

## Ограничения и следующие этапы

- Режим `autonomous` сейчас может составить предложение плана без уточнений, **но не вносит молча изменения в канонический `book-plan`**. Это следующий шаг: контролируемый `review → accept plan → generate` с проверкой структуры глав и сохранением версии.
- Чат не ставит прямые команды в очередь Ollama: только вызывает проверенный конвейер.
- Настоящий E2E с локальной Ollama и проверка восстановления после отключения сети должны идти на **уже существующем тестовом сервере**. Отдельного `17080` не создаём.
- Новый экран не развёрнут в `main` или на работающем `7080`; без самостоятельного merge зависимых PR от #62 до #72.
