# ACHEWIW · генерация большой книги с гибридной памятью

Ветка feature/technical-epub-first. Эта инструкция касается безопасного
продолжения уже написанной книги. Данные НЕ удалять.

## Откуда бралась остановка на 1081 слове

Ollama иногда возвращает повтор уже написанной прозы. Прежняя версия
отклоняла три таких ответа подряд и помечала задачу ошибкой. Весь принятый
текст оставался в ai_book_chapters, но повторное возобновление могло
вычислять те же случайные seed, потому что счётчик успешных фрагментов
не менялся.

Теперь повтор приводит к последовательной смене редакторского задания
и seed; на каждом явном возобновлении повышается retry_epoch в SQLite.
После шести неудачных попыток генератор по-прежнему безопасно
останавливается, вместо того чтобы добавлять мусор в книгу. Кнопка
«Продолжить» перечитывает сохранённый текст; начинать книгу заново не нужно.

## Никакого искусственного усечения ответа

Базовый запрос к пишущей модели — около 900 слов. В зависимости от
фактически полученных ответов он может адаптироваться до 1500 слов.
Токенный лимит num_predict рассчитывается из реального Ollama eval_count
и фактического числа слов. Запрашиваемый объём — ориентир, не гарантия;
полученный ответ сохраняется полностью, без резки на фиксированные части.

Для RAG отдельно создаются индексируемые выдержки примерно по 1350
символов. Это не уменьшает исходную рукопись в canon.

## Что содержится в каждой SQLite

1. data/achewiw.sqlite3 — canon. Официальный каркас, авторские факты,
   граф причин, главы, непринятые черновики генерации и задания.
   Ни одна гипотеза ИИ автоматически не повышается до авторского канона.
2. data/search.sqlite3 — восстанавливаемый FTS5 и реальные embeddings.
   Модель nomic-embed-text:latest преобразует выдержки в векторы,
   сохраняемые вместе с digest источника. При изменении фрагмента его
   вектор аннулируется, остальные НЕ пересчитываются.
3. data/work.sqlite3 — рабочие checkpoint и дословные последние абзацы
   главы, привязанные к SHA256 сохранённого текста; это не отдельный
   второй канон.

Перед очередной генерацией модель получает объединённый контекст
из канона, авторского графа, FTS5, векторной семантической выдачи,
рабочей точки продолжения и утверждённого плана ВСЕЙ книги. Поиск
строго фильтрует текущий проект, ветку main, предел уже достигнутой
главы и job_id непринятой генерации; никакие чужие истории и
будущие спойлеры не попадают в контекст.

Передача компактных выдержек в Ollama не означает, что вся
рукопись целиком помещается в её контекстное окно: долговременную
память организуют дисковые SQLite и Python в ОЗУ, а не GPU KV-кэш.

## Использование номик на CPU и сохранение VRAM

Загрузка embeddings происходит через локальную Ollama POST /api/embed.
Передаётся options.num_gpu=0 для CPU и keep_alive=0 для выгрузки
ТОЛЬКО embedding-модели после запроса. Пишущую модель Qwen3 не
выгружаем и не очищаем GPU насильно после каждого фрагмента.
Если embedding-модель отсутствует, программа не скачивает её
тайно: продолжает с FTS5 и каноном, а состояние семантического
индекса явно видно в UI. По окончании книги индексируется и
последняя глава, у которой уже не будет следующего запроса.

## Как пользоваться

Сначала сформируй и сохрани редакторский каркас всей книги с
моментом раскрытия, кульминацией и финалом. Генерация последовательно
создаёт главы, после каждого принятого фрагмента делает
checkpoint в canon, заполняет поисковый FTS5 и рабочее состояние,
а на следующем шаге дозаполняет векторный индекс и ищет
релевантную память. По завершении книги автор отдельно
принимает главы для чистовика.

В блоке «Память сюжета» теперь показаны реальные числа FTS5
фрагментов, векторов и embedding-модель. Кнопка «Обновить
RAG-индекс» выполняет обновление FTS5 и CPU embeddings выбранного
проекта, пока не выполняется другая задача.

Если сохранилось 1081/2506 слов и задание имеет статус ошибки,
нажми «Продолжить написание». НЕ нажимай «Написать книгу» ради
возобновления — это создаст новое независимое задание.

## Безопасно обновить сервер

    cd /1tbdisk/achewiw
    bash scripts/update-studio-clean.sh preview
    bash scripts/update-studio-clean.sh apply
    bash scripts/achewiw-control.sh auth-check

Затем в браузере Ctrl+Shift+R. Если активна генерация, дождись её
завершения или безопасной остановки. Не применяй полный wipe,
rm -rf data, git reset --hard и глобальный Docker prune.

## Ограничения

Наличие векторного поиска НЕ равно полностью автоматической
литературной экспертизе. RAG может найти не все смысловые параллели,
а модель может незаметно нарушить характер героя. Граф проверяет
утверждённые автором связи; автоматическое извлечение всех состояний
персонажей, доказательство причинности и самостоятельная работа с
многотомными сиквелами всё ещё требуют отдельной реализации.
