# Промпт 02 — хранение, долговременная память и миграции

Восстанови устойчивое хранение ACHEWIW. По документации известны три роли SQLite: data/achewiw.sqlite3 (авторские проекты и генерация), data/work.sqlite3 (редакторские состояния и рабочие проверки), data/search.sqlite3 (индекс поиска/RAG). Перед изменением проверь фактические схемы и пути в репозитории: названия могут меняться.

Предусмотри атомарность операций, внешние ключи, миграции, WAL при уместности, блокировки, историю глав, версии правок, сохранение состояния очереди и возобновление после обновления страницы/перезапуска. Храни канон отдельно от непроверенного черновика. Индекс FTS5 должен перестраиваться без уничтожения оригинального текста. Для резервной копии открытой SQLite используй согласованный backup API или корректный snapshot, не простое копирование активного файла.

Выход: миграционная стратегия с обратной совместимостью, тесты сохранности и восстановления, контрольные инварианты (не потерять ни одной принятой автором версии), план мониторинга размера базы и индексов. Не загружай в Git реальные книги, БД и секреты.
