# ACHEWIW · Шаг 04: чат → настоящие immutable редакции Studio

**Статус:** изолированный Python bridge + тесты на синтетической книге. Ещё нет endpoint/UI/LLM и нет развёртывания.

## Что связывается с существующим кодом

- Используются `editorial_review.initialize` и таблица `work_book_versions`, из которой текущая издательская система уже читает сохранённые снимки книги.
- В `work.sqlite3` создаются только два дополнительных объекта: `work_chat_book_heads` (текущая рабочая редакция проекта) и `work_chat_book_edits` (предложения текста одной главы).
- `attach` один раз связывает выбранную существующую версию, повторное обращение **не переключает молча** текущую редакцию.
- `propose` готовит diff и SHA исходного текста, не меняя книгу.
- `decide(approve=True)` в **одной SQLite-транзакции** проверяет текущую версию, создаёт immutable версию через тот же формат `work_book_versions.payload_json` и обновляет рабочий указатель CAS. Отказ `approve=False` оставляет текст нетронутым.
- `prepare_restore` создаёт отдельное предложение вернуть текст главы из предыдущей версии; сам откат тоже требует решения автора.
- Все старые редакции, соседние главы, исходные тексты `ai_book_chapters`, основной canon, генерация, DOCWORK и экспорт не изменяются.

## Автоматическая минимальная глава

Текст «Глава 1. Головка HDD» включает короткий технический абзац и разговорную фразу «Я решил вам рассказать…». Редакторское предложение заменяет только эту фразу. Дополнительная глава служит проверкой отсутствия побочных изменений.

Шесть unit-сценариев: приемка и возврат; отказ; stale предложение; изоляция проектов; явное подтверждение; отклонение пустых/идентичных правок.

```bash
python -m unittest discover -s tests -p test_chat_editorial_version_bridge.py -v
```

## CI и изоляция инфраструктуры

GitHub Actions workflow запускает только указанный набор тестов. **Отдельного сервера `17080` нет.** Никаких GPU/LLM/сети. Для браузерного E2E позже применять действующий тестовый сервер владельца; его параметры не меняем.

## Граница готовности

Этот bridge уже опирается на формат **настоящих** хранимых редакций, но пока `work_chat_book_heads` — отдельный рабочий указатель, а не указатель канона/экспорта. Новая версия появится в общей истории `editorial_review.versions`, но автоматического выбора её в редакторе и типографии **пока нет**. До подключения API нельзя заявлять, что синхронизация вкладок завершена.

Следующий шаг: привязка `work_chat_proposals` и владельца диалога к редакторскому предложению, серверная авторизация/accept/reject, затем UI, последовательно без переноса текста в разные хранилища.
