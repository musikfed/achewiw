# R3.8 — первый реальный эталон распознавания, без использования пользовательских книг

Эта процедура продолжает основную методику [TESTING-METHODOLOGY-R31-R38-RU.md](TESTING-METHODOLOGY-R31-R38-RU.md). Её задача: измерить **качество одного реального ответа Ollama Vision**, а не вновь запускать 27 старых проверок.

## Контрольный рисунок

Скрипт `scripts/docwork-vision-benchmark.py` создаёт один безопасный синтетический DOCX, PNG и JSON с пятью эталонными объектами:

- Прямоугольник слева, прямоугольник справа.
- Горизонтальная стрелка слева направо.
- Надпись **PUMP** внутри левого блока.
- Надпись **VALVE** внутри правого блока.

Размеры 800×480 px. Все объекты, координаты и подписи заранее заданы, нет частной книги, телефонов, секретов, сторонних изображений и необходимости скачивать модель. Артефакты по умолчанию создаются в `/tmp/achewiw-vision-bench-r38/`. Они намеренно не коммитятся в GitHub, чтобы хранилище содержало исходный рецепт, а не устаревающие производные изображения.

### Этап 1 — только сгенерировать эталон (без сети и GPU)

```bash
cd /1tbdisk/achewiw
python3 scripts/docwork-vision-benchmark.py --fixture-only
```

Результат: `synthetic-scheme.docx`, `synthetic-scheme.png`, `ground-truth.json`. Можно открыть тестовый DOCX в интерфейсе DOCWORK, проверить рисунок и выбрать модель вручную.

### Этап 2 — проверить готовность локальной Studio (без загрузки модели)

```bash
python3 scripts/docwork-vision-benchmark.py
```

Скрипт открывает защищённый **одноразовый** DOCWORK-черновик из синтетического файла, проверяет чтение исходного рисунка и `vision/preflight`, печатает названия возможных vision-моделей и пытается удалить **только созданный им черновик**. Без флага `--model` он **НЕ выполняет** inference и не резервирует GPU.

### Этап 3 — один настоящий запрос к Ollama (только с явного разрешения)

Перед запуском нужно убедиться, что нет чужих задач на общей RTX 3060. Модель должна быть заранее установлена. Пример (название модели уточнить по выводу этапа 2):

```bash
python3 scripts/docwork-vision-benchmark.py \
  --model 'granite3.2-vision:2b' --confirm-gpu
```

Эта команда использует только локальную Ollama через уже установленный защищённый маршрут ACHEWIW R3.8. Она **может занять GPU**. Скрипт не запускает ComfyUI, не скачивает модели, не выгружает чужие модели и не меняет загруженный пользователем DOCX. Выдаёт `model-proposals.json` и `evaluation.json`. Результаты модели могут быть пустыми или некорректными: при сбое надо сохранить ошибку, а не утверждать успех распознавания.

### Этап 4 — ручная оценка результата

Отчёт показывает время ответа, количество предположений и найденных объектов. Для геометрических фигур простой критерий совпадения — IoU ≥ 0,5; для надписей — точное совпадение нормализованного текста PUMP/VALVE. Это **первичный диагностический ориентир**, а не окончательная метрика качества. Координаты надписей и стрелок могут оцениваться неточно; нужно смотреть изображение и предложения глазами.

Далее в браузере открыть синтетический DOCX, выполнить анализ, по одному принять и отклонить кандидатов, проверить Undo, F5, экспорт SVG/JSON и отсутствие изменений в исходнике. Лишь после этого увеличивать эталонный корпус: разные толщины линий, плохой контраст, русский текст, диагональные и перекрещённые связи, схема из 10–30 элементов.

## Почему этап не требует очередной пересборки Docker

Этот скрипт находится в репозитории и запускается из хостовой Python-среды; он обращается к **уже установленной R3.8 Studio**. Исправление редакторского `SyntaxWarning` в отдельной ветке также не обязательно развертывать для данного эксперимента — оно не влияет на модельный маршрут. Новый скрипт и GitHub CI не меняют ни запущенный контейнер, ни SQLite, ни реальные черновики.

## Правило приемки

Хранить сведения: версия ACHEWIW/commit, точное имя Ollama-модели, PNG и эталон, JSON предложений, количество правильных блоков/стрелок/слов, время выполнения, ошибки и замечания интерфейса. Формулировка «R3.8 установлена и регрессия 63 PASS» **не равна** «OCR технических схем проверен и точен».

При любой неожиданной ошибке остановить испытание; не модифицировать реальные книги и не запускать бесконечные повторы.
