# ACHEWIW · R4.0 — безопасная нормативная диагностика DOCX

**Дата:** 23.11.2026. **Draft PR №33:** https://github.com/musikfed/achewiw/pull/33

## Место в главном пайплайне

R3.6 = мастерская иллюстраций с импортом и заменой внешних картинок. R4.0 = диагностика готовой копии книги, первые справочные профили ГОСТ и библиографии. Не менять структуру основного приложения, не запускать GPU и облака, не зависеть от Верфи моделей.

Редактор DocWork на той же странице раскрывает блок **«R4 · Нормативная проверка и библиография (без изменения книги)»**. Выбрать класс документа (авторская/учебная книга, отчёт о НИР, организационно-распорядительный документ, без профиля). Нажать «Проверить DOCX». Система **создаёт текущую копию DOCX** с уже выбранными правками редактора, отправляет её на read-only preflight и показывает замечания. Есть «Скачать отчёт JSON».

**Ничего автоматически не «исправляется по ГОСТ».** При изменении рукописи прежний отчёт помечается устаревшим. Отчёт не означает соответствия стандарту и не снимает издательскую блокировку 00-Д.

## Проверяемые параметры R4.0

- Контрольная сумма SHA-256 обследованного DOCX, число абзацев, таблиц, рисунков и разделов.
- Размер страницы и поля для каждого раздела DOCX, без ошибочного требования сделать каждую книгу A4.
- Кандидаты подписи «Рисунок 1», «Таблица 1», наличие поля автоматического оглавления, перекрёстных ссылок `REF/PAGEREF`, сносок, концевых примечаний.
- Определение заголовка «Список литературы» и приблизительная численность записей. **Это не проверка пунктуации и полноты каждого библиографического описания.**
- Предупреждение: необходимо открыть настоящий PDF и сравнить шрифты, рисунки, подписи, страницы, нумерацию, колонтитулы.

## Основания по типам документа (официальный реестр Росстандарта)

- Авторская/учебная книга — ГОСТ Р 7.0.100-2018 (**описания ресурсов**, если применимо), ГОСТ Р 7.0.5-2008 (**библиографические ссылки**, если применимо).
- НИР/технический исследовательский отчёт — дополнительно ГОСТ 7.32-2017, применимость которого зависит от действительного вида документа.
- Организационно-распорядительный документ — ГОСТ Р 7.0.97-2025, **не применять** как универсальную норму художественной книги.
- Без профиля — чистая техническая диагностика.

Ссылки на официальные карточки стандартов уже встроены в `app/docwork_normative.py` и должны перепроверяться перед нормативным выпуском (включая редакции и изменения). Изменение списка стандартов не доказывает соответствие их пунктам.

## Испытания и ограничения

- `tests/test_docwork_normative.py`: самостоятельный синтетический DOCX, геометрия, таблицы, список источников, статус `needs_editor_review`, отказ от лжесертификации, проверка чужого/неверного профиля и API без работы с реальными книгами.
- CI дополнительно компилирует `app/docwork_normative.py`, запускает уже имеющийся набор R1–R3.6, проверяет 00-Д как BLOCKED.
- Ручная приёмка на сервере пока **не выполнялась**; не выдавать зелёный CI за утверждение готового издания.

**Что НЕ реализовано R4.0:** формальная проверка всех элементов библиографической записи, уникальные издательские профили (Литрес и др.), PDF/A/PDF/X, корректность каждой ссылки, глубинная проверка сносок/формул, сложная страничная геометрия, встроенные пользовательские шрифты и постраничное сопоставление Word↔PDF. Это будущие подэтапы R4.1+ после ручной проверки.
