# ACHEWIW: реальный хостовый прогон шагов 11–15

**25.11.2026.** Это операционная инструкция для **действующей** Ubuntu-машины `/1tbdisk/achewiw`. Она не заменяет хостовую проверку GitHub Actions. **Из этого чата SSH-доступа к хосту нет**, поэтому нельзя заявлять, что код развёрнут, пока хост не возвратил собственный отчёт.

## Результат первого прогона на хосте, 25.11.2026

Первый запуск на Huananzhi дошёл до **сборки и запуска нового контейнера** и проверил: 7080 HTTP 200, Ollama (10 моделей), ReportLab A5 PDF (9 стр.), DOCX-TOC, совпадение трёх глав на стр. 3/5/7. Smoke сообщил `PASS 12 / FAIL 4` и автоматически откатился на коммит `89b51ae`; сохранились SQLite backup `/1tbdisk/achewiw/data/backups/host-trial-20261125-193242`.

**Причина четырёх FAIL:** FastAPI 0.165.0 подключает дочерний `APIRouter` как ленивый `_IncludedRouter`, а прежняя проверка искала его вложенные пути только в плоском `app.routes`. В свежем CI проверено, что все четыре endpoint доступны через `app.openapi()["paths"]` и зарегистрированы в защищённом `api.routes`; обновлены smoke и тест реестра. Никакой потери маршрутов или неисправности SQLite не обнаружено; **не стирать базу ради этой ошибки**. Повторный host trial нужен для проверки на живом Docker. Старую Studio и хранилище при неудаче сохраняем.

## 1. Сначала только чтение (без рестарта)

Из обычного пользовательского терминала Ubuntu на сервере:

```bash
cd /1tbdisk/achewiw &&
git fetch --no-tags origin '+refs/heads/feature/final-print-gate-step15-20261125:refs/remotes/origin/feature/final-print-gate-step15-20261125' &&
git show refs/remotes/origin/feature/final-print-gate-step15-20261125:scripts/host-baseline-11-15.sh | bash
```

Проверка: источник и текущий SHA; локальные изменения; свободное место; принадлежность Studio, монтирование `/data`; SQLite только read-only и статусы задач; `7080/api/health`; GPU; Ollama; офисный движок; синтетический запуск нынешних (уже фактически собранных) модулей **в работающем контейнере**, без записи в книги. Если код ещё старый, новых импортов/API там может не быть — это основание продолжить подготовку сборки, не утверждение, что сервер уже обновлён.

Вывод команды будет сохранён в локальном `/tmp/achewiw-host-baseline-....txt`. Отправлять только текст итоговых `PASS/WARN/FAIL`, без конфигурационных секретов.

## 2. Развёртывание только ACHEWIW Studio (по явной команде владельца)

```bash
cd /1tbdisk/achewiw &&
git fetch --no-tags origin '+refs/heads/feature/final-print-gate-step15-20261125:refs/remotes/origin/feature/final-print-gate-step15-20261125' &&
git show refs/remotes/origin/feature/final-print-gate-step15-20261125:scripts/host-trial-11-15.sh | bash -s -- apply
```

Скрипт `host-trial-11-15.sh` **проверяет и останавливается**, если есть незакоммиченные файлы, неожиданный Git origin/Compose-владелец, запущенные задания, недостаточно места или неоднозначная принадлежность контейнера. Далее он создаёт онлайн-снимок доступных основных SQLite в `data/backups/host-trial-<дата>/`, записывает прежний SHA, переключает **только** исходники в detached HEAD на проверенный commit, перестраивает **только собственный** контейнер Studio штатным `achewiw-control.sh rebuild`, проверяет 7080 и выполняет синтетический HTTP/API/PDF/DOCX smoke **в реальном контейнере**.

В случае ошибки пытается вернуть **прежний Git-коммит и образ Studio** (отдельный шаг rebuild) и оставляет DB-снимки. Он **не** восстанавливает SQLite автоматически, поскольку это могло бы затереть реальные записи, появившиеся после снимка. Никакого `docker prune`, сброса Git, уничтожения `data`, управления Ollama/ComfyUI или запуска `17080` нет.

**Ограничение:** возможные автоматические SQLite-миграции при старте нового приложения могут остаться в базе даже после возврата старого кода. Поэтому backup сохраняется, а миграционную совместимость необходимо учитывать отдельно. Проход хостового smoke означает **базовую работоспособность**, но не разрешает без дополнительных проверок публиковать реальную авторскую книгу.

## 3. Что должно отработать после сборки

- HTTP `/api/health` и доступ к уже существующему `7080`;
- перечисление реально зарегистрированных API `print-proof` (предпросмотр, RAG-кандидат, редакторская приёмка);
- настоящая A5 PDF-проба из **синтетического** трёхглавого проекта и извлечение номеров TOC;
- DOCX с динамическим полем `TOC`;
- корректная блокировка выпуска при отсутствии офисного пересчёта;
- маршрутизатор пустых полос и растянутых пробелов;
- GPU/отвечающий Ollama (наличие проверяется, без платного или длительного инференса);
- защита оригинальных книг: smoke не обращается к данным проекта на запись.

Перед полноценной эксплуатацией нужно ещё проверить **настоящую короткую генерацию** локальной Qwen в контролируемом синтетическом проекте, сохранение чата после F5 и визуальные переходы 01–08. Базовый дымовой прогон этого не имитирует и не подтверждает.

## 4. Не перепутать CI и host

GitHub Actions `ACHEWIW host trial scripts verification` только проверяет Bash/Python-синтаксис диагностических и эксплуатационных скриптов. В нём нет SSH-доступа к Ubuntu. Реальная хостовая проверка начнётся **только** когда вышеуказанная команда исполнится на самой машине и вернёт результат.
