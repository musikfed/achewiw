# RFC-0002 — Генерация без ретконов: контракт между автором и LLM

## Основной закон

LLM не является источником канона. LLM создаёт **предложение** в выбранной области: события baseline, приёмы подачи, карточки, абзацы или аудит. Автор подтверждает предложения перед переносом в основной проект.

## Отдельные команды генератора

### 1. `generate_baseline` — голая линейная история

Вход: замысел, жанр, персонажи, начальное/конечное состояние, ожидаемые тома/главы.

Выход: предложения `world_events[]`, `facts[]`, связи причин `cause_event_ids[]`, структура `volumes[]` / `chapters[]` / `scenes[]`, текстовые summaries абзацев. **Без** техники сокрытия, обмана ожиданий и насильственного клиффхэнгера. События строго в порядке мира, читатель на этом этапе знает всё необходимое.

Прикладывается карта переходов состояний: какие знания/предметы/отношения/местоположения изменяются после каждого события. При длинном романе генерация по одной главе с консистентным общим реестром, не целым томом за один вызов.

### 2. `propose_disclosure` — художественная интрига

Вход: неизменяемые `canon_hash`, `fact_ids`, `world_events`, выбранные главы/сцены, `reader_knowledge`, приём из атласа, целевой эффект.

Выход: массив **операций над подачей**, а не новые события. Пример:

```json
{
  "canon_hash": "sha256-of-canonical-snapshot",
  "technique_ids": ["I01", "I07", "I32"],
  "operations": [
    {"type": "focus", "card_id": "scene-02", "fact_id": "fact-03", "intensity": "low"},
    {"type": "hint", "card_id": "scene-02", "fact_id": "fact-02"},
    {"type": "reveal", "card_id": "scene-08", "fact_id": "fact-02", "mode": "explicit"}
  ],
  "expected_reader_question": "Что находится в футляре?",
  "risks": ["Проверить видимость футляра в сцене 02"],
  "canon_edits": []
}
```

`canon_hash` связывает предложение с конкретной версией базы. Если канон изменился после генерации, предложение требует повторной проверки. Любая `canon_edits` делает предложение **неприменимым в автоматическом режиме**, но может создать отдельно помеченный запрос к автору.

### 3. `generate_card` / `rewrite_segment`

Вход: выбранная карточка и её версия, ближайшие принятые соседние карточки, факты, POV, читательское знание, якорь, стиль, исходный текст (для rewrite), авторский запрет `ai_policy`.

Выход: `TextRevision(status="proposal", origin="ai", model_id="...")` и список `used_fact_ids`, `suggested_new_facts[]`, `risks[]`.

Предложенные новые факты никогда не внедряются автоматически. В ответе нет операции прямого изменения существующих принятых абзацев.

### 4. `audit_story`

Два независимых слоя проверки:

- **Детерминированный:** ссылки на ID, типы родителей, наличие фактов, причины до следствий, восстановимость корзины, проверка подсказка→раскрытие, перегруз активных объектов, разрывы ветки.
- **LLM-гипотезы:** нарушенная мотивация, слишком очевидный виновник, неправдоподобная улика, провисание внимания, повтор деталей, неожиданный предмет, диалог не по характеру. Каждая гипотеза должна указывать конкретные scene/paragraph/fact IDs и степень уверенности.

Не считать вывод LLM автоматическим доказательством ошибки.

## Изоляция контекста

Для каждого запроса собирается компактный неизменяемый пакет:
`world_rules` + `canon_facts_relevant` + `timeline_window` + `card_context` + `reader_knowledge` + `author_instruction`.

Глобальная библия и реестр фактов имеют приоритет над предыдущими сгенерированными черновиками. Черновик, который не принят, не может стать «истиной» для следующей генерации.

При очень больших произведениях можно индексировать канонические записи с `nomic-embed-text` на **хостовой Ollama**. Векторный поиск возвращает только кандидатов; ограничения причинности опираются на точные ID/связи и полные исходные записи, не на один похожий текст.

## Безопасные операции

- `insert_after(card_id)`: вставить предложение после указанной карточки.
- `replace_segment(revision_id)`: принять новую ревизию, старая остаётся в истории.
- `move(card_id, target_id)`: менять только порядок карточек.
- `remove(card_id)`: мягкое удаление, показать затронутые ссылки и сюжетные нити.
- `branch(scene_id, technique_ids[])`: экспериментальный вариант дискурса; не менять канон.
- `restore(revision_id)`: вернуть ранее принятую ревизию.
- `amend_canon(fact_id)`: отдельная явная авторская команда с отчётом по всем зависимостям.

## Показатели качества, которые не подменяют литературу

На сцену: ясность, информационная нагрузка, число активных сущностей, цель сцены, новая информация, эмоциональный сдвиг, крючок/отсутствие крючка, ссылки на канон. Для сюжетной линии: setup/payoff, доля раскрытых обещаний, неожиданные скачки знания, дубли. Оценки условные; автор вправе сознательно нарушать «оптимальные» значения.

## Непосредственный приоритет

Сначала карты и надёжность версий, потом rich AI. Никаких полнотомных генераций или скрытых автоправок, пока не пройдены tests of stable IDs, undo and canon locks. Docker/запуск не входят в текущий этап.
