# ACHEWIW — исследователь, интернет-источники и заказ литературы

**Дата:** 2026-11-26. **Статус:** архитектурный план, НЕ реализовано. Не изменять действующие модели/базы/редактуру. Отдельный модуль ResearchDesk + SourceLibrary поверх текущего SQLite/RAG, совместимый с опциональным Manager на Ardor.

## 1. Три сценария для автора

**А. Автономный поиск.** Автор задаёт книгу/главу/вопрос и допустимые виды источников; исследователь формирует search queries на русском и английском, вызывает подключённые API/разрешённые сайты, собирает ссылки, DOI/ISBN, дату публикации, краткие выдержки, аннотации, достоверность и происхождение. Без фиктивных цитат. Можно работать независимо от Ardor через штатный Python connector; GPT Manager на Ardor улучшает постановку запроса и синтез.

**Б. Копировать запрос.** Когда нет доступа к ресурсу, достигнута квота или требуется ручной поиск: ResearchDesk показывает готовые запросы для поисковой системы, научного каталога или ассистента, кнопку «Копировать», перечень нужных данных/файлов. После вставки результата назад в чат/импорт библиотека проверяет метаданные, фиксирует retrieval=manual, дату, URL и ограничения.

**В. «Заказать литературу».** Автор может попросить «подбери литературу для главы о плотности магнитной записи/современных HDD» или «найди книги с художественными диалогами для исследования структуры». Модуль формирует **заявку на материалы** LiteratureRequest: темы, приоритеты, тип (статья, стандарт, учебник, патент, книга), причина, язык, год, библиография, где получить легально, статус (discovered/requested/supplied/processed), оценка релевантности и предполагаемые главы. «Заказать» здесь означает запросить **у автора загрузку** или предложить законный источник, не делать финансовую покупку и не обходить закрытый доступ автоматически.

## 2. Источники и коннекторы

- OpenAlex API: поисковый граф работ, авторов и связей; использовать API-ключ/квоты по текущей документации, а не считать неограниченно бесплатным.
- Crossref REST: DOI и библиографические метаданные; публичный API, polite запросы с contact.
- arXiv и другие открытые исследовательские репозитории: metadata и open access PDF только в соответствии с их правилами.
- Project Gutenberg и другие библиотеки public domain/открытых лицензий: индекс и книги с проверкой страны и условий лицензии.
- Сайты издателей, официальные мануалы, ГОСТ/стандарты: сохранять ссылки/метаданные; полный текст получать только при наличии права на скачивание и обработку.
- Веб-поиск по ключу провайдера/разрешённому API — опционально; не путать метаданные с наличием полного текста. Не скрапить сайты с обходом paywall/captcha/ограничений.

**Отделить** получение метаданных от скачивания/индексации полного текста. Если доступа нет — показывать заказ автору с DOI/ISBN и возможными законными площадками. Проверять robots/terms/license/rate limits. Нельзя считать текст обучающим датасетом лишь потому, что его разрешено прочесть или цитировать.

## 3. Поток данных

    Автор/чат ACHEWIW
       |
       +-- локальный Manager (Ardor .103, по желанию) / встроенный Python Router
       v
    ResearchDesk: цель → поисковые запросы
       |
       +-- SEARCH_AUTO: доступные API/сайты → метаданные → кандидаты → проверка
       +-- SEARCH_MANUAL: готовые запросы копипастой → автор передаёт результаты
       +-- LIBRARY_REQUEST: список материалов → ожидание загрузки/ссылки
       v
    SourceLibrary (SQLite): DOI/ISBN/URL/license/version, provenance, SHA, status
       |
       +-- RAG/FTS5 только подтверждённые доступные фрагменты с источниками
       +-- KnowledgeGraph: тезис → доказательство → источник
       +-- план книги/главы: цитаты/сноски/библиография/отмеченные пробелы
       +-- Верфь: отдельное решение о допустимости training rights и opt-in

**Research Manager не создаёт «правду» своей уверенностью.** Любое фактическое утверждение в технической книге должно ссылаться на источник или отмечаться как непроверенная гипотеза. RAG — поиск по источникам, не гарант точности.

## 4. Импорт и «переработка» материалов

Принимать файлы автора: PDF, DOCX, EPUB, TXT, Markdown и ссылки, с MIME/размер/антивирусной и parser-safe обработкой; сохранять оригинал и извлечённый текст отдельно, PDF page anchors и цитаты, версии/хеши. Форматы без поддерживаемого парсера помечать unsupported; не выдавать выдуманный разбор.

Режимы работы: извлечение фактов и ссылок, конспект, критический обзор, сравнение авторов, построение глоссария/временной шкалы, перечень пробелов, переработка **идей и проверенных сведений в оригинальное изложение**. Для книг под авторским правом без разрешения на создание производного произведения **не переписывать и не маскировать исходный текст** для публикации; использовать собственную структуру, краткие цитаты с атрибуцией в допустимом объёме, либо явно лицензированные материалы. Отдельно проверять права на обучение LoRA/QLoRA; чтение не равно training permission.

Существующие личные файлы и рукописи **не отправлять в сторонние облака по умолчанию**.

## 5. UI редакции: отдельная вкладка «Источники и исследования»

Три действия «Искать автоматически» / «Подготовить запрос» / «Запросить литературу». Кнопка копирования query, таблица кандидатов «название/автор/год/DOI/ISBN/URL/лицензия/релевантность», значок «метаданные» против «полный текст», статус подтверждения автора. «Добавить в библиотеку» → SourceLibrary, «Привязать к главе» → source_ids, «Запросить файл» → очередь LiteratureRequest. Отдельные кнопки «Собрать библиографию» и «Проверить источники главы».

Проекты изолированы по project_id; менеджер видит только разрешённую библиотеку проекта и записывает provenance/время извлечения.

## 6. API-концепт (не объявлять реализованным)

Маршруты: POST /api/projects/{id}/research/search, POST .../queries, POST .../literature-requests, POST .../sources/import, GET .../sources, POST .../sources/{source_id}/attach-to-chapter. В обработчиках проверять auth, разрешённые URL-протоколы и домены, DNS/IP после redirect (SSRF), размер, MIME, тайм-аут, квоты API и права доступа. Никаких непроверенных команд shell от LLM.

## 7. Выполнение после стабилизации основной редакции

1. MVP без внешних ключей: шаблоны поисковых запросов, очередь литературы, ручной импорт разрешённых файлов, библиография и привязка к главам.
2. OpenAlex/Crossref metadata API, dedup по DOI/ISBN/hash, подтверждение существования источника; логирование расходов/квот.
3. Автоматический разрешённый поиск, открытые полные тексты, page-level citations и проверка фактов с независимым QA; смешивание результатов без потери происхождения.
4. Интеграция Manager на Ardor (опционально), RAG и editorial brief; оценки hallucination rate и точности привязки citation → claim.
5. Интеграция с Верфью: только явно лицензированные наборы и подтверждённая цель обучения.
