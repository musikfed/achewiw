# ACHEWIW R3.5 — эксперимент: растровая схема → настоящий SVG → PNG

Дата: 23 ноября 2026. Draft PR №31: https://github.com/musikfed/achewiw/pull/31

## Зачем

В больших технических книгах множество PNG/JPEG с блок-схемами, кнопками, символами и подписями. При большом увеличении растр становится размытым. Нужно попробовать векторизацию отдельных схем и получить альтернативный PNG нужного масштаба — **без автоматической замены оригинальных рисунков**.

## Как это работает

В том же редакторе `/docwork/` открыть DOCX, выполнить «Проверить структуру», выбрать одну иллюстрацию слева и развернуть раздел «Эксперимент: схема → SVG → PNG». Выбрать 2, 4 или 6 цветов, затем отдельно нажать «Подготовить SVG» либо «SVG → PNG (2×)». Возникают отдельные файлы; оригинал остаётся в черновике и экспортируемом документе. SVG выводится в ограниченном окошке сравнения.

Преобразование применяет локальную цветовую квантизацию Pillow, затем `potrace` трассирует контуры каждого цветового слоя. В итоговом SVG настоящие `<path>` и `<rect>`, нет встроенных base64 PNG. Обратная растеризация выполняется PyMuPDF с увеличением 2×; её результат — обычный PNG.

Никаких LLM, моделей, CUDA, сети, OCR, внешних API и запуска ComfyUI. В Docker добавляется пакет `potrace`. Исходник DOCX не переписывается; библиотека книг и версии SQLite не удаляются.

## Чёткие ограничения и честное качество

- Это **эксперимент**, а не полноценное интеллектуальное восстановление исходных векторных объектов. На гладких схемах/логотипах контуры могут стать более резкими. На фотографиях, сложных рисунках, градиентах, мелких буквах, штрих-кодах или тонких линиях результат часто хуже.
- Растровые буквы становятся **контурными фигурами**, а не редактируемым текстом. Тексты в DOCX лучше сохранять как настоящий текст Word; в PDF такой текст и так масштабируется чётко, если присутствуют векторные шрифты.
- Число цветов ограничено 2/4/6, трассировка может изменить оттенки. Не утверждаем пиксельной идентичности.
- До **1,3 млн пикселей** в одной исходной картинке; не более **одной трассировки одновременно**; по 7 секунд на цветовой слой, SVG не более 1,8 МиБ, итоговый PNG не более 5 МиБ. Если схема сложная — сервер возвращает отказ, а не затирает исходник.
- Все операции ручные, **без пакетной обработки 60+ картинок** до накопления метрик качества. Пользователь сравнивает исходник и альтернативу при масштабировании 200–400% и принимает решение самостоятельно.
- Полученные SVG/PNG не вставляются автоматически назад в DOCX; обратный импорт надо разрабатывать отдельно, с контролем совместимости Word/LibreOffice.
- SVG уже исходно векторных схем предпочтительнее сохранять **из исходного редактора** — тогда геометрия и подписи не теряются при трассировке.

## Где проверяется

- `tests/test_docwork_vector.py`: проверяет настоящий SVG с контурами, отсутствие `<image>` и data URI, PNG-растеризацию, сохранность SHA-256 исходного DOCX, закрытую авторизацию R3 и ошибки параметров.
- `scripts/docwork-image-host-smoke.py`: продолжение хостового smoke; на синтетической схеме отправляет защищённый запрос SVG и обратный PNG, затем закрывает **только созданный тестовый черновик**. Без обращений к проектам пользователя.
- GitHub Actions устанавливает `potrace` в одноразовом CI runner, затем выполняет все тесты. Физический Huananzhi этим PR не обновляется автоматически.

## Введение на Huananzhi только после зелёного CI

Проверить `git status --short`, закрыть незавершённую редактуру в браузере. Переключить чистую рабочую копию `/1tbdisk/achewiw` на ветку `feature/docwork-vector-experiment-r35-20261123` без `reset/clean`. `bash scripts/achewiw-control.sh rebuild` — только собственный Studio, `bash scripts/achewiw-control.sh auth-check`. Затем `docker exec -i -w /app achewiw-studio python - < scripts/docwork-image-host-smoke.py` и `docker inspect --format '{{.State.Status}} / {{.State.Health.Status}}' achewiw-studio`.

Визуально сравнить из тестового DOCX схему с SVG и PNG 2× при 200–400% масштабе. Результат зафиксировать комментарием в PR №31. Общий издательский допуск по ГОСТ (R4 / 00-Д) всё ещё BLOCKED.
