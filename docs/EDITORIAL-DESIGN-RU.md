# ACHEWIW — редакционный дизайн v0.3 и обновление Ubuntu

**Рабочая ветка:** `feature/technical-epub-first`  
**Код:** https://github.com/musikfed/achewiw  
**Каталог:** `/1tbdisk/achewiw`  
**Адрес после отдельного запуска:** http://192.168.0.100:7080/ (доверенная LAN/VPN).

## Изменения интерфейса

ACHEWIW оформляется как **книжная/издательская мастерская**, а не панель системного администратора:

- типографичная иерархия: крупные книжные заголовки, узкие строки для чтения, печатные блоки с тонкими разделителями;
- светлая бумажная палитра, цвет чернил и тёплый медный акцент без яркого интерфейсного шума;
- **кнопки больше не слипаются**: единый шаг между кнопками, чёткие состояния hover/focus/selected, область нажатия не менее 44 CSS px;
- боковой список **«Мастерские»** — единые кнопки на полную ширину, ровные отступы и аккуратное выделение активного направления;
- библиотека рукописей и этапы «Задание → План → Редактор → Проверка → Типография» читаются отдельно от системного мониторинга;
- поля, панели моделей, карточки CPU/RAM/GPU/LLM, экспортные форматы и редактор масштабируются без горизонтального переполнения;
- для длинного текста применяется системный шрифт семейства Georgia/Palatino, для элементов управления — системные UI-шрифты. **Веб-шрифты из Интернета не загружаются.**

### Адаптация к ширине экрана

| Дисплей | Поведение |
| --- | --- |
| **2200 px и шире** | Страница по центру с максимальной шириной чтения, увеличенная типографика, отдельная боковая панель |
| **1300–2199 px** | Боковая библиотека + редактор, широкая сетка с адаптивными карточками |
| **1051–1299 px** | Более узкий сайдбар, подвижные поля и карточки; вкладки не склеиваются |
| **721–1050 px** | Мастерские располагаются над текстом, две колонки направлений, горизонтальная библиотека |
| **431–720 px** | Одна колонка основного редактора и модели, вкладки прокручиваются горизонтально |
| **320–430 px** | Компактная типографика, большие элементы управления, кнопки действий становятся отдельными строками |

Ограничение максимальной ширины нужно для комфортной длины строки на 2K/4K, а не для искусственного сжатия сайта. Версия рассчитана на **адаптивную** вёрстку, но реальную проверку на каждом физическом разрешении выполнить можно только в браузере после развёртывания.

Дизайн не меняет SQLite, структуру данных, логику генерации и выбор LLM.

## Как скачать и безопасно пересобрать только ACHEWIW

Сначала убедитесь, что текущая работа сохранена: пересборка прервёт текущие HTTP-сеансы и **незавершённые генерации**, которые не поддерживают безопасную приостановку. Не выполнять во время активной генерации.

```bash
bash <<'BASH'
set -euo pipefail
cd /1tbdisk/achewiw

test "$(git branch --show-current)" = feature/technical-epub-first
if [[ -n "$(git status --porcelain)" ]]; then
  git status --short
  echo "ОСТАНОВКА: локальные файлы изменены, ничего не затираем"
  exit 1
fi

git fetch --no-tags origin
git merge --ff-only origin/feature/technical-epub-first

bash -n scripts/update-editorial.sh
bash -n scripts/achewiw-control.sh
bash scripts/achewiw-control.sh rebuild
bash scripts/achewiw-control.sh auth-check
bash scripts/achewiw-control.sh status
BASH
```

Для последующих обновлений достаточно:

```bash
cd /1tbdisk/achewiw
bash scripts/update-editorial.sh
```

**Область действия:** Fast-forward Git в ACHEWIW и принудительная пересборка `docker compose ... up -d --build --force-recreate --no-deps studio` после проверки принадлежности Docker-контейнера. Скрипт НЕ использует `docker compose down -v`, `docker system prune`, `docker builder prune`, не удаляет `.env`, `data/`, рукописи, не затрагивает `Ollama` или `PegineLab/projects`.

Если `rebuild` остановится из-за **отсутствия** собственного контейнера, скрипт не будет неожиданно запускать ранее остановленный проект. Запуск — отдельная операция.

## Как обновляется кэш

Разметка ссылается на файлы с общей версией ассетов:

- `/static/style.css?v=20261104-editorial-v3`
- `/static/app.js?v=20261104-editorial-v3`
- `/static/monitor.js?v=20261104-editorial-v3`

Они отдаются с `Cache-Control: no-store` через уже существующий backend. Так браузер загрузит новый CSS/JS после `rebuild`, **не нужно удалять кэш всего Chrome**. Если открыта старая вкладка — `Ctrl+Shift+R`, при необходимости открыть новое приватное окно. Кэш Docker-сборок **не очищается глобально**: он может относиться к другим сервисам сервера, а не к ACHEWIW.

## Проверки и откат

- GitHub Actions проверяет `bash -n`, синтаксис браузерного JS, баланс HTML-тегов, наличие адаптивных правил CSS, контрольной версии ассетов и изоляцию Docker.
- Для проверки без перезапуска: `git status -sb`, `bash scripts/achewiw-control.sh status`, `bash scripts/achewiw-control.sh auth-check`.
- Если после обновления вёрстка неудобна на конкретном мониторе, зафиксируйте ширину окна и масштаб браузера и пришлите скриншот: правим CSS отдельным Git-коммитом. **Не применять `git reset --hard` или удаление базы**.

Версии ОС, браузера и фактическая доступность GPU-метрик не зависят от этих визуальных изменений.
