# ACHEWIW StoryEngine 0.6.0 — руководство личной редакции

Документ относится к ветке `feature/technical-epub-first` репозитория `musikfed/achewiw`.
Режим: один автор, локальная Ubuntu, браузер по LAN/VPN, Ollama на хосте и
опциональный ComfyUI на том же компьютере. Никаких публичных TCP-портов и паролей в UI.
Не используй инструкцию как обещание автоматической литературной безошибочности.

## Схема всего процесса

**Задание → утверждённый каркас → режиссура объёма/интриг → память сюжета
→ длинная генерация с checkpoint → проверка → принятие автором
→ иллюстрации/обложка → паспорт издания → просмотр → EPUB / FB2 / DOCX / PDF.**

Пока текст сгенерирован, но не принят, «Типография» не должна считать его чистовиком.
Скачиваемые версии содержат только сохранённые автором главы.

## 01. Задание

Создай проект и заполни: название, тип литературы, жанр, аудиторию, атмосферу,
целевой объём (например, **20 000 слов**), сюжет/конфликт, загадку, момент
раскрытия и неизменяемые детали канона.

В той же форме находятся **имя автора**, **год выпуска**, **издатель**
(необязательно) и **редакция** («Первое издание»). Нажми **«Сохранить ТЗ»**.
Год — действительный год выпуска, а не дата генерации текста; приложение
не подставляет за автора неизвестные факты. Устаревшие книги без этих полей
продолжают экспортироваться, но предпечатная проверка отмечает неполные метаданные.

Автоматически добавляемая технологическая строка:
**«Создано в ACHEWIW StoryEngine v0.6.0 (Python, FastAPI, SQLite;
Ollama для текста и ComfyUI/SDXL для изображений — при использовании)»**.
Она присутствует в выходных сведениях; автор/издательство не выдумываются.

## 02. Story.prj — неизменяемый каркас, память и режиссура

Сначала сделай каркас глав. Не подменяй текст главы её краткой карточкой.
В «Режиссура глав» регулируются число слов, напряжение, частичное раскрытие,
редакторская цель. Сумма целей должна совпасть с общим объёмом.

Раздел «Память сюжета · RAG + граф причин» позволяет явно закрепить факт,
персонажа, событие, предмет, загадку и отношения (причина, требуется для,
раньше, подсказка, раскрытие). Порядок глав добавляется как **плановые**
узлы, но НЕ считается доказанным фактом мира. ИИ не имеет права сам
утверждать новый факт как канон.

### Три SQLite без трёх канонов

- `data/achewiw.sqlite3` — существующая главная база и **единственный**
  источник правды. В ней пока также остаются исторические `ai_jobs` и
  `ai_book_chapters`; они не удаляются и не переносятся автоматически.
- `data/work.sqlite3` — долговечные рабочие таблицы для экспериментов,
  QA и регистра checkpoint. Пока регистр — дополнение, а не замена
  существующим checkpoint текстов.
- `data/search.sqlite3` — воспроизводимый полнотекстовый индекс FTS5
  по известным фрагментам из основной базы. В нём предусмотрено хранение
  векторов, **но их вычисление через Ollama и семантический векторный поиск
  ещё не подключены**. Полная изоляция рабочих веток через overlay
  и наследование канона в нескольких томах остаются следующими этапами.

Это сознательно безопасная **аддитивная миграция**. Никогда не удаляй
`achewiw.sqlite3` под предлогом переноса на три файла.

## 03. Генерация и проверка

Нажми «Написать всю книгу». Qwen пишет последовательно, несколькими
фрагментами на главу. Текст сохраняется с прогрессом в SQLite. RAG
помогает поднять нужные предыдущие абзацы, а граф — видеть явно
закреплённые авторские связи.

Если первая глава остановилась на 1266 словах, нажимай
«Продолжить прерванную генерацию». Не удаляй базу и не начинай новую
задачу ради исправления повторов. После завершения оцени главы во вкладке
«05 · Проверка» и **только затем** нажми «Принять все главы».
На ошибки канона, художественный смысл и достоверность источников нельзя
полагаться только на автоматический QA.

## 04. Как сделать иллюстрацию и обложку

1. Вкладка **«04 · Иллюстрации»**. Для обычного рисунка выбери существующую главу.
   Для обложки выбери **«Обложка книги (отдельная страница)»**.
2. Выбери местоположение: **после заголовка**, **после абзаца № N**
   (нумерация с единицы по абзацам, отделённым пустой строкой),
   **после конца главы** либо **обложка**. Если указанный абзац
   удалён, изображение безопасно переносится в конец главы.
3. Введи подпись и промпт. Важно: для обложки описывай именно художественный
   фон **без нарисованных букв, текста и логотипов**. Название книги,
   автора и год экспорт вставит отдельным типографским текстом.
4. Если ComfyUI выключен, нажми **«Подготовить генератор»**. Он устанавливается
   и загружает SDXL только по кнопке. `qwen2.5vl` — vision-модель,
   она **не создаёт** картинки; изображение строит ComfyUI с diffusion checkpoint.
5. При желании нажми **«Уточнить описание»**: Ollama подготовит английский
   SDXL-промпт, который можно проверить и поправить вручную.
   Это отдельное действие с запросом согласия при выгрузке модели из VRAM.
6. Нажми **«Сгенерировать и добавить в главу»**. Или загрузи собственный
   PNG, JPEG либо WebP. Убедись, что изображение появилось в каталоге.
7. Открой «06 · Типография» и проверь **расположение каждого рисунка** в
   визуальном просмотре. После смены текста можно поправить номер абзаца
   загрузкой новой иллюстрации; существующие не меняются скрытно.

Одна обложка на издание. Для замены удали прежнюю обложку во вкладке
иллюстраций, затем создай новую. Экспорт сохраняет оригинальные PNG
в `data/illustrations/<project-id>`.

## 05. Выпуск книги

Вкладка **«06 · Типография»** показывает **только сохранённую рукопись**,
титульную страницу, обложку, видимое «Содержание», главы и выходные сведения.

Скачиваемые файлы:
- **EPUB3** — cover.xhtml, title.xhtml, навигационное Содержание,
  главы с иллюстрациями, метаданные dc:creator/date и выходные сведения;
- **DOCX A5** — редактируемая рукопись, титул, содержание, обложка,
  рисунки после заданных абзацев;
- **PDF A5** — текст, иллюстрации, обложка, титул и Содержание с номерами
  страниц через двухпроходную сборку. **Это НЕ PDF/X и не готовый
  полиграфический разворот обложки**;
- **FB2** — главы, дата, автор, изображения и выходные сведения;
- **Markdown** — исходная авторская рукопись с содержанием и паспортом.

Если планируешь бумажный тираж, типография должна отдельно подтвердить
формат обреза, припуски, CMYK/ICC, разрешение изображений и конструкцию
обложки с корешком. A5 PDF здесь является **пробой для чтения и проверки**.

## 06. Безопасное серверное обновление

**До обновления останови/дождись завершения текущей генерации.**
Не выполняй `git clean -fd`, `git reset --hard`, глобальный
`docker system prune` и удаление `data/`.

```bash
cd /1tbdisk/achewiw
bash scripts/update-studio-clean.sh preview
bash scripts/update-studio-clean.sh apply
bash scripts/achewiw-control.sh auth-check
```

Скрипт обновляет только подтверждённую ветку и собственный Docker Studio.
На шаге 3 выполняется `story-storage-maintenance.py apply`:
при первом создании производных SQLite делается **backup основного файла
через SQLite Backup API**, затем создаются `search.sqlite3` и
`work.sqlite3`. FTS5 индексируется **инкрементально** по изменённым digest;
прежний канон не чистится. На последующих запусках существующие базы
сохраняются. Все фотографии, ComfyUI, Ollama, host-монитор и соседние
проекты в `/1tbdisk/PegineLab/projects` не удаляются.

Ручная диагностика и повторный индекс (если отстаёт):

```bash
cd /1tbdisk/achewiw
python3 scripts/story-storage-maintenance.py preview
# Только без активных задач:
python3 scripts/story-storage-maintenance.py apply
```

Результаты проверки просматривай в `GET /api/storage/status`.
В `POST /api/storage/reindex` есть запуск индексации из студии, но
она ничего не удаляет из основных книг. После успешного обновления
перезагрузи страницу `Ctrl+Shift+R`.

## Список того, что ещё НЕ сделано

Вторая и третья базы реально создаются как производный поиск и рабочая
область, однако **все** исторические черновики из главной базы не перенесены;
нельзя стирать их до отдельного подтверждённого переноса. Нет полноценной
семантической индексации через embeddings, опубликованных immutable томов,
автоматической корректной машины состояний персонажей и независимой
генерации веток с наследованием родительского канона до fork.

Никакая архитектура не гарантирует хороший роман автоматически. Нужны
читательская проверка, редакторские решения и реальные тесты локальной модели.
