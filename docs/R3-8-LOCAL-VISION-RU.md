# ACHEWIW R3.8 — локальное распознавание одного рисунка через Ollama

**Основа:** R3.7G (28 Node-тестов + 27 DOCWORK smoke успешны по журналу Huananzhi). R3.8A (preflight) входит в эту ветку. **До единой хостовой приёмки R3.8 не развёртывать в рабочей Studio.**

## Реализовано
1. Кнопка «Проверить готовность Ollama Vision» запрашивает только установленные/загруженные модели. Затем пользователь выбирает модель и нажимает «Распознать рисунок · локальная Ollama» с явным подтверждением.
2. Серверный маршрут POST `/api/docwork/drafts/{draft_id}/vision/analyze` получает тот же секретный capability-токен DOCWORK, что и чтение изображений; внешние ссылки, произвольные URL и изображение в теле запроса не принимаются. Рисунок извлекается из **неизменяемого исходного DOCX**; вход ограничен PNG до 3 МиБ и 2048 px по каждой стороне. Пока поддерживается только original, не сторонняя замена. При большом рисунке возвращаем явную ошибку без попытки запускать модель.
3. Модель **должна уже быть установлена** в общей Ollama. Сервер проверяет `/api/tags` и `/api/ps`; если чужая модель загружена, не выгружает её автоматически и запрещает анализ. Перед вызовом Ollama использует существующий SQLite GPU lease ACHEWIW. Вызов `/api/chat` отправляет один PNG base64 локальной Ollama, просит максимум 60 объектов; таймаут ~105 секунд. Ни одного pull/download. `keep_alive=30s` не принуждает общую Ollama к выгрузке модели.
4. Ответ модели — недоверенный. Парсер `app/docwork_vision.py` обрезает неправильные/выходящие за размеры фигуры, сохраняет оценку уверенности, но всегда выставляет `verification=unverified`. Нет утверждённых связей, распознавание текста может ошибаться. В UI результат повторно проходит R3.7F валидатор и показывается через прежний R3.7G список индивидуального принятия/отклонения.
5. **Никакого автоматического применения к DOCX**, никакой записи изображения или ответа модели в серверную SQLite, никакого изменения книги, библиотечных записей и настройки сторонних GPU-сервисов.

## Важные ограничения
- GPU lease ACHEWIW **не координирует сторонние хостовые службы** вроде Video Studio, если они не используют тот же арендный механизм. Проверка Ollama `/api/ps` тоже не гарантирует отсутствие одновременного внешнего клиента. Для общей RTX 3060 это остаётся ограничением: перед ручным запуском проверь мониторинг GPU и чужие задачи. 
- Распознавание геометрических схем локальной vision-моделью **экспериментальное**: надписи могут читаться плохо, связи можно упускать, координаты неверны. Встроенной оценки точности на эталонном корпусе пока нет.
- Не утверждать, что DOCWORK R3.8 полностью сертифицирован, пока не сделан браузерный цикл и метрики ошибок. Тесты R3.1–R3.6 проверяют старый функционал, не содержат реального inference.

## Единый план приёмки (одна пересборка хоста)
1. CI `.github/workflows/docwork-r38-tests.yml` проверяет синтаксис Python/JS, 28 Node-тестов R3.7 и Python unittest для R3.8. Исполнение CI проверяется отдельно — наличие YAML ещё не равно зелёному результату.
2. На Huananzhi выполнить эти тесты **до** единственной пересборки. После неё выполнить старые 27 DOCWORK smoke.
3. В браузере открыть **синтетический тестовый DOCX** с двумя нарисованными прямоугольниками, стрелкой и подписью. Нажать preflight, проверить список фактически установленных моделей. Явно выбрать локальную vision-модель и запустить анализ одного исходного изображения.
4. Проверить полученные предложения, по одному отклонить/принять; проверить Undo, экспорт SVG/JSON и что оригинал не изменился. Сравнить распознанные текст и геометрию с эталонными.
5. Смоделировать активную аренду GPU, отсутствие модели, рисунок >2048 px, неверный токен, занятость другой моделью и недостоверный ответ JSON. Все случаи должны завершаться контролируемой ошибкой без изменения оригинала.
6. Если фактическая точность неприемлема — оставляем ручную R3.7 как рабочий режим. Дальнейшие доработки качества — отдельный этап, без повторных бессмысленных хостовых циклов.

## Приёмочные команды
```bash
cd /1tbdisk/achewiw || exit 1
python3 -m py_compile app/main.py app/docwork_vision.py
node --check app/static/docwork_workbench.js
node --test tests/diagram-graph.test.cjs tests/diagram-import.test.cjs tests/vision-proposals.test.cjs
PYTHONPATH=app python3 -m unittest discover -s tests -p test_docwork_vision.py -v
```
