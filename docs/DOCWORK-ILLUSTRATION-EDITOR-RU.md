# ACHEWIW · Редактор иллюстраций в DocWork (R3.1)

**23.11.2026.** Реализация в [черновом PR №27](https://github.com/musikfed/achewiw/pull/27), созданном поверх проверенного на хосте R3 PR №26.

## Почему раньше этого не было

R1 переносил простые рисунки из PDF в DOCX, R2 объединял рисунок с подписью при издательской верстке, R3 добавлял сохранение черновика и истории. Ни один из этих этапов не давал пользователю выбирать **оформление конкретной иллюстрации** в DocWork.

## Что реализовано

1. При выборе **DOCX** после «Проверить структуру» Workshop строит список встроенных картинок с реальными миниатюрами, размерами и признаком доступности редактирования.
2. Можно выбрать **ширину 25–100% от текстовой области страницы**. Пропорции картинки сохраняются автоматически; длинные рисунки дополнительно ограничены по высоте печатной полосы.
3. **Выравнивание:** слева, по центру, справа. Используется обычный *inline image in its own paragraph*, в потоке текста. Это не плавающий объект и не свободное перетаскивание по странице.
4. **Скругление углов 0/8/16/24%** по меньшей стороне изображения с прозрачной альфа-маской, упакованной в **новый PNG**. Даже если исходный PNG повторён в нескольких местах документа, изменён только выбранный экземпляр.
5. Миниатюры передаются из серверного оригинала отдельным защищённым API \`GET /api/docwork/drafts/{id}/images/{index}\`: обязательный секретный заголовок R3, \`Cache-Control: no-store\`, ограничение размера.
6. Изменения попадают в **редакционный черновик R3** и историю с проверкой конкурирующих вкладок. Файл-оригинал и авторские проекты не переписываются. После F5 настройки восстанавливаются.
7. Кнопка «Посмотреть страницы PDF» использует **реальный** обновлённый DOCX→PDF через LibreOffice (когда доступен); живой вид внутри панели — только упрощённый предварительный просмотр.

## Намеренные ограничения первого этапа

- Для **PDF** сначала получить редактируемый DOCX (импорт R1), затем открыть полученный DOCX для оформления. Прямой редактор изображения внутри PDF не заявлен.
- Табличные изображения, картинки вместе с текстом в одном абзаце, несколько рисунков в одном абзаце, плавающие/векторные/необычные объекты **не меняются** автоматически. Они показаны как недоступные, чтобы не испортить соседнее содержимое.
- Не добавлено перетаскивание по странице, текстовое обтекание, изменение цветокоррекции, поворот или кадрирование; это следующий отдельный модуль при необходимости.
- Размер рассчитывается по текстовой области **первого раздела** DOCX. Для книг с разными колонтитулами, колонками и секциями нужна отдельная проверка.
- Это оформление Word, а не контроль соответствия ГОСТ; финальный документ необходимо визуально проверить в Word/LibreOffice. Нормативный выпуск 00-Д остаётся BLOCKED.
- Скругление создаёт отдельный PNG. При большом количестве иллюстраций размер выходного DOCX может увеличиться; исходный файл не изменяется.

## Как проверить в GitHub и на Huananzhi

Автоматические регрессионные тесты: \`tests/test_docwork_image_layout.py\` вместе с предыдущими наборами.

Проверки: точные пиксели в скруглённом PNG, альфа в углах и середине, соотношение сторон после масштабирования, выравнивание абзаца, исходные байты авторской книги, одинаковые изображения в нескольких местах, ошибки некорректных параметров, отказ редактировать сложные объекты, приватные миниатюры и сохранение картинки через редакции R3.

**На работающем испытательном хосте**, если владелец решит установить эту ветку:

~~~bash
cd /1tbdisk/achewiw || exit 1
git status --short
# Только если выше нет изменений — без reset и clean.
git fetch --no-tags origin \
  '+refs/heads/feature/docwork-illustration-styling-20261123:refs/remotes/origin/feature/docwork-illustration-styling-20261123'
git switch --detach origin/feature/docwork-illustration-styling-20261123
bash scripts/achewiw-control.sh rebuild
bash scripts/achewiw-control.sh auth-check
~~~

Оператор должен убедиться в чистом статусе Git перед переключением. Команда \`rebuild\` управляет только подтверждённым контейнером ACHEWIW; она не должна трогать другие проекты, Docker prune, GPU, Ollama или рукописи. **Сейчас это только инструкция, на Huananzhi новую ветку ещё не разворачивали.**

Перед тестированием живого редактора возьми небольшой документ с 1–2 искусственными PNG. Выбери иллюстрацию, 65% ширины, центр и 16% скругления, нажми «Применить», «Показать страницы PDF», проверь полученный файл и восстановление настроек после F5.

**Вернуться к подтверждённой R3 версии кода** можно командой \`git switch --detach c5ff94dc187bb15a035b238fd4119070ece5fff1\` и штатным \`bash scripts/achewiw-control.sh rebuild\` после проверки локальных изменений. Сохраняются все файлы \`data/\`; новые записи R3 SQLite не удаляются.

## Следующие возможности при отдельной приёмке

Предметные стили «фото», «схема», «полностраничная иллюстрация»; обтекание с контролем отступов; кадрирование/поворот; подписи/якоря и отдельные макеты для комиксов KARATE LINUX. Всё остаётся в едином ACHEWIW.
