# ACHEWIW: растр и вектор — политика обмена с CorelDRAW/Photoshop

**Статус: проектное требование**, а не заявление о готовой конвертации всех форматов. На 24.11.2026 существующая DOCWORK R3.6 **загружает новые изображения в виде PNG** через `POST /api/docwork/drafts/{draft_id}/assets`; полноценное round-trip SVG/EMF/фигур Word пока не реализовано. Нельзя скрывать потерю векторности под надписью «SVG».

## Что встречается в исходных файлах

- DOCX — контейнер OOXML (ZIP). Может содержать PNG/JPEG/TIFF, SVG, EMF/WMF и собственные Office DrawingML/диаграммы/группы. Тип надо определять по **фактической связи/part MIME и сигнатуре байтов**, а не только по расширению файла или миниатюре. Извлекать embedded изображение без перепаковки и потери оригинала.
- PDF — страничное представление с независимыми растровыми изображениями, рисующими командами векторных контуров и текстовыми объектами. Нельзя считать целую страницу одним редактируемым SVG. Для импортируемого PDF требуется анализ объектов; в сомнительных случаях — безопасное превью и явное предупреждение.
- Вектор внутри SVG иногда содержит `<image>` или внешние URI. Такие файлы **смешанные**, их нельзя обозначать «чистый вектор».

## Как выбирать редактор и формат экспорта

| Вход | Редактор по умолчанию | Рабочая копия | Возврат в типографию |
| --- | --- | --- | --- |
| PNG/JPEG/TIFF | Photoshop 2026 | PSD + исходник (PNG/TIFF) | PNG с сохранением размера/прозрачности и метаданных обработки |
| SVG/EMF/WMF | CorelDRAW Technical Suite 2026 | CDR + исходный SVG/EMF/WMF | **Векторный SVG/EMF**, если безопасен и поддерживается экспортом; опциональный PNG fallback |
| Office фигуры/группы | Совместимый Office/Corel импорт после диагностики | исходный рисунок + промежуточные копии | либо векторный формат, либо подтверждённая растризация с предупреждением |
| PDF векторы/текст/растры | по извлечённому объекту | отдельная копия объекта, не страница вместо документа | сохранять тип объекта, пока возможно |

**Photoshop:** SVG/PDF может открываться как Smart Object для недеструктивного масштабирования; это не делает каждую SVG-кривую отдельным объектом Photoshop. Обычное Open может растрировать SVG. Если Photoshop возвращает PNG вместо исходного SVG, это осознанная **вектор→растр** операция и требует подтверждения.

**CorelDRAW:** PNG→PowerTRACE→SVG создаёт векторные *контуры*, но не гарантирует восстановление редактируемых символов, исходного текста/логических связей. Сохранять оригинал PNG + рабочий CDR + чистый SVG + optional PNG для Word. Показывать количество контуров, присутствие `<image>`, текстовые объекты.

## Надёжное возвращение именно на прежнее место

1. Отмечаем `draft_id`, `image_index`, исходный SHA-256, **формат**, ID редакции черновика, режим и job-id; никакого сопоставления по имени файла.
2. ACHEWIW отдаёт агенту на Windows **копию** выбранного объекта (либо png preview, либо его raw media part); оригинальный DOCX хранится в прежней таблице, без изменений.
3. Пользователь редактирует в CorelDRAW/Photoshop и явно сохраняет готовый результат. Windows-agent передаёт копию с MIME+magic validation и source binding.
4. Сервер принимает *новую ревизию*; кнопка **«Принять в книгу»** обновляет только сопоставление конкретного image_index, без перемещения абзаца/подписи. При конкурирующем редактировании — 409 и ревью, не применять молча.
5. При экспорте сохранять векторность, **если бэкенд реально умеет безопасно встраивать SVG/EMF**. До реализации этого механизма возврат в текущий DOCX — только совместимый PNG, а исходный SVG/CDR хранится рядом как редактируемый master.
6. Если формат меняется, явно показать пользователю: `Вектор → растр 300/600 DPI` или `Растр → контуры, OCR текста не выполнен`, не скрывать деградацию, не удалять исходники.
