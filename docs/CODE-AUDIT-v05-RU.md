# ACHEWIW · ревизия рабочего прототипа и литературной мастерской v0.5

Дата: 04.11.2026  
Точка проверки: `feature/technical-epub-first`.  
Это описание **фактического кода и автоматических проверок**, а не обещание завершить все RFC. Состояние ноутбука/домашнего Ubuntu и качество генерации реальной Ollama отдельно не проверялись. Соседние проекты, Ollama, VPN, systemd и SQLite на пользовательском сервере из GitHub не изменялись.

## 1. Реализованные функциональные цепочки

| Цепочка | Где код | Фактический статус |
| --- | --- | --- |
| Творческий проект, техкнига, выступление, нонфикшн | `app/main.py` модели Project/Scene, `app/static/app.js` | CRUD/редактор SQLite, выбор типа, сохранение содержания. Отличия типов — поля и системный промпт; **не четыре полностью независимых движка** |
| План книги и генерация сцены | `build_prompt`, `/api/ai`, `app/generation_core.py` | Вызов host Ollama; черновик сохраняется в SQLite, работа не зависит от открытой вкладки. Только один активный job на весь ACHEWIW |
| **Поблочная генерация рассказа (новое)** | `SceneBlock`, `app/writing_blocks_core.py`, `app/static/writing_blocks.js` | У каждого блока ID, описание события, 80–1000 слов, предпосылки, вводимые предметы, идентификатор причинного блока, запреты и стиль. Генерируется именно выбранный фрагмент. Цель слов — **ориентир**, вывод модели может отличаться. `num_predict` масштабируется с целью |
| **Принятие и история версий (новое)** | `/api/ai/jobs/{id}/accept`, `author_text_revisions` | Черновик **не попадает в сцену автоматически**. При принятии проверяется хеш исходной сцены; принятие записывается атомарно в SQLite, повтор блокируется; текст до правки доступен для безопасного отката |
| **Повторная проверка фактов (новое)** | `writing_blocks_core.preflight`, `/api/projects/{id}/continuity` | Указанные автором `requires`, `introduces`, `caused_by` сверяются по принятым блокам. После ручного редактирования сцены прежние введения помечаются как требующие повторной проверки |
| **Литературная QA и очистка ИИ-штампов (новое)** | `AIRequest.continuity/polish`, `writing_blocks_core.editorial_lint/review_prompt` | Для выбранной сцены / обзора произведения проверяются возможные причинные разрывы и шаблонность. Редактура сохраняется как **предложение**, требует принятия и сохраняет исходник. Автор задаёт конкретные инструкции |
| Книга и документы | `manuscript_core.py`, `publishing_exports.py` | Скачиваются реальные EPUB, DOCX, FB2, PDF A5, Markdown. QA-отчёт не вставляется в текст книги |
| Иллюстрации | `illustrations_core.py`, `image_engine.py` | PNG/JPEG/WebP, привязка к сцене, вставка в EPUB/DOCX/PDF. **Генерация** возможна только при реально установленном ComfyUI с checkpoint; модели Ollama Vision не создают PNG |
| Нагрузка хоста | `monitoring_core.py`, `monitor-v2.sh` | Монитор читает хостовый файл и Ollama /api/ps; реальный nvidia-smi требует работающей отдельной службы на Ubuntu. Автосборка Docker не гарантирует его запуск |
| Изоляция сервисов | `scripts/achewiw-control.sh` | Запуск/пересборка проверенных контейнеров ACHEWIW, без глобального Docker prune/останова Ollama. Прежний неподтверждённый user-unit не трогается |

### Непустые результаты, а не имитации

- EPUB действительно собирается как ZIP с `mimetype`, XHTML, навигацией и ресурсами; DOCX через python-docx; PDF — через ReportLab.
- Генерация текста вызывает Ollama `/api/generate`, поток по частям сохраняется в SQLite. На CI это проверяется через подмену сети/процесса, **не тестируется качество художественного текста на RTX 3060**.
- Серверный мониторинг получает значения через JSON от хоста. UI **не подменяет отсутствие датчиков нулём или выдуманными цифрами**.
- Детектор повторов/штампов опирается только на точные текстовые совпадения и явно **не является детектором ИИ**.
- QA предлагает гипотезы, а не автоматически назначает человеку «сюжетные ошибки».

## 2. Реальные недоработки и технический долг

### Критически важно до публичного/платного выпуска (P0)

1. **Нет полноценного связанного с редактором canon/storygraph.** `app/storygraph_core.py` (факты, события, раскрытия, ревизии) существует как отдельное экспериментальное ядро. Новый реестр блоков отслеживает только **явно записанные автором** предпосылки и предметы; он не может автоматически и безошибочно определить все новые сущности в произвольной русской прозе. LLM-замечания могут ошибаться. Следующий этап: точные fact/event IDs, собственный словарь сущностей, проверка переходов состояния, принятие/отклонение каждого факта, автоматические тесты цепочек.
2. **Неполная типографская подготовка.** PDF A5 — реальная печатная проба, но **не PDF/X-4**; нет законченного экспорта с профилем ICC, вылетами, контролем обреза, полиграфической цветопробой и верифицированными лицензиями на иллюстрации/шрифты. Нет IDML/собственного файла для InDesign, а DOCX — редакторский исходник.
3. **Отсутствует подтверждённый end-to-end прогон на конкретной GPU/моделях пользователя.** GitHub Actions проверяет API, SQLite и экспорт, но не отрабатывает русскоязычную художественную генерацию/ComfyUI/VRAM на домашнем Ubuntu.
4. **Нет полноценной системы проверки источников, плагиата и прав на публикацию.** Указания в промпте не доказывают достоверность цитаты/DOI и не являются антиплагиатом или юрэкспертизой.

### Важные ограничения текущего MVP (P1)

5. **Длина фрагмента не гарантируется.** Цель 80–1000 слов управляет промптом и бюджетом токенов, после генерации виден реальный объём и допуск ±15%. Для гарантии размера нужен управляемый второй проход, пересчёт и сравнение без порчи фактов.
6. **Длинные романы проверяются частями.** Сюжетный аудит получает окно ограниченного контекста: у длинной сцены часть пропускается и прямо помечается. Для полной проверки целой книги нужны постраничный/посценный проходы и сводный граф фактов, а не заявление «LLM прочитала всё».
7. **Редактура «убрать ИИ-стиль» субъективна.** Есть явные сигналы повторов/клише и LLM-переписывание, но нельзя научно удостоверить «не-ИИ происхождение» текста. Итог принимает автор, а не алгоритм.
8. **Ветка структурного плана остаётся отдельной от истории текстовых ревизий.** Замена всего плана сцен через старую кнопку требует явного подтверждения, но не записывает столь же подробную автоматическую историю изменений, как новое принятие текста сцен/блоков. Нужны server-side revisions для структуры.
9. **Один активный AI-job на все произведения.** Защищает слабую GPU и исключает гонки, но не даёт параллельной генерации разных книг и постановки очереди. При рестарте частичный текст сохранён со статусом interrupted; автоматического продолжения с последнего токена нет.
10. **Конфигурация моделей и управление GPU неполные.** Конкретная скорость, качество, доступная VRAM и совместимость checkpoint ComfyUI проверяются на сервере. Случайное использование одной RTX 3060 двумя приложениями может вызвать OOM.

### Неблокирующие (P2)

11. `ebook_preflight_core.py` и `production_graph_core.py` частично присутствуют в репозитории как standalone primitives/RFC, но весь маршрут «проверить → утвердить → выпустить» ещё не соединён в UI единым обязательным ReleaseGate.
12. Нет сквозных браузерных screenshot-тестов для всех разрешений и сценариев drag/drop; CSS проходит структурные проверки, а реальные экраны нужно проверять после установки.
13. Нужны история изменений на уровне абзаца, свободный перенос блоков, индивидуальные профили редакторского стиля с примерами автора, а также управляемые рецензии второго читателя.

## 3. Приоритетный сценарий литературной работы

1. **Каркас:** разбить сюжет на сцены, указать факты/предметы, причины и их первое появление.
2. **Фрагменты:** в «03 · Редактор» для каждой сцены создать блоки; задать описание, цель слов, что уже существует, что появляется, от чего зависит, какие детали запрещены.
3. **Написание:** «Написать этот фрагмент». Модель показывает и хранит отдельный текст. Автор проверяет смысл и фактический объём.
4. **Принятие:** отдельное подтверждение; сервер проверяет исходную версию сцены, сохраняет текст и историю; если версия уже изменена — `409` без перезаписи.
5. **Контроль:** в «05 · Проверка» выбрать обзор всей истории или конкретную сцену, задать вопрос «откуда появился предмет / как узнал герой», прочитать детерминированные сигналы и отчёт LLM; принять или отклонить замечания.
6. **Стиль:** указать «что именно улучшить» и выполнить «Литературная редактура без ИИ-штампов». Сначала прочитать предложение, затем принять либо оставить оригинал. История принятия сохраняется.
7. **Выпуск:** в «06 · Типография» скачать EPUB, DOCX или пробный PDF A5, не выдавая их за проверенный PDF/X.

## 4. Оценка проекта — не рекламная

| Критерий | Оценка /10 | Комментарий |
| --- | --- | --- |
| Идея и отличие | **8.5** | Связка самостоятельного автора, структурных причин, локального LLM, истории редактур и реальных книжных форматов значительно полезнее обычного генератора текста |
| Архитектура MVP | **7** | Отдельный host Ollama, изоляция данных, сохранение AI-jobs в SQLite и чистые export core; но центральный canon graph ещё не подключён |
| Удобство интерфейса | **7** | Литературная типографика и отдельные рабочие этапы; вёрстка адаптивна, но нет полного браузерного UX-регресса |
| Реальное качество литературного текста | **не оценено** | Без серии русскоязычных сравнительных генераций, принятия правок и измерений нельзя ставить честную цифру |
| Готовность к платному издательскому продукту | **4.5** | Требуются права/источники, PDF/X, стабильность многоэтапных задач и интегрированный canon |

**Общая характеристика:** рабочий экспериментальный издательский MVP, **не** законченная издательская система. Наиболее перспективное конкурентное ядро — «управляемый длинный текст с причиной, каноном и правом автора на финальное решение». Уходить в создание ещё одного универсального AI-чата не нужно.

## 5. Проверки и безопасная установка

Текущая CI-матрица включает проверку Python, HTML, JS, жизненного цикла Docker/user-systemd, SQLite-заданий, реальных EPUB/DOCX/PDF, связанных иллюстраций и нового сценария фрагментов с обязательным авторским принятием, защитой старого текста и ревизиями.

Обновление **не удаляет** ни базу ACHEWIW, ни какие-либо другие проекты:

```bash
cd /1tbdisk/achewiw
git status -sb
git fetch --no-tags origin
git merge --ff-only origin/feature/technical-epub-first
bash -n scripts/update-editorial.sh
bash scripts/update-editorial.sh
bash scripts/achewiw-control.sh auth-check
```

Здесь `update-editorial.sh` — историческое имя общего скрипта обновления ACHEWIW (он пересобирает **только** проверенный `studio`, пытается запустить свой v2 монитор). Он не выполняет очистку SQLite или `docker system prune`.

**Не выполнять** `scripts/reinstall-studio-fresh.sh` ради этих функций: это отдельно подтверждаемая **необратимая очистка** старой библиотеки, а не часть обновления.
