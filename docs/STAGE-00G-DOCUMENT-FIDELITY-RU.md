## 1. Цель и границы

Определить на конкретных искусственных документах, что текущий Document Workshop действительно сохраняет при импорте, редактировании и экспорте DOCX/PDF. Проверить условия недопустимых потерь до разработки полноценного издательского оформления, ГОСТ-профилей и модерации произведений других авторов.

Рабочие рукописи владельца, `data/`, SQLite, Docker, GPU, ComfyUI, Ollama, `ai_draftsman`, сервер и платные облака **не используются**. Тесты создают документы исключительно в памяти процесса. На сервере тесты пока не выполнялись.

**Обоснованный исходный код:** `app/document_workshop.py`, `app/publishing_exports.py`, `tests/test_document_workshop.py`, `tests/test_illustrations.py` и `docs/DOCUMENT-WORKSHOP-RU.md`. Наличие проверенного HTTP 200 для `/docwork/` НЕ доказывает точность конверсии.

## 2. Фактические ограничения действующей реализации

- DOCX: python-docx открывает документ и сохраняет новое DOCX; стиль меняется по пресету, «сложные» абзацы с картинками, гиперссылками, полями и некоторыми объектами защищены от текстовой замены. Это полезная защита, но **не гарантирует визуально идентичный результат в Word/LibreOffice**.
- PDF → DOCX: `page.get_text("blocks")` выбирает только текстовые блоки (`item[6] == 0`). Растровые изображения, исходный макет колонок и их координаты **не переносятся**. Сортировка текстовых блоков по `(y, x)` может перемешать чтение двух колонок.
- PDF → PDF: исходные байты возвращаются без изменения.
- Скан без текстового слоя: OCR отсутствует, преобразование отвергается.
- DOCX → PDF: используется LibreOffice, фактическая визуальная проверка зависит от установленного ПО и шрифтов.
- Ограничения: 20 МиБ на загрузку, 180 МиБ распакованного DOCX, 20 000 обычных абзацев, 400 страниц PDF; интерфейс показывает максимум 3000 непустых абзацев, хотя экспортирует весь DOCX.
- В `app/publishing_exports.py` при книжном экспорте изображение и подпись добавляются как **разные абзацы/flowables**. Их неразрывность при переносе на следующую страницу не доказана.
- Книжные пресеты `book`, `technical`, `modern`, `karate`, `preserve` **не являются проверенной реализацией ГОСТ**. Библиография, библиографические ссылки, сноски, таблицы и формулы требуют отдельного набора правил для конкретного типа издания.

`strict xfail` **не означает успешную конверсию**: это зафиксированная, воспроизводимая известная ошибка. Если исправление даст неожиданную победу (XPASS), тест должен потребовать пересмотра отметки и проверки новой реализации.

### Как проверять результат

1. Выполнить синтетический тестовый модуль на изолированной среде (не на рабочем сервере и не с реальными книгами).
2. Зафиксировать количество PASS/XFAIL/FAIL, версии python-docx/PyMuPDF и локали.
3. После исправления потерь G06/G07 убрать `xfail` и проверить визуальный результат отдельно.
4. Сверить экспортируемый DOCX/PDF/EPUB/FB2 на стандартных, граничных и длинных документах, затем визуально принять эталон.
5. Только после этого переходить к «другой автор загрузил свою работу → ГОСТ/библиография → модератор → скачивание готового продукта».

## 4. Обязательные продуктовые решения после диагностики

**P0 — без потери данных:** для PDF с изображениями/таблицами/колонками нельзя представлять экспорт в редактируемый DOCX как полную конверсию. Один из вариантов реализации: явный режим «извлечь только текст» с предупреждением и отдельным подтверждением; полноценный режим должен использовать отдельный движок и не выпускать результат при потере объектов.

**P0 — рисунок + подпись:** у каждой иллюстрации должен быть устойчивый идентификатор, связь с подписью, alt-текст и якорь размещения. В DOCX/PDF не допускать разрыва пары при пагинации и пропуска файла без ошибки.

**P1 — ГОСТ:** профили оформлять как версии нормативных правил (область применения, конкретные стандарты и редакции, параметры, доказательства проверок); не объявлять соответствие только из-за выбора шрифта и полей.

**P1 — модерация:** отдельный авторский источник, издательский рабочий вариант, визуальный предпросмотр, протокол проверки, решение модератора, опубликованная неизменяемая версия для скачивания. Пока это целевая схема, не реализованное API.

**P1 — сохранение интерфейса:** редакторская сессия и предложения должны переживать F5, но авторский оригинал не изменяется без подтверждения. Связано с этапом 01.
