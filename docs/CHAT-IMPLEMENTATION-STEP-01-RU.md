# ACHEWIW · Шаг реализации 01: безопасный разбор команд двух чатов

**Статус:** код подготовки предложений, НЕ готовый чат и НЕ развёртывание. Основано на проектной спецификации `CHAT-GENERATION-EDITORIAL-WORKFLOWS-RU.md` и макетах #63.

## Что появилось

- `app/chat_command_planner.py`: чистая функция `plan_command(message, workspace, mode, project_id, scope)`.
- `tests/test_chat_command_planner.py`: адресная проверка распределения сложного поручения, двух режимов помощника и запрета самовольного применения.
- Два логических пространства: `generation` и `editorial`; каждый план ссылается на существующие этапы 01–06 и DOCWORK.
- Выход: `actions[]`, `question`, `warnings`, `status=proposal_only`, `applied=false`. Ни текст книги, ни утверждённая редакция не изменяются.

## Как испытать локально

```bash
python -m unittest discover -s tests -p test_chat_command_planner.py -v
```

## Ограничения

Это детерминированная первичная маршрутизация по русским/английским словам, НЕ семантический анализ большой LLM. Не вызывается ни один endpoint, нет новой вкладки или кнопки, нет сохранения диалога и автоматического исполнения. Это намеренно: сначала проверяем контракт планирования, затем интегрируем SQLite-предложения, проверку source_version и отдельную авторскую приёмку; только после этого UI и реальные генерация/редактура.

## Следующий шаг

1. Привязать планы к `project_id` / внешней DOCWORK-сессии; сохранять сообщения и предлагаемые операции в SQLite.
2. Версионированные предложения по одной главе с SHA исходника, точным diff, отказом при изменившейся главе и только ручным `accept`.
3. Подключить API к существующему редактору и шесть этапов, сохранив старые маршруты и светлый интерфейс.
4. Проверить одну реальную главу end-to-end; PR остаётся черновиком до проверки и согласованного слияния цепочки.

**Без изменений:** серверы 7080/17080, текущая база, фоновые задания, Ollama, модели, DOCWORK, стили и существующий UI.
