# ACHEWIW · После QA: решения автора, готовая рукопись и EPUB

Рабочая ветка: `feature/technical-epub-first`. Адрес сервера для доверенной LAN/VPN: `http://192.168.0.100:7080`. Код в GitHub: [musikfed/achewiw](https://github.com/musikfed/achewiw).

## Почему после «Готово · ожидает решения автора» не появилась книга?

Раньше это сообщение выводилось для **трёх разных задач** — создания плана, написания сцены и QA-проверки. На практике QA возвращает список ошибок и предложений. **Это не художественный текст и не готовая книга.** Смешивать отчёт с рукописью опасно: локальная модель может предлагать повторяющиеся или внутренне противоречивые исправления.

Сейчас после QA показывается явное «Отчёт QA готов · выбери действия по правкам» и пояснение: ничего копировать или вставлять в книгу не требуется. Отчёт сохранён отдельно от рукописи в SQLite. При повторном открытии проекта результат доступен в **04 · Анализ → Мои сохранённые QA-отчёты**, в том числе после новых генераций.

## Полный рабочий путь из идеи в книгу

1. **01 · Техническое задание:** название, мир, жанр, сюжет, твист и желаемый объём. Нажмите «Сохранить ТЗ».
2. **02 · Story.prj:** сформируйте каркас сцен. Если создан JSON от модели, кнопка «Принять предложение» переносит предложенную последовательность сцен в проект — **после проверки**. Затем нажмите «Сохранить сцены». Это план, не книга.
3. **03 · Редактор:** выберите сцену и напишите её художественный текст сами или нажмите «Предложить текст сцены». После генерации нажмите **«Принять предложение»**, затем **«Сохранить текст»**. Повторите для каждой нужной главы. Пустые сцены остаются незавершёнными.
4. **04 · Анализ:** запускайте аудит уже написанных сцен. ИИ отметит проблемы, но **не вносит правки автоматически**. В блоке «Решение автора по QA» можно выбрать «Принять отдельные замечания в работу», «Проверил и внёс нужные исправления» или «Оставить только как справку», записать *свои* решения и нажать «Сохранить решение». Заметки и выбранный статус сохраняются в SQLite, сам текст книги не меняется.
5. **05 · Книга:** полноценная читательская форма, сцены идут по порядку и включают **только записанный художественный текст**. Карточка покажет «2 из 7 сцен написано», перечислит пропуски и количество слов. Можно читать в браузере, скачать **Markdown** и **EPUB**. На компьютере или электронной книге открыть EPUB.

**Важно:** если при QA в сценах был только план и ещё не было художественного текста, анализ касается **карточек сцен**, а не законченной книги. Модель теперь получает прямое указание не изображать чтение отсутствующего романа и не выдавать повтор исходного предложения за исправление.

## Где сохраняются файлы и ответы?

- Данные проекта, написанные сцены и решения автора — `/1tbdisk/achewiw/data/achewiw.sqlite3`, таблицы `projects`, `ai_jobs`, `ai_job_reviews`.
- История генераций и черновики QA хранятся независимо от загрузки/перезагрузки браузера.
- **Книга EPUB/Markdown не копируется автоматически в GitHub и не пишется на диск сервера**, а формируется из сохранённых сцен по кнопке скачивания браузера. Файл появится в папке загрузок устройства.
- Скачивание **технического паспорта** через старую `/export` — отдельная функция, она включает ТЗ и метаданные, а **не только книгу**.
- Скачивание отдельного QA-отчёта через «Скачать QA-отчёт .md» — не заменяет EPUB книги.

Для диагностики без раскрытия произведения:

```bash
cd /1tbdisk/achewiw
bash scripts/achewiw-control.sh status

# Устанавливается ли SQLite-файл на смонтированном томе:
ls -lh data/achewiw.sqlite3

# Если в системе установлен CLI sqlite3:
sqlite3 data/achewiw.sqlite3 '.tables'
sqlite3 data/achewiw.sqlite3 'SELECT mode,status,count(*) FROM ai_jobs GROUP BY mode,status;'
```

Если выполняется генерация, **не запускайте `update` до её завершения**: пересборка контейнера прерывает запрос Ollama, хотя уже записанные части ответа остаются в SQLite.

## Обновление кода на Huananzhi

```bash
cd /1tbdisk/achewiw
git branch --show-current
git status --short

# Должна быть чистая feature/technical-epub-first
bash scripts/achewiw-control.sh update

# При отсутствии новой команды на старой версии и только при чистой рабочей ветке:
# git fetch origin
# git merge --ff-only origin/feature/technical-epub-first
# bash scripts/achewiw-control.sh update
```

Пересобирается только уже работающий контейнер ACHEWIW `studio`. Хостовые Ollama, RTX 3060, YadroKreator и другие проекты не перезапускаются. Обновите браузер Ctrl+Shift+R.

## Тесты

CI проверяет сохранение решений QA в SQLite, доступ к истории, пустые рукописи, безопасное XHTML-экранирование, структуру EPUB, отсутствие QA/ТЗ в книге, сохранность обычного экспорта и авторизацию API. Готовый EPUB и вёрстку следует дополнительно открыть на конкретном устройстве — GitHub Actions не заменяет аппаратную проверку Huananzhi.
