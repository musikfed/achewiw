## Как редактировать текст

Откройте Document Workshop, выберите DOCX и нажмите «Проверить структуру». В правой части страницы располагается единый лист текста и рисунков. Щёлкните по обычному текстовому абзацу и печатайте прямо в его поле. Выделение мышью, Delete, Backspace, обычное копирование/вставка работают как в текстовом поле. При фокусе на абзаце верхняя панель показывает его номер и доступные действия.

Панель даёт: выравнивание слева, по центру, справа, по ширине, возвращение исходного положения, роль «обычный текст» / «заголовок 1» / «заголовок 2» / «исходный стиль».

Выравнивание применяется ко ВСЕМУ выбранному абзацу и реально записывается в результирующий DOCX как OOXML w:jc. Изменение только выравнивания не разрушает форматирование отдельных текстовых runs внутри абзаца.

## Отмена действий

Кнопки ↶ «Отменить» и ↷ «Повторить», плюс клавиши Ctrl+Z и Ctrl+Y (Ctrl+Shift+Z) внутри листа.

- До 200 шагов в браузерной памяти текущей вкладки, но при больших правках возможно меньше из-за лимита объёма снимков (примерно 5 млн символов).
- Набор текста с короткими паузами менее 850 мс объединяется в один шаг.
- Отменяются изменения текста, подписей, заголовков, выравнивания, перемещений и стилей изображений.
- Новое изменение после Undo очищает очередь Redo.
- При F5 быстрая браузерная очередь Undo не сохраняется. Восстановление сохранённого состояния и прежних версий выполняется отдельно через серверную историю черновиков R3 (не более 500 версий на черновик).

Это не внешний резервный архив и не бесконечная история.

## Ограничения текущего этапа

Текст редактируется на уровне простого абзаца. Изменение форматирования только выделенных слов (B/I/U внутри строки) пока не реализовано. Полная замена многостилевого абзаца может упростить различия начертания его отдельных фрагментов: это старое ограничение конвертера, о котором интерфейс предупреждает. Сложные поля, гиперссылки, таблицы и текст рядом с изображениями остаются защищёнными, чтобы исключить повреждение OOXML.

Большой DOCX может содержать тысячи абзацев и много таблиц: веб-редактор показывает структурно безопасную часть, а для точной постраничной вёрстки нужно открыть PDF-предпросмотр и сверить результат в Word/LibreOffice.

## Тесты

GitHub Actions выполняет:

- Python: tests/test_docwork_editor_undo_align.py — реальные четыре вида выравнивания, сохранность исходника, проверка ошибочных значений, сериализация через SQLite R3 и экспорт DOCX API.
- Node: tests/test_docwork_undo.js — фактическая клиентская логика, группировка набора текста, многошаговое Undo/Redo, смена направления, предел 200 шагов.
- scripts/docwork-image-host-smoke.py — синтетический HTTP тест в запущенной Studio: новое выравнивание сохранено через R3 и реально присутствует в итоговом DOCX. После теста удаляется только собственный тестовый черновик.

## Испытательный сервер Huananzhi

Пока R3.3 находится в черновом PR и на Huananzhi не установлена. На сервере остаётся ранее успешно проверенная R3.2. Не сливать PR в main автоматически.

Инструкция для владельца:

1. Убедиться, что в /1tbdisk/achewiw нет несохранённых локальных изменений.
2. Забрать ветку feature/docwork-undo-paragraph-align-20261123 и переключить checkout без reset/clean.
3. Штатной командой bash scripts/achewiw-control.sh rebuild пересобрать только собственный контейнер ACHEWIW.
4. Выполнить bash scripts/achewiw-control.sh auth-check.
5. Выполнить синтетический дымовой тест: docker exec -i -w /app achewiw-studio python - < scripts/docwork-image-host-smoke.py.
6. Открыть /docwork/ через LAN/VPN и Ctrl+F5, проверить набор текста, 3–5 последовательных Undo/Redo, абзацные выравнивания и скачанный DOCX.
7. После ручной проверки записать обезличенный результат в PR №29.

Не выполнять общий Docker prune, compose down, git reset, git clean, изменение других контейнеров, моделей, личных книг или базы чужих проектов. Нормативная издательская приёмка 00-Д и ГОСТ R4 остаются отдельными этапами.
