# ACHEWIW · Шаг реализации 02 — сохраняемые чаты и предложения

**Статус:** код для `work.sqlite3` и изолированные тесты; UI/API/LLM пока не подключены. В существующие рукописи, canonical SQLite и job таблицы не пишем.

## Изменения

- `app/chat_conversations.py` — отдельные таблицы `work_chat_threads`, `work_chat_messages`, `work_chat_proposals` внутри уже предусмотренной рабочей SQLite `work.sqlite3`.
- `tests/test_chat_conversations.py` — проверка транзакционной записи поручения и плана, сохранения истории при переключении режимов, изоляции проектов, отклонения и выявления устаревшего исходника.
- Для DOCWORK можно использовать его собственный стабильный ключ в `project_id`; привязка к реальной DOCWORK-сессии будет отдельной серверной задачей.
- Исходный фрагмент не сохраняется в таблицы чата: только `source_ref` и SHA-256 выбранной версии. Предложения имеют состояние `proposed` или `rejected`. **Состояние `accepted` намеренно отсутствует, пока нет атомарного применения через канонический редактор.**
- Метод `proposal_preflight` сообщает, изменился ли переданный текущий текст, но не даёт права на запись: `can_apply=false`. Финальная проверка исходника будет выполняться в той же транзакции, что и применение редакции.

## Локальная проверка без отдельного тестового сервера

```bash
python -m unittest discover -s tests -p test_chat_command_planner.py -v
python -m unittest discover -s tests -p test_chat_conversations.py -v
```

Тесты используют `tempfile.TemporaryDirectory` и не затрагивают реальную базу. Сам факт наличия тестов не означает, что они прошли CI или что функциональность внедрена.

## Зафиксированное решение по инфраструктуре

**Не создавать и не использовать дополнительный тестовый сервер `17080`.** Пользователь уже располагает собственным тестовым сервером. Не менять порты, развёртывание, маршрутизацию и работающую среду этой веткой. Для будущего E2E использовать уже имеющуюся тестовую инфраструктуру, а рабочий `7080` не трогать до отдельного решения о выпуске.
