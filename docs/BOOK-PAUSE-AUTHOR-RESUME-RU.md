# ACHEWIW — очередной работающий переход конвейера: мягкая пауза главы

Дата: 24 ноября 2026. Продолжение PR #54 и #55, НЕ замена генератора.

**Авторский цикл:** замысел → каркас → объём и редакторские задачи глав → Ollama/RAG + StoryGraph → сохранённые фрагменты → **⏸ После фрагмента — пауза** → правка задачи конкретной незавершённой главы → **▶ Продолжить написание** → проверка повторов → авторская редактура → типография.

## Реализация
- `app/book_pause_control.py`: новая таблица `ai_book_pause_requests` с только `job_id` и `requested_at`, без копирования текста. Создаётся через существующий `init_db`, ничего не удаляет.
- `POST /api/books/jobs/{job_id}/pause`: принимает запрос только для `queued/running` книжного задания; запрос идемпотентен, не прерывает активный Ollama stream.
- `execute_book`: перед следующей порцией/ретраем и перед финальной обработкой проверяет флаг; после завершённого сохранения переводит `ai_jobs.status` в существующий `interrupted`, который поддерживается штатной кнопкой resume.
- `GET /api/books/jobs/{job_id}` и другие существующие ответы показывают `pause_requested`; в `app/static/index.html` на панели книги появляется кнопка «После фрагмента — пауза».
- При `resume` старый флаг очищается, а существующая логика перечитывает сохранённые главы. Затем доступны безопасное уточнение `editorial_goal` конкретной незавершённой главы из PR #54 и продолжение.
- Непринятая рукопись и черновой поток не стираются. Не меняются тексты, оригинальные хеши, структура книги, история, Ollama и ComfyUI.
- Если Ollama возвращает ошибку/повтор, исходная bounded retry/error политика остаётся. Мягкая пауза не маскирует сбой как успешную книгу.

## Практическое применение
Открыть книгу в генерационной Studio. Пока пишет, нажать «⏸ После фрагмента — пауза» (не перезапускать сервер). Дождаться статуса «Пауза по запросу автора». В карточке незавершённой главы задать новое направление и нажать «▶ Продолжить написание». Проверить, что `job_id` и число ранее сохранённых слов неизменны при самой паузе, новый фрагмент продвигает историю, RAG/Graph привязан к тому же проекту.

## Границы подтверждения
- Код и отдельные CPU/SQLite unit-тесты + syntax CI в PR; до развёртывания на Huananzhi это НЕ сквозная пользовательская приёмка.
- В текущей проверенной серверной SQLite: `projects=0, ai_jobs=0, ai_book_chapters=21, ai_book_plans=1, docwork_drafts=1`. Нельзя утверждать, что книга с 67% там доступна через обычный project/job. Нельзя автоматически присоединять осиротевшие главы к другому произведению.
- Для реального browser E2E нужна новая безопасная **учебная книга** на копии базы/отдельном окружении, а не разрушительный сброс рабочей базы.
- Независимая редактура стороннего DOCX/PDF в `/docwork/` остаётся неизменной.
- Модели Qwen/Hermes сравнивать по одинаковому авторскому сценарию позже; не скачивать и не менять VRAM на этом этапе.
