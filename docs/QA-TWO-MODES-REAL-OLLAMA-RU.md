# ACHEWIW: сравнительное испытание двух режимов с реальной Qwen

**Назначение:** без участия автора проверить обычную сборку технической мини-книги и чат-режим, затем редактирование главы через редакционный чат с локальной Ollama. Испытание рассчитано на **действующую Studio 7080**, не CI-имитацию. Код хранится в `scripts/host-dual-mode-book-qa.py`.

## Два независимых тестовых проекта

Обе книги имеют одинаковый исходный замысел, но **не копируют «Гантову зебру»**.

* Тема: «Дежурство маленького контроллера». Искра — вымышленный контроллер, который объясняет движение головки, ожидание сектора и передачу данных на HDD. Никаких реальных исторических дат и выдуманных ссылок.
* **Обычный режим:** создаётся технический проект с тремя вручную заданными карточками глав, сохраняется стандартный план `book-plan`, вызывается существующий `/books/generate` и ожидается законченная книга.
* **Чат:** создаётся другой, пустой технический проект и чат в режиме `autonomous`. Исходное поручение сохраняется сообщением, затем локальная Qwen генерирует **новый**, отдельный план 3 глав через `new-outline/batch`, который испытатель утверждает как тестовый, и запускается **тот же** канонический книжный движок через `book-control`. Ни второго генератора, ни независимой очереди не создаётся.
* В обоих проектах подтверждаются готовые отдельные AI-черновики, измеряются слова в каждой главе, формат PDF/DOCX, страницы/ссылки оглавления, сохранение рукописи после повторного GET (аналог F5 без браузера).
* После получения чат-книги создаётся редакционная версия. Через отдельный чат `editorial` локальная Qwen готовит **полный новый вариант первой главы** по краткому поручению, возвращает diff, редакторский QA-процесс принимает кандидат. Проверяется, что опубликованный канон **не переписывается**: новая версия — самостоятельная глава в `work.sqlite3` с новым ID и прежней сохранённой версией.
* Отчёт JSON хранится в `/data/qa-reports/dual-mode-real-ollama.json` внутри ACHEWIW `data/`. Созданные книги остаются с префиксом `QA 11–15` — их можно открыть во вкладках и сравнить.

**Объём:** по 600 слов на 3 главы, модель по умолчанию `qwen3:4b-instruct`. Эксперимент не тестирует литературную ценность большой книги, но проверяет причинность, пересечения и взаимодействие режимов. В отчёте нет содержимого рукописей, только названия тестовых глав, количества слов, хеши, страницы и статусы.

## Что проверено, а что пока нет

- CI проверяет **синтаксис и охват сценария**, но не запускает настоящую Ollama.
- Реальное выполнение возможно только в контейнере Studio на Huananzhi; никакой ChatGPT SSH-сессии в этом разговоре нет.
- HTTP-проверка повторного GET не доказывает визуальное поведение браузера после F5. Для браузерного E2E позже необходим Playwright/браузер на хосте.
- Две книги генерируются **последовательно**, чтобы не конфликтовать за GPU 12 GB. Если модель застряла или вернула ошибку, скрипт сохранит статус сбоя и ID проекта, но не станет стирать другие книги, вмешиваться в соседние сервисы или автоматически удалять задачи.
- На тестовой книге разрешена автоматическая приёмка AI-черновиков и чат-предложения **только** для QA; это не правило редакционной работы с реальными авторскими книгами.

## Команда для отложенного исполнения на хосте

Когда можно занимать GPU и нет чужой генерации, через существующую Docker Studio:

```bash
cd /1tbdisk/achewiw
git fetch --no-tags origin '+refs/heads/test/dual-mode-real-ollama-qa-20261125:refs/remotes/origin/test/dual-mode-real-ollama-qa-20261125'
git show refs/remotes/origin/test/dual-mode-real-ollama-qa-20261125:scripts/host-dual-mode-book-qa.py \
  | docker exec -i -w /app achewiw-studio python -
```

Не требуется новый Docker-образ или переключение Git в текущем рабочем каталоге: скрипт тестирует уже развёрнутые API по HTTP. Рекомендуется выполнять **только после подтверждения, что нет других активных заданий**. Эта команда намеренно не запускается без доступа к терминалу хозяина.

## CorelDRAW и Photoshop: реальные границы реализации

- `app/document_workshop.py`: непосредственно принимаются **только DOCX и PDF**. Ни `.cdr`, ни `.psd` не импортируются.
- `app/docwork_vector.py`: экспериментальная векторизация **растровых рисунков, уже встроенных в DOCX**, посредством Potrace → SVG или PNG. Potrace в Dockerfile устанавливается, но это не нативный формат CDR, не редактор слоёв PSD, не идеальное сохранение текста/фотографий/градиентов.
- Экспортируемый **SVG** потенциально можно открыть или импортировать в CorelDRAW; **PNG** — редактировать в Photoshop. Это обмен универсальными файлами, а не прямая интеграция с их API, слоями, палитрами, шрифтами или историей правок.
- Полноценная интеграция CorelDRAW/Photoshop потребует отдельно определённого формата обмена, проверки реального ПО и при необходимости отдельного коннектора/автоматизации. Называть её уже готовой нельзя.

## Последующие критерии

Если обе книги и чат-правка завершатся — сравнить: количество содержательных слов, дублирование повторяющихся фраз, качество переходов и соответствие плану, объём и фактическую пагинацию, поведение RAG/Graph, сохранение редакции после обновления браузера. Только после реальной оценки модели считать систему готовой к большому изданию.
