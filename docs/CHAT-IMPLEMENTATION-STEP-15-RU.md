## 15.1 Независимый выпускной gate

`app/print_release_gate.py` не принимает на веру «книга готова» из модели или UI. Он анализирует **реальные финальные байты DOCX и PDF**.

- В DOCX должен быть настоящий `w:instrText` с командой TOC, а `w:updateFields` — включено.
- Нужна отдельная отметка, что документ реально прошёл через офисный движок с обновлением индекса. Наличие `updateFields` само по себе **недостаточно**.
- В PDF должно существовать печатное оглавление; для каждой запрошенной главы извлекаются напечатанный номер и фактическая физическая страница заголовка. Пропуск, несовпадение или невозможность определения — блокировка.
- Проверяется наличие внутренних переходов PDF со страниц содержания. Число обнаруженных `GoTo` должно покрывать главы; корректность каждого прямоугольника ссылки при этом ещё нуждается в дополнительной проверке.
- Расхождение общего количества страниц, забытые заголовки и непредусмотренный пустой финальный лист блокируют выпуск. Намеренный пустой последний лист можно разрешить отдельной явной политикой.
- Иные предупреждения `preflight` выводятся редактору.
- Ответ возвращает `PASS/BLOCKED`, массив `blocking`, замечания и реальные страницы. Проверка не модифицирует PDF или DOCX.

**Важно:** `office_refreshed` — доверенный маркер того, что файл прошёл офисную стадию в контролируемом процессе, а не физически проверяемое свойство Office XML. Нельзя давать пользователю возможность просто отправить `true` через публичный endpoint и обойти стадию. На этом этапе механизм используется **локально в CI**, не как открытая команда публикации.

## 15.2 Реальный пересчёт полей Word

`scripts/refresh_docx_toc_office.py` запускает `libreoffice-writer` через отдельный UNO pipe с одноразовым профилем и скрытым документом. Перебирает импортированные индексы содержания и вызывает `update()`. Экспортирует **копии** нового DOCX и PDF, не перезаписывая входной документ. Если UNO/index/экспорт недоступен — процесс заканчивается ошибкой, выпуск не разрешается.

На GitHub Actions пакет LibreOffice/UNO ставится **только в одноразовый runner**. На домашнем сервере ничего не устанавливается. После теста runner удаляется.

## 15.3 Проверка настоящего офисного PDF

`final-print-gate-step15.yml` берёт синтетическую книгу из E2E шага 11–14; офис пересчитывает TOC, экспортирует PDF, затем `print_release_gate` сравнивает номера, главы и ссылки. Отчёт и синтетические файлы сохраняются как Actions artifact.

Оставить CI красным, если:
- LibreOffice не смог открыть или обновить поле TOC;
- PDF не содержит читаемого TOC, ссылки ведут не в главы либо их недостаточно;
- номер в оглавлении не соответствует фактическому номеру страницы;
- Word/PDF разошлись по структуре.

Не снижать требования, чтобы тест «позеленел». Если некоторые данные офисного PDF недоступны для надёжной проверки, показывать ограничения и продолжать развитие без ложного статуса `PASS`.

## Граница ответственности

Это выпускной **технический** gate: корректность нумерации, страниц, TOC, минимальная целостность файлов. Он не подтверждает истинность всех фактов, авторские права на иллюстрации, полную доступность PDF, правильность bleed/обложки для конкретной типографии и полную визуальную вычитку.

**Никаких изменений `main`, `7080`, DOCWORK, оригинальных авторских рукописей и порта `17080`.**
