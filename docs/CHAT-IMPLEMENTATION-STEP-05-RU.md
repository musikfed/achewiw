# ACHEWIW · Шаг 05 — связка редакторской правки с сообщением автора

**Состояние:** реализация сервисного слоя + отдельные unit-тесты. Без API, UI, LLM, внешнего сервера и реальных рукописей.

## Что добавлено

- `app/chat_linked_edits.py` связывает `work_chat_threads` → `work_chat_messages` → `work_chat_proposals` с `work_chat_book_edits` и существующим `work_book_versions`.
- Предложение привязывается к конкретному сообщению, главе, версии и хешу текста. Запрет на создание правок из чата генерации либо для другой главы.
- Принятие правки и статус исходного чатового предложения записываются в **одной SQLite-транзакции**. При смене версии между подготовкой и решением проводится отказ; все изменения откатываются.
- `chat_conversations.initialize` выполняет миграцию прежнего CHECK ограничения `proposed/rejected` к `proposed/accepted/rejected` для существующих баз, сохраняя уже записанные диалоги.
- Прямое отклонение связанного предложения через старый plan-only API запрещено — решение должно обновлять обе сущности вместе.
- Переходы через реальные сетевые API и генерацию текста LLM пока не подключены. Метод `prepare` принимает подготовленный текст (из будущего адаптера модели).

## Проверочный сценарий

Автоматически создаётся малая книга HDD из двух глав во временной SQLite. В чат автора помещается поручение «Убери разговорный оборот» с SHA выбранной главы; предлагаемая замена сохраняет соседнюю главу и immutable исходную редакцию. Тесты проверяют полный цикл, отклонение, отсутствие обхода согласования, чужой чат/книгу, несовпадающий хеш, устаревшее предложение/двойное принятие и миграцию старой базы.

```bash
python -m unittest discover -s tests -p test_chat_linked_edits.py -v
```

**Тесты изолированы:** `TemporaryDirectory`, никаких запросов к 7080, дополнительного 17080 не существует, никакой Ollama. Для последующего реального E2E применяется уже имеющийся тестовый сервер владельца без новых портов.

## Важная граница

`work_chat_book_heads` — **рабочий указатель** и не переписывает каноническую рукопись или выбор версии в типографии. Сохранение новой версии видно в `work_book_versions`; синхронизация уже открытых вкладок и применение в DOCWORK пока требуют отдельной интеграции.

Далее: безопасный server API для текущего проекта/авторизованной сессии, затем адаптер Ollama на малом фрагменте, а потом UI в шестиэтапном издательском интерфейсе.
