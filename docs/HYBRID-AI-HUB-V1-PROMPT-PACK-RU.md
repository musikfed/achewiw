## Авторская цель

Превратить существующую локальную «Типографию в кармане» в **ACHEWIW Hybrid AI Hub**: редактирование и производство книг с местной Ollama, подключаемыми облачными LLM и Codex, единым счётчиком `отправлено / получено`, раздельной стоимостью, квотами, правилами согласия автора и надёжным откатом. Это **эволюция ACHEWIW**, а не переписывание продукта с нуля.

Поддерживаемые направления: OpenAI GPT, Codex, DeepSeek, Hugging Face Inference Providers, Cloudflare Workers AI / AI Gateway, Modal, Replicate; Mistral и Perplexity — по мере получения ключей. Kaggle — **отдельный notebook/batch-провайдер вычислений**, а не обычный API диалога.

### Неприкосновенные правила для каждого промпта

1. Работа **только** в ветке `feature/hybrid-ai-hub-v1`; сначала изучить код и тесты, не предполагать, что заявленное в старых документах уже реализовано.
2. Не запускать, не перезапускать и не останавливать рабочие сервисы на Ubuntu, Ollama, Docker, ComfyUI и соседние проекты; не изменять сервер, VPN, публичные порты. Для деплоя нужно отдельное разрешение владельца.
3. Не удалять и не пересоздавать `data/`, `achewiw.sqlite3`, `work.sqlite3`, `search.sqlite3`, редакции книг, изображения и checkpoints. Изменение схем — только обратимыми аддитивными миграциями, с тестами.
4. **Запрещены** `git reset --hard`, `git clean`, `docker compose down -v`, глобальные prune и операции с чужими процессами. Не сливать ветку в `main` автоматически.
5. Рукописи, фрагменты и файлы не отправляются в облако автоматически: cloud-off по умолчанию, отдельный осознанный выбор провайдера, явное подтверждение платного/внешнего вызова.
6. Ключи API никогда не в Git/SQLite/браузерной разметке/телеметрии/отладочных логах; не просить пользователя прислать ключи в чат. Хранить в ограниченном хранилище секретов/переменных окружения согласно существующему механизму проекта.
7. Никакого автоматического принятия текста LLM, исправления авторского канона, перезаписи выпущенных книг. Сначала предложение, сравнение, решение автора, новая редакция.
8. Проверки проводить на синтетических книгах и mock-провайдерах; не делать реальные платные API-запросы без явного разрешения.
9. После каждого этапа: список файлов, тесты, известные ограничения, небольшие коммиты и точка отката. Отсутствие API-поля — `unknown`, **не 0**.
10. Расход токенов не равен расходу денег: цены, кеш, reasoning, поиск, изображения, GPU-секунды, Neurons и внешние списания учитывать **по реальному тарифу провайдера**; не смешивать подписку ChatGPT с API-биллингом.

## PROMPT 01 — Архитектурный контракт Hybrid AI Hub

> По результатам аудита спроектируй **недеструктивную** архитектуру `ProviderAdapter → ModelRouter → RequestScheduler → UsageLedger → BudgetGate → ApprovalGate`. Раздели text/chat/reasoning/image/batch/agent, local/remote, учёт и полномочия. Определи typed-интерфейсы, состояния задания, ошибки, таймауты, дедупликацию, продолжение после F5, отмену и одобрение автора. Покажи поток данных и границы приватности для книги. Не добавляй четвёртую БД или новый обязательный сервис. Подготовь ADR с таблицей миграций и схемой компонентов. Код — только после утверждения ADR.

**Критерий:** API и доменная модель не привязаны жёстко к одному облаку.

## PROMPT 02 — Универсальный реестр моделей и маршрутизация

> Реализуй конфигурационный реестр провайдеров и моделей: `provider`, `model_id`, `capabilities`, `context_limit`, `cost_model`, `data_destination`, `auth_status`, `enabled`, `budget_scope`, `task_role`. Поддержи Ollama как стандартный local route. Выбор модели для ролей «Писатель», «Критик», «Редактор», «Проверка фактов», «Художник», «Агент Codex» — независимый. Не переключайся сам на платную модель и не обещай доступную квоту без подтверждения API. Добавь mock providers и unit tests.

**Критерий:** неготовые Mistral/Perplexity видны как `not configured`, выбор не вызывает внешнюю сеть.

## PROMPT 03 — OpenAI API, DeepSeek и безопасные секреты

> Добавь коннекторы OpenAI Responses API и DeepSeek (официальный совместимый интерфейс, с проверкой его фактических полей). API-ключи получай из защищённого конфигурирования с server-side retrieval; в JS браузера не передавай. Для каждого запроса логируй только технический `request_id`, модель, счётчики usage и статус, без рукописи и секретов. Поддержи streaming и финальное usage, timeout, cancellation, retries с dedupe ID. Напиши mock-тест с 1 200 входных и 3 400 выходных токенов: total=4 600. Отдельно проверь cached tokens и reasoning tokens как подмножества соответствующих категорий, а не дополнительную сумму.

**Критерий:** Mock проходит без единого реального платного вызова.

## PROMPT 04 — Mistral, Perplexity, Hugging Face

> Добавь расширяемые адаптеры Mistral API, Perplexity Sonar API и Hugging Face Inference Providers. Проверь актуальные официальные схемы авторизации и usage перед реализацией: не переносить слепо OpenAI-формат на все сервисы. Perplexity может тарифицировать поиск отдельно от токенов; HF routing может иметь иного фактического плательщика. Покажи `configured/unauthorized/insufficient-quota/unavailable/unknown`, но не выводи ложный нулевой баланс. Сеть по умолчанию выключена; fixtures и contract tests обязательны.

**Критерий:** каждый провайдер возвращает нормализованный UsageEvent либо честное unknown.

## PROMPT 05 — Cloudflare: Workers AI и AI Gateway

> Сделай отдельные режимы Cloudflare Workers AI и AI Gateway. В Workers AI единица расхода может включать токены/Neurons, у Gateway — статистика проходящих запросов и дополнительные услуги. Для проксируемого GPT/HF/DeepSeek фиксируй `route` и `billing_provider`, сохраняй один канонический request ID и не удваивай стоимость базовой модели из-за Gateway. Настройки account ID, gateway ID, endpoint и credentials не показывать публично. Используй fake gateway в тестах.

**Критерий:** двойной учёт суммы предотвращён и проверен тестом.

## PROMPT 06 — Modal, Replicate, Kaggle без путаницы единиц

> Раздели коннекторы для Modal Model APIs, Modal GPU runtime, Replicate prediction API и Kaggle batch/notebook. Modal/Replicate могут тарифицировать не токены, а compute duration, конкретный output или запуск; Kaggle имеет квоты notebook/GPU, это не LLM chat endpoint. Сделай расширяемую таблицу единиц: `input_tokens`, `output_tokens`, `gpu_seconds`, `neurons`, `predictions`, `images`, `search_calls`. Не делай ложное преобразование GPU-часов в токены. Пользователь должен понимать разницу между лимитом и реальным счётом.

**Критерий:** на экране отдельно показывается usage и денежная оценка по корректной единице.

## PROMPT 07 — Единый журнал потребления и цены

> Создай append-only `UsageLedger` в существующей рабочей SQLite по согласованной в ADR схеме. Поля: request/job/book/chapter/role/provider/model/route/timestamps/status, вход/выход/кеш/reasoning/провайдерский total, non-token units, версия тарифа, оценка USD и подтверждённая сумма USD, source of truth, reconciliation status. Не храни промпты и конфиденциальное содержимое. Повторы ответов, ретраи и webhook должны быть идемпотентны. Протестируй пакетные запросы, потоковые ответы, оборванный стрим и постфактум уточнение биллинга.

**Критерий:** счётчик «отправлено 1 200 / получено 3 400» совпадает с подтверждённым API usage; неизвестная стоимость не показывается как $0.

## PROMPT 08 — Лимиты, квоты и защита от неожиданных расходов

> Реализуй `BudgetGate` с дневным, месячным, проектным и книжным лимитами, предупреждениями 50/80/95%, резервированием ожидаемых затрат перед параллельным запуском и отказом **в новых** вызовах при достижении лимита. Если API сообщает недостаточную квоту, покажи причину без повторных дорогих запросов. Если статус биллинга неизвестен, показывай отдельную оценку. Не обещай абсолютный hard cap у провайдера; задержка биллинга и внешние приложения делают его приблизительным. Переход на платную модель — только после явного решения автора.

**Критерий:** тесты гонок, отмен, retries и исчерпания бюджета.

## PROMPT 09 — Коннекторы и настройки в интерфейсе

> Создай экран **«Облака и модели»** внутри существующей визуальной системы ACHEWIW, а не отдельный админ-сайт. Карточки провайдеров с логотипом/названием, статусом подключения, текущей моделью, режимом расчёта, назначенными ролями и настройкой лимитов. Действия: добавить/проверить/отключить ключ без показа секрета, выбрать модель, тестировать разрешения без генерации где возможно, выбрать privacy policy и доступ к рукописи. Отдельный экран «Расход»: отправлено, получено, кеш, потрачено $, неизвестно, фильтры по книге/главе/провайдеру/периоду; экспорт CSV/JSON. Дизайн книжный, адаптивный, читаемый на телефоне и ПК.

**Критерий:** экран полезен без подключённых API; local Ollama продолжает работать.

## PROMPT 10 — Codex как управляемый агент, не общий LLM

> Подключи **Codex agent** отдельным интеграционным контуром через официальные поддерживаемые SDK/CLI/app-server после проверки действующей документации. Отличай API-ключ и биллинг от авторизации по подписке ChatGPT; не обходи пользовательские ограничения. Агент может предложить изменение в изолированном рабочем дереве, вывести diff и ждать разрешения. Ограничь разрешённые каталоги проекта, внешнюю сеть, shell-команды и действия с файлами. Запрети автоматическое редактирование исходных рукописей, сервисов Ubuntu и Git main; нет фонового безнадзорного исполнения. Usage Codex записывай с provenance и меткой `unknown`, если его интерфейс не предоставляет точных цифр.

**Критерий:** от тестового запроса до diff и авторского разрешения можно пройти без доступа к рабочему серверу.

## PROMPT 11 — Связка с редактором книги и замечаниями Word

> Применяй Hybrid AI Hub в существующей последовательности ACHEWIW: «Каркас → Черновик → Замечания на полях → Предложения редактора → Решение автора → Чистовик → PDF/EPUB». Для каждой редакторской заметки (см. #19) можно выбрать local Ollama или облачную модель, заранее видеть отправляемый отрывок и примерную стоимость, а затем получить предложенную **локальную точечную замену**. Ничего не менять в тексте до явного «Принять». Сохраняй снимок с замечаниями и отдельно чистовую версию. Не менять глобальные стили A5, подписи, сноски и изображения; при сдвиге страниц предупреждать.

**Критерий:** чистовик без служебных пометок, редакционный журнал полный, исходный DOCX не затронут.

## Порядок применения

В начале нового сеанса Codex **вставь PROMPT 00, дождись аудита и просмотри вывод**. Следующий промпт давай только после проверки результатов предыдущего. При неуспехе этапа сначала исправить проблему в нём, а не перепрыгивать вперёд. Запросы Codex к облаку и любые изменения на рабочем сервере отдельно согласовываются с автором.

**Набор промптов — дорожная карта и требования, а не обещание, что соответствующие коннекторы уже существуют.**
