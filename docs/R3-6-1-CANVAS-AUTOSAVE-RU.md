# ACHEWIW R3.6.1 — восстановление незавершённой разметки мастерской

**Основа:** R3.6 (27/27 HOST smoke на Huananzhi по предоставленному журналу). **Статус:** отдельная ветка для проверки; не считать развернутой до реального повторного host smoke.

## Проблема
До R3.6.1 мастерская сохраняла только принятый PNG-asset. Несохранённые стрелки, прямоугольники, подписи, линии при F5 могли пропадать. Нужно вернуть незавершённую работу, не меняя исходный DOCX, SQLite и авторский текст.

## Реализация
- Данные **только о фигурах** (тип, координаты, цвет, текст, размер) сохраняются в локальном хранилище браузера, разделённые по ID черновика, номеру рисунка и идентификатору применённого asset. Токены и пиксели туда не записываются.
- Восстановление при повторном открытии того же рисунка и той же базовой версии, с проверкой формата и лимитом 100 фигур.
- После успешного «Применить замену» прежний черновик разметки удаляется из локального хранилища, чтобы стрелки не нанести второй раз поверх нового PNG.
- Для внешних изображений, загруженных с диска, и временной трассировки восстановление разметки между F5 **не обещается**: после перезагрузки браузер не располагает теми же исходными пикселями. Использовать «Применить замену» или «Скачать PNG».
- Это **локальный браузерный автосейв**: он не синхронизируется между двумя устройствами, не заменяет принятие в SQLite, может исчезнуть при очистке данных сайта или приватном режиме. На общем компьютере учитывать сохранение текста надписей в профиле браузера.
- Сохранение исходного DOCX и защищённая серверная модель R3.6 не меняются. Код не требует миграций базы, не использует LLM/GPU.

## Ручная проверка перед приёмкой

1. Синтетический DOCX с минимум двумя картинками и подписями; открыть R3.6.1 на тестовом хосте.
2. Нарисовать стрелку, прямоугольник и подписать один рисунок. **Не применять замену**. Нажать F5, повторно открыть DOCX/тот же черновик, проверить восстановление.
3. Выбрать другой рисунок, нарисовать другую фигуру; вернуться к первому — наборы должны различаться.
4. Undo/Redo после восстановления; фигуры не должны дублироваться при возврате.
5. Применить замену, нажать «Сохранить изменения», экспортировать DOCX. После F5 ранее принятые фигуры должны присутствовать **однократно**.
6. Нажать «Снять замену», убедиться, что оригинальный рисунок не изменён.
7. Проверить переключение между двумя черновиками и чистым профилем браузера (нельзя подхватывать чужую разметку).
8. Выполнить штатный smoke `docker exec -i -w /app achewiw-studio python - < scripts/docwork-image-host-smoke.py` и вручную проверить браузер; smoke не имитирует F5 и не доказывает сохранение через интерфейс.
9. Убедиться, что никаких пользовательских проектов не удаляли и другие службы сервера не затрагивались.

## Ограничения и дальнейшая работа
Это **не** полный undo версий в SQLite, не векторный экспорт и не R3.7 семантическая реконструкция схем. R3.7 остаётся отдельным исследовательским этапом с ручным утверждением текста/связей. Переключать сервер на эту ветку только после проверки чистоты Git и штатным безопасным rebuild; не удалять data для этой доработки.
