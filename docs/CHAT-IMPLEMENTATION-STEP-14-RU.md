# ACHEWIW — шаг №14: редакторская приёмка смысловой вставки и пересчёт страниц

**Статус:** отдельный зависимый Draft PR после шага 13. Старый интерфейс, DOCWORK, работающий 7080 и оригинальные файлы не затронуты.

## Выполненный цикл

1. **Оллама/RAG/Graph** из шага 13 подготавливают один абзац с указанием авторских опор (источник не означает независимую историческую достоверность). Основной текст не меняется.
2. Кнопка **«Подготовить редакторскую приёмку»** строит две независимые PDF-пробы **до и после** предполагаемого добавления в память. Измеряются фактическое количество страниц, сдвиги заголовков и замечания PDF preflight. Подготовка сохраняет в `ai_page_fit_reviews` исходный digest, точный вариант новой главы и digest предпросмотра.
3. UI показывает исходный текст, новую главу, изменения страниц и ссылки на авторские свидетельства. Два независимых чекбокса подтверждают проверку **фактов/ссылок/повторов** и **пагинации/оглавления**. Дополнительно требуется подтверждение браузера.
4. `POST /api/projects/{id}/print-proof/fit-reviews/{review_id}/accept` сверяет идентификаторы проекта, главы, предложения, SHA исходного проекта и главы, digest увиденного предпросмотра и отсутствие работающего книжного задания. В **одной транзакции** обновляет только `projects.data` и записывает полные снимки до/после + отметку принятия. Если другой редактор успел изменить книгу — **409, ничего не переписывается**.
5. После принятия сервер создаёт **новую** PDF-пробу и возвращает итоговый preflight: количество страниц, найденные замечания, готовность к выпуску. Если печать или проверка после записи не удалась, в журнале остаётся обратимая новая версия, но выпуск **не считается готовым**; ошибку показывает ответ API.
6. Вкладки 01–06 перечитывают обновлённый канонический проект. Для DOCX сообщается необходимость **обновления настоящего поля TOC** после открытия в Word/совместимом движке. На стороне сервера поле Word ещё не пересчитывается принудительно.
7. **Откат:** `POST .../undo` разрешён только когда текущий проект **точно равен** сохранённому снимку после принятия. Иначе запрещён, чтобы не уничтожить другие правки. Историческая запись о том, что вставка применялась и отменена, сохраняется.

## Важные ограничения

- Система пока не осуществляет **автоматическую независимую факт-проверку** исторических утверждений, оригинальности и добросовестности источника. Чекбокс — осознанное авторское действие, а не декларация доказанного факта.
- Обновление **Word TOC** на сервере пока недоступно; DOCX может требовать открытия и обновления всех полей перед финальным экспортом. Проверка PDF — измерение фактически созданной **PDF-пробы**, не Word-документа, который может иметь другую пагинацию.
- До независимой финальной проверки и соответствия TOC публикацию нельзя объявлять автоматически безопасной. Значение `release_ready` относится к данному PDF-прогону и не означает прохождение всех иных издательских критериев.
- `ai_page_fit_reviews` — отдельная история до/после в **канонической SQLite**. Она защищает откат, но ещё не синхронизирует автоматически версию с независимой историей `work_book_versions` в другой базе. Избегаем неатомарной двойной записи.
- Прямых обращений к внешним LLM, нового порта, сервера, отдельного раннера, автоматической записи без подтверждения нет.

## API

- `POST /api/projects/{id}/print-proof/fit-reviews` — подготовить реальное сравнение для `suggestion_id`.
- `GET /api/projects/{id}/print-proof/fit-reviews/{review_id}` — восстановить сохранённую процедуру.
- `POST /api/projects/{id}/print-proof/fit-reviews/{review_id}/accept` — `confirm_sources:true`, `confirm_pagination:true`, `expected_preview_digest`; атомарное принятие.
- `POST /api/projects/{id}/print-proof/fit-reviews/{review_id}/undo` — безопасный CAS-откат.
