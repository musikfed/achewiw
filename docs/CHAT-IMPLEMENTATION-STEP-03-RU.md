# ACHEWIW · Шаг 03 — одна короткая глава и автономная проверка

Проверка выполняется на полностью **синтетическом тексте** о магнитной головке HDD, без пользовательских рукописей, без модели и без отдельного тестового сервера. Это узкий тест механизма редакции, а не доказательство литературного качества ИИ.

## Сценарий

Исходная глава (около одного абзаца): два объяснения работы HDD и фраза «В общем, я решил вам рассказать…». Предложенная новая редакция заменяет эту фразу на ясное описание работы головки, не затрагивая предшествующие абзацы.

1. Создать синтетическую главу с immutable revision id и SHA-256.
2. Предложить правку и показать точный unified diff; исходник ещё не меняется.
3. Смоделировать явное авторское решение `approve=True` **только внутри теста**, получить новую ревизию.
4. Вернуться к исходному тексту через **новую** rollback-ревизию, не удаляя историю.
5. Проверить отказ от правки, устаревшее предложение, изоляцию проекта, необходимость явного bool approval.

## Изоляция

`app/chat_synthetic_editor.py` использует исключительно **новые тестовые таблицы** `work_chat_synthetic_*` в `work.sqlite3`; не изменяет canonical manuscripts, реальные `ai_book_chapters` или DOCWORK. Изолированные тесты создают `TemporaryDirectory` и удаляют его после проверки. **Не подключать эти синтетические таблицы к реальному UI/API.** Для реальных книг понадобится отдельная транзакционная интеграция с существующим механизмом редакций.

## Выполнение

```bash
python -m unittest discover -s tests -p 'test_chat_synthetic_editor.py' -v
```

Ветка содержит GitHub Actions проверку на PR, работающую без сервисного порта, GPU, Ollama и данных автора. Запуск CI, если он состоялся, следует проверить отдельно по GitHub Actions; наличие workflow не равнозначно пройденной проверке.
