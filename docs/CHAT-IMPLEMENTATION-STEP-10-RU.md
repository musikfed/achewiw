# ACHEWIW · Шаг 10 — разговор → предлагаемый каркас → общие 01–02

**Состояние:** код в зависимой Draft-ветке (после #73), без развёртывания в `main` или на рабочем сервере.

## Действие

1. Автор в `07 · Чат генерации` сохраняет поручение в SQLite — никаких автоматических изменений.
2. Кнопка «Предложить изменения через Ollama» собирает **текущий** проект и план из канонической `achewiw.sqlite3`, проверяет модель и GPU lease и просит Ollama вернуть JSON только с разрешёнными полями.
3. `app/chat_plan_proposals.py` сравнивает входящие поля с неизменным списком допустимых, сверяет **те же scene_id, порядок глав и target_words**, валидирует новое содержание уже существующей `chapter_planning.validate_plan`. Предложение с полным снимком-основанием хранится в новой таблице `ai_chat_plan_proposals` **в основной SQLite**.
4. В UI отображается человекочитаемое сравнение старых и предлагаемых значений, после обновления страницы оно восстанавливается с сервера.
5. Только `decision {approve:true}` обновляет **одной транзакцией** `projects.data`, `ai_book_plans` и статус предложения. Перед записью перепроверяется SHA полного проекта и исходной сохранённой настройки плана. При рассинхронизации — 409, запись запрещена.
6. Принятые настройки становятся общими для вкладок `01 Задание`, `02 План`, `03 Редактор`, `05 Проверка`, `06 Типография`, потому что сохранены в **тех же таблицах**, которые они используют. Событие `achewiw:chat-outline-approved` перезагружает проект и план в открытой мастерской.
7. Существующие `/books/generate`, `/pause`, `/resume`, главы, RAG/Graph, типография и исходный текст не заменяются. Запуск после согласования — отдельная явная кнопка старого конвейера.

## Строгие ограничения первой итерации

- Поддержка запроса к модели на каркас из **1–12 существующих глав**; длинные книги требуют дальнейшего поэтапного/чанкового планирования. Не утверждаем поддержку генерации нового списка глав из свободного описания с нуля.
- Модель может изменить `premise/atmosphere/audience/twist/reveal/anchors`, а в уже существующих сценах `title/anchor/hook`, а также `tension/reveal_level/editorial_goal`. **Не вправе** менять число и идентификаторы сцен, `target_length`, `target_words` или текст глав.
- Если у книги есть текущее незавершённое задание, изменение каркаса запрещено, чтобы не обесценить сохранённые фрагменты. Требуется закончить или разрешить эту задачу в исходной мастерской.
- API остаётся за существующим `require_auth` на частной сети/VPN. Новый порт и сервер `17080` **не создаются**.
- На сервере **не исполняются** команды, содержащиеся в тексте автора или ответе модели. JSON проходит строгую проверку и предварительный просмотр.
- Пока не осуществляется `accept` изменений в DOCWORK: это другой режим и другая исходная рукопись.
- Уведомление об успешном принятии перезагружает авторский проект. Если до этого была локальная несохранённая копия формы, она резервируется в отдельном ключе `preChatOutlineBackup` и не восстанавливается автоматически поверх утверждённого плана.
