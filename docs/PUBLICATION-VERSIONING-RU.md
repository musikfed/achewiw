# ACHEWIW — произведение как проект: ветки редакции, контрольные точки и издания

24 ноября 2026. Стадия **R0 — первая реализация**. Не путать с полноценным архивом всех изображений/экспортированных книг. Код добавлен в отдельную ветку GitHub; работающая типография не обновлялась.

## Зачем это нужно

Книга, комикс, серия рассказов и технический учебник — это **произведения**, над которыми могут параллельно идти несколько направлений работы. «Редакция» — изменяемое направление, «контрольная точка» — неизменяемое сохранённое состояние, «издание» — закреплённая точка для определённого выпуска (бумага / электронная книга / версия 2 / иной язык). Вернуться к прошлой редакции означает **создать от неё новую ветку**, сохранив более новые редакции. Не «откатить всё» и не перезаписать главную рукопись.

Пример дерева:

```text
Произведение «Книга / Комикс» [project_id]
│
├─ Авторская редакция
│  ├─ 001 — текст до правок
│  ├─ 002 — редактирование глав
│  └─ 003 — готово к корректуре
│          ├─ Издание №1 (ссылка на точку 003, неизменно)
│          └─ Ветка «Версия для детей»
│              └─ 001 — правки новой ветки
│
├─ Комикс, сезон 1
│  └─ 001 — сценарий и манифест страниц
│
└─ Локализация / отдельная адаптация
   └─ 001 — свой вариант
```

## Уже создано в этом PR

- `app/publication_versions.py`: **три новые отдельные SQLite-таблицы**, без изменения существующих `projects`, `docwork_drafts`, `work_book_versions` и AI jobs:
  - `publication_branches`: ветка произведения, её тип (`book`, `comic`, `illustrated_book`, `other`), исходная точка и текущая вершина;
  - `publication_checkpoints`: полный *Project JSON*, манифест ассетов/экспортов, parent, хеши SHA256, дата;
  - `publication_editions`: закреплённая ссылка на контрольную точку, номер издания, метка.
- Записи checkpoint **append-only**: старые не перезаписываются. Сохранение новой редакции требует `expected_head`; при параллельном изменении — `409 Conflict`. Любую точку можно открыть и создать от неё другую ветку. Источник `projects.data` при этом **никогда не обновляется**.
- `app/main.py`: маршруты, унаследовавшие существующий private LAN/VPN auth:
  - `GET /publication/` — отдельный экран версий, основной интерфейс Studio не перестроен;
  - `GET/POST /api/projects/{project_id}/publication/branches`;
  - `GET/POST /api/projects/{project_id}/publication/branches/{branch_id}/checkpoints`;
  - `GET /api/projects/{project_id}/publication/checkpoints/{checkpoint_id}`;
  - `GET/POST /api/projects/{project_id}/publication/editions`.
- `app/static/publication.html` + `publication.js`: выбор произведения, новая ветка, список контрольных точек, просмотр, ответвление из предыдущей редакции, фиксация издания, отображение изданий. Выбирая контрольную точку, UI **не переписывает** книгу.
- `tests/test_publication_versions.py`: SQLite in-memory — самостоятельная редакция, отсутствие изменения главного проекта, fork старой версии, frozen edition, подмена проекта запрещена, конкурентный конфликт, проверка контрольных сумм.
- `.github/workflows/publication-versions.yml` — отдельный CI.

## Что происходит с текущей книгой, остановившейся на 67%

**Никакой фоновой или автоматической миграции этой книги нет.** Пользователь должен сознательно открыть проект, создать ветку и сохранить контрольную точку. Это не перезапускает генерацию и не меняет 4 готовые главы.

**Ограничение:** текущий `Project JSON` хранит сцены и метаданные проекта, но результаты генерации/главы могут храниться дополнительно в отдельной таблице book generation и DOCWORK, а сам комикс содержит PNG и исходники CDR/PSD на Acer. **Текущий R0 НЕ архивирует автоматически эти дополнительные таблицы и бинарные материалы.** Нельзя утверждать, что на 67% создан полноценный самостоятельный backup, пока не появится связанный контрольный пакет из текста, иллюстраций, исходников, вывода и хешей.

## Следующий этап — R1: версия как полный пакет издания

1. `work_id + branch_id + checkpoint_id + revision/edition`: единый глобальный паспорт для книги/комикса и внешних графических версий.
2. Атомарный content-addressed архив всех файлов: главы из книжного генератора; DOCWORK source + image assets; страницы комикса, исходники CDR/PSD, PNG/SVG/PDF/EPUB/FB2, обложка, описание, аудио при наличии. Манифест `sha256 + mime + role + source + derivative`, проверка реально существующих файлов. Снимок не считается «полным», пока все файлы не подтверждены.
3. Создание отдельной рабочей копии из полного checkpoint, **не перезаписывая** исходную книгу и её job. Кнопка «Вернуться в редакцию» должна вести к **новой ветке**, а не к разрушительному откату.
4. Ветки слияния: только явное ревью с диффом главы/рисунков, никакого скрытого overwrite.
5. Издание: язык, серия, номер, формат, дата, дата выпуска, канон/редакция, каналы публикации; статус `draft → proof → approved → published`. Этикетка «издание» сама по себе ещё не означает, что оно опубликовано.
6. Для книг — запускать типографию от **зафиксированного checkpoint**, а не от живой рукописи. Для комикса — пакет страниц, порядок свайпов, метаданные каждого кадра.

## Чек-лист приёмки

- [ ] На тестовом проекте UI создаёт 2 ветки; обе отдельно показывают версии.
- [ ] После сохранения редакции оригинальная таблица `projects` побайтно та же.
- [ ] Выбор старой версии не удаляет новую.
- [ ] Из старой версии успешно создаётся другая ветка; две ветки не делят изменяемое состояние.
- [ ] Издание №1 привязано к фиксированному checkpoint, дальнейшие правки не меняют издание.
- [ ] Конкурентная вкладка получает `409`, никакой тихой потери данных.
- [ ] Перезапуск Studio и обновление страницы сохраняют историю.
- [ ] При архивации full package сверяются все SHA, размер и наличие оригинальных рисунков (запланировано для R1).

## Промпт для продолжения

> Продолжи ACHEWIW по `docs/PUBLICATION-VERSIONING-RU.md`. Не своди книги/комиксы к файлу DOCX; произведение — проект с независимыми редакционными ветками, неизменяемыми контрольными точками и именованными изданиями. Действующая стадия R0 хранит Project JSON, но НЕ хранит все результаты генерации и бинарные изображения. Сначала сделай надёжное восстановление полного пакета (source job chapters, DOCWORK, иллюстрации и исходники), затем подключи typographic exports к immutable checkpoint. Никаких разрушительных rollback, закрытия оригинальных черновиков, автоматических слияний или захвата GPU.
